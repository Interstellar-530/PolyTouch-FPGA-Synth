# 外部硬件清单、最终产物与版本规划

日期：2026-10-10

本文只做规划，除已经写进 v0.4 的内容之外不再动代码。目的是把"下一步要买什么、做到什么算完成、按什么顺序推进"固定下来，避免在没有目标的情况下堆功能。

## 一、当前完成度基线

现在板子上跑的 v0.4 已经具备：单声部 DDS 合成、ADSR 包络、512 点波表线性插值降噪、(1,4,6,4,1)/16 平滑滤波、约 -12 dB 数字音量、S1/S2 两个按键切音、S3 同步复位，以及一条 115200 的 UART 频率控制接口。它还完全没有触摸、力度、多声部、音色切换、效果器和标准 I2S 输出，所以离赛题最低实现还有一段距离。

## 二、UART 频率控制接口（v0.4 已实现）

接口在 `source/rtl/audio/uart_pitch.v`，跑在 Dock 的 BL702 USB-UART 桥上，115200 8N1。FPGA 侧引脚是 `uart_rx = N6`（接 BL702 的 UART1_TX）、`uart_tx = N7`（接 BL702 的 UART1_RX）。要提醒的是这两根网络同时接到了 RGB LCD 连接器，插上屏幕就得让路。

协议是纯 ASCII，以 CR 或 LF 结束，大小写不敏感：

| 命令 | 含义 |
| --- | --- |
| `F440` | 把音高设成 440 Hz，取值范围 16 到 20000 |
| `M0` | 数字静音，用于区分"数字信号里的噪声"和"板级底噪" |
| `M1` | 解除静音 |

收到合法命令回 `OK\r\n`，非法回 `ERR\r\n`。频率到相位增量的换算封装成一个 Verilog 函数：

```verilog
// fs = 27e6 / 18 / 32 = 46875 Hz
function [31:0] freq_to_phase_inc;
    input [15:0] f;
    begin
        freq_to_phase_inc = f * 32'd91626;   // f * 2^32 / 46875
    end
endfunction
```

常数 91626 与精确值 91625.937 的相对误差是 6.9e-7，换算到 440 Hz 是 0.0003 Hz，音分误差 0.0012，完全听不出来。上位机只要往串口写 `F261.63` 这样的整数赫兹值就能直接决定音高，不需要知道 DDS 的内部表示。等以后采样率改成 48 kHz，只需要把常数换成 `2^32/48000 = 89478.485`，接口不变。

### 3.4 按键与复位

板载 S1、S2、S3、S4 已经够用：S1 和 S2 当音色或八度切换，S3 是 v0.4 里实现的同步复位，S4 是 RECONFIG_N，任何情况下都不要当普通按键用。如果之后想要一排实体琴键，用 MPR121 的触摸通道更省引脚；如果坚持用机械按键，12 个按键至少要 12 根 IO 或者用矩阵扫描，占用会明显多于触摸方案。

## 四、修复与排查记录（本轮）

### 4.1 高云烧录不成功

先给出结论：**不是连线方式的问题，JTAG 就是正确接口，也不应该换成别的接口。** 这块 Dock 的 USB-JTAG 口接的是板载 BL702，BL702 内部实现了 USB 转 JTAG 的桥，FPGA 侧的 TCK/TDI/TMS/TDO 分别走 D11、A11、B11、D10，全部由 BL702 驱动。所以"用 JTAG 烧录"本来就是唯一正确的路径，没有别的下载口。

实测也支持这个判断：在图形界面打不开的情况下，命令行 `programmer_cli.exe --device GW2A-18C --operation_index 0` 能正常读到 `ID Code 0x0000081B`，说明电缆、驱动、JTAG 链路、器件供电全都是好的。

那图形界面为什么失败？最可能的几个原因，按概率排序：

1. 编程器界面里 Cable 或 Device 没选对。默认可能是空的或者别的器件，必须手动选 `Gowin USB Cable(FT2CH)` 和 `GW2A-18C`。
2. 同一个 JTAG 电缆被两个程序同时占用。高云 IDE 自带的编程器和独立的 Gowin Programmer 都会各自拉起 jtagserver，两个一起开就会报 `Cable failed to open`。
3. 用了 `Program and Verify` 这类带读回校验的操作。这块板子读回校验本来就失败，会报 `Verify Failed` 和状态码 `0x00006020`，看起来像烧录失败，其实编程阶段已经成功。要么用 `SRAM Program`，要么忽略这条校验错误。
4. 接的是 USB-OTG 口而不是 USB-JTAG 口。Dock 上有两个 Type-C，只有 USB-JTAG 那个连着 BL702 的调试桥。这条可以排除，因为命令行能读到 ID。
5. 底板 1 号拨码没打开。未使能时核心板不启动，但这种情况命令行也读不到 ID，所以本轮同样可以排除。

另外注意，本轮读器件时发现板子当时跑的 User Code 是 `0x0000E195`，既不是上一版的 `0x000071A6` 也不是更早的 `0x00009F8A`，说明中间发生过一次重配置，FPGA 从板载 Flash 里加载了别的码流。这正好反过来印证了 S4 的行为。

### 4.2 高频啸叫

数字侧已经被证明是干净的：插值和 (1,4,6,4,1)/16 平滑之后，相对理想正弦的带内误差是 -94.8 dBFS，最强带内杂散在 16.5 kHz 处只有 -111 dBc。这个量级远低于 16 位系统的底噪，不可能被听成明显的啸叫。所以剩下的"略尖的闪烁啸叫"大概率来自数字链路以外，主要嫌疑有三个：

1. PT8211 到耳机功放之间的模拟通路耦合。1.5 MHz 的 BCK 是板上离功放输入最近的高速信号，边沿越陡耦合越强。本轮已经把 BCK、WS、DIN、UART 的 `DRIVE` 从默认 8 mA 降到 4 mA，如果有效说明确实是这个机理。
2. 供电与地环路。用 PC 的 USB 口给板子供电时，PC 的地噪声会顺着 USB 进到模拟侧。换成充电宝或独立 5 V 电源是最省事的对照实验。
3. 耳机本身的灵敏度或者功放固定增益太高。已经用 -12 dB 数字衰减压过一次，如果还觉得尖，可以在硬件上加一个简单的 RC 低通。

为了把这三条分开，v0.4 加了 `M0` 命令：发 `M0` 之后 DAC 数据被强制为 0，如果此时啸叫依然存在，那它一定不是我们产生的数字信号；如果 `M0` 之后啸叫消失，说明问题还在数字侧，需要继续查。

### 4.3 复位按键

结论是这块板上不存在一个"按下去只复位你的设计、不影响配置"的硬件按键，原因有两个：S4 接的是 B10 的 RECONFIG_N，语义就是重新配置；S0 虽然网络名叫 `FPGA_~RST`，但 T10 在 GW2A-18PG256 封装里被保留给配置用的 SSPI 功能，布局布线器直接拒绝把它当用户 IO 使用，本轮实测报 `'key_s0' cannot be placed according to constraint, for the location is a dedicated pin (SSPI)`。

所以 v0.4 把同步复位做在 S3/D7 上：D7 是普通 1.5 V 用户 IO，和已经在用的 T3、T2 属于同一组，可靠性有保证。复位的实现是两拍同步器加一个 `por | soft_rst` 的复位树，耳机功放使能只跟随上电复位，按复位键时功放不会关断，因此不会产生爆音。

## 五、结合大赛要求的优化方向（暂时不动手）

评分口径是 `吞吐量 = 同时发声的独立振荡器数量 × 实际输出采样率`，而且明确说内部过采样不加分、波表查表算一个振荡器。这条口径基本决定了优化的主攻方向。

**第一优先级是把声部数拉上去。** 4 声部是门槛，8 到 16 声部是比较舒服的目标，32 声部是扩展要求。要注意资源账：每个声部至少需要一个相位累加器、一次包络乘法，32 声部若每个都配一个 18×18 乘法器就超过了 GW2A-18 的 24 个 DSP。可行的做法是时分复用——27 MHz 主时钟下，48 kHz 采样率、32 声部，每个声部每个采样点有 `27e6 / 48000 / 32 ≈ 17.6` 个时钟周期可以用，一个共享乘法器加一个调度器完全够。波表 ROM 也可以只放一份，用多周期读代替多端口。

**第二优先级是把采样率提到标准 48 kHz。** 现在 46.875 kHz 是为了从 27 MHz 整数分频推 PT8211 的调试通道临时妥协出来的。赛题要求标准 I2S 到 PCM5102A，所以要一颗 12.288 MHz 有源晶振：÷4 得 3.072 MHz 的 I2S BCK，÷64 得 48 kHz LRCK；同一个 12.288 MHz ÷8 得 1.536 MHz 刚好给 PT8211。采样率从 46.875 k 提到 48 k，吞吐量直接提升 2.4%，同时接口才符合赛题表述。

**第三优先级是演奏维度。** 赛题要求至少两个独立可控维度，扩展要求三个以上。MPR121 的 12 键是第一个维度，FSR 压力是第二个维度；第三个维度可以再想，比如第二片 FSR 做弯音、或者触摸键的接近量做音量包络前馈。

**第四优先级是音色和效果。** 两种以上音色是扩展要求，做法是再加一到两个波表（方波、锯齿、或者几个谐波叠加），BSRAM 每块 18 Kbit，1024 点 16 位表占一块，加到四块也远没到 46 块的极限。效果器里最有性价比的是延迟和合唱，用 BSRAM 做环形缓冲即可，混响代价偏大，放在最后。

**延迟指标**要在架构定下来的时候就留好余量：赛题要求控制到发声不超过 10 ms，扩展要求 5 ms。现在触摸事件到下一个采样点之间最多 21 µs，延迟主要会花在去抖、声部分配和 I2C 轮询上，所以触摸不能走"轮询加长去抖"这条最省事的路，否则延迟会失控。

**现场证据**要提前准备：测试模式要能同时输出多个不同频率、频谱上要能看到独立峰、RTL 要能证明是实时生成而不是回放。建议从 v0.6 开始就固定一个"演示模式"，用按键或 UART 一键进入，输出固定的多音测试信号，省得答辩当天手忙脚乱。

## 六、最终预期产物

到 v1.0 时希望交付下面这些：

**硬件整机。** Tang Primer 20K 核心板加 Dock 3714 作为主控，外接一块 12 路触摸板（MPR121）、一个 FSR 力度条（MCP3208）、一片 PCM5102A I2S DAC 和一颗 12.288 MHz 有源晶振，装在一个固定的底板或面板上，能做到插上电源就能演奏。

**RTL 工程。** 纯 HDL 的合成引擎，包含 N 个独立声部的 DDS、可切换波表、每声部 ADSR、并行混音与饱和、至少一种硬件效果、标准 I2S 发送器、MPR121 的 I2C 控制器、MCP3208 的 SPI 控制器、UART 控制接口，以及一个多音测试模式。全部可综合、可复现，构建脚本一条命令跑通。

**上位机工具。** 一个小的 Python 脚本，通过串口设频率、音色、声部数、音量，并能读取状态；再附一个频谱显示脚本，用声卡输入实时看输出频谱，作为现场证据。

**文档与证据。** 设计说明（时钟树、数据流、资源预算、每个模块的算法依据）、综合与时序报告、资源占用表、延迟实测方法和数据、验收清单、以及一份按赛题评分口径整理的功能对照表。

**演示材料。** 单音、和弦、音色切换、力度变化的演示视频，频谱截图，以及一份能说明"没有预录 PCM、全部实时生成"的证据包。
