# 调试日志：四声部复音与《兰花草》测试曲（2026-10-10 修订十二）

## 目标

把单声部链路扩成四声部复音，用一首能听出对错的曲子验证复音与混音，用按键切换两套和弦验证按键功能，并把将来接实时控制键盘的接口留出来。

## 设计

数据流是播放器写事件 FIFO、分配器取事件、四个声部分别发声、混音器求和输出。事件字是 `{on, note[6:0], velocity[7:0]}`，两个来源共用这条总线：内置播放器和 UART 音符命令，UART 优先。

分配器的取声顺序是先取包络已经归零的空闲声部，再取处于释放段中最老的声部，最后才抢仍在按住的声部。这样旋律重新触发时不会把按着的和弦音切掉。一次事件突发里所有关音都排在开音之前，避免分配器把即将复用的声部抢走。

测试曲的旋律与和弦 ROM 由 `tools/gen_song_rom.py` 生成，音高表常量也由同一个脚本算出，保证 Verilog 里的 12 个常量和金模型一致。

## 过程中发现并修掉的问题

第一版混音器把主音量放在饱和之后。金模型渲染出来峰值正好是 8192，也就是四路相加后先被削平、再右移两位，和弦部分全是削波失真。改成先求和、再乘主音量、最后饱和之后峰值降到 12705（-8.2 dBFS），波形完整。这个错误单看 RTL 不容易发现，是金模型先暴露出来的。

`voice_alloc` 的组合逻辑里 `best_age` 只在部分分支被赋值，综合报出锁存器警告。在组合块开头无条件赋初值后警告消失。

`song_player` 拼装事件字时把 8 位音号放进 7 位字段，综合报出表达式截断警告。改成显式取低 7 位后警告消失。

第一次烧录时用 `Select-Object -First 25` 截断输出，PowerShell 提前终止了编程进程，器件回读的 User Code 还是旧值。换成完整读取再取尾部之后烧录正常完成，User Code 变为 `0x00009EC7`。

## 验证证据

## 还没验证的

板上听感没有人耳确认，四声部同时发声是否干净、两套和弦的差别是否明显，都需要实际戴上耳机听。串口音符控制虽然已接线，但底板 USB-JTAG 口还没在电脑上枚举成功，暂时无法从电脑触发。

## 回退方式

外部 Flash 里仍然是修订十一的基线码流（User Code `0x000059D1`），按 S4 触发重配置或者断电再上电就会回到那一版。基线码流文件保存在 `artifacts/instrument.fs`，本版码流保存在 `artifacts/instrument_poly_v0.5.fs`。软件侧的回退点是 Git 标签 `v0.4-20261010`。
