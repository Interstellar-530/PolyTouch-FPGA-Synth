# 调试日志：仿真门禁落地与节奏、和弦、音量优化（2026-10-10 修订十七）

## 一、把仿真核验变成强制环节

要求是把仿真写入项目配置，只有仿真通过才能烧录。做法分三层。

第一层是规则，写在项目 `AGENTS.md` 新增的"仿真与烧录门禁（强制）"一节：任何 Verilog 改动烧录前必须先过 RTL 仿真，不接受"改动很小""只调参数"之类的例外；新增或修改功能时同步补测试台，测试台必须自检，断言不成立时用 `$fatal` 结束让退出码非零。

第二层是执行，`source/sim/run_simulation.ps1` 编译并运行全部测试台，任何一个失败就返回退出码 1。三个测试台各管一段：

| 测试台 | 检查内容 |
| --- | --- |
| `tb_tick_rate` | PT8211 的采样节拍周期必须是 576 个 27 MHz 时钟，即 46875 Hz |
| `tb_song_timing` | 一遍曲子占多少采样节拍、发多少个开音事件，期望值由生成的 `song_expect.vh` 提供 |
| `tb_poly` | 顶层连线：上电复位、默认速度档位、S1 与 S2 两个按键 |

第三层是拦截，`source/build/program_sram.ps1` 默认先调用门禁，未通过直接抛错拒绝烧录；`-SkipSimulation` 只在仿真器本身不可用时使用，并且必须在日志里说明原因。整轮门禁约 95 秒。

## 二、门禁立刻抓到两个问题

第一个是 `reset_cnt` 没有上电初值。FPGA 上电时寄存器默认为零，所以硬件一直跑得正常；但仿真里它是 x，`reset_cnt != 16'hFFFF` 的比较结果也是 x，计数永远不增加，上电复位永不释放，`tb_poly` 读到的输出全是 x。给 `reset_cnt` 和两个按键同步器加上显式初值后恢复正常。这也顺带说明显式写初值对仿真友好，值得保持。

第二个是我自己文档里的错误。档位指示灯是低电平点亮、驱动写法为 `~tempo_sel[bit]`，所以**灯亮表示那一位是 1**。我先前给出的表格是按"亮=0"写的，把 2 倍档和 3 倍档写反了。现场反馈的"3 号灯常亮"按真实逻辑对应 2 倍档，也就是原来的默认档，因此默认值保持 2 倍不变，表格改正。

如果没有这道门禁，这两件事都还会继续藏在文档和仿真环境里。

## 三、节奏优化

原来每句的时值长短不一（10 到 16 个单位），句长不齐，和弦因此只能跟着句走、落不到固定格子。现在每句统一为 14 个十六分音符的发声长度，并保留原谱的三类句型：记作"6 3 3 3"的句子是四个八分音符，记作"1. 2 1 7"的句子句首是附点八分加十六分，记作"6 -"起句的句子开头是四分音符。全曲 169 个槽位单位。

## 四、和弦与音量

和弦由每句一个改为每句两个，一组 18 个，和弦变化密度翻倍。两套进行的差别也拉开：A 套留在自然小调范围（i–iv–VII），B 套偏向多利亚的明亮色彩（III–VII–iv–v）。此外两套的力度分开，A 套 30、B 套 46，按 S1 切换时音区与响度同时变化，比只换进行更容易听出来。

主音量由右移两位改为右移一位，提升约 6 分贝。金模型实测峰值 A 套 -3.1 dBFS、B 套 -2.1 dBFS，都没有触到饱和器。

## 五、验证结果

仿真门禁三个测试台全部通过：采样节拍 576 个时钟无误；默认 2 倍档一遍 3300908 个采样节拍，折合 70.4 秒，与 169 单位乘 9766 乘 2 一致；一遍 95 个开音事件，等于 41 个旋律音加 54 个和弦音；顶层复位、默认档位与两个按键均按预期动作。

构建无警告，资源 4573 逻辑单元、789 寄存器、4 块 BSRAM、6 个 DSP，码流 SHA256 `640c892480bb7de376d57fbbf5048dac3c91271e96b0d0a34e4df492113bd1ce`，User Code `0x00006DD1`，已通过带门禁的 `program_sram.ps1` 写入 SRAM 并回读确认。

## 六、环境与注意事项

写完 PowerShell 门禁脚本后又踩了一次编码坑：Windows PowerShell 5.1 以 ANSI 读取没有 BOM 的 `.ps1`，中文注释被打乱直接导致语法错误。两个脚本都已改成带 UTF-8 BOM 保存，这是本项目早就记录过的约定。

另外测试台里出现过一次命名冲突：任务名不能叫 `expect`，那是 SystemVerilog 的关键字，已改名 `check_equal`。
