# 2026-10-12 事件队列与演示/手动模式修复

本轮对应零外设任务清单第二项。上电仍自动播放《兰花草》；收到 `N<note>`、`O<note>` 或 `X` 后，进入手动模式、清掉歌曲事件与原有声部，歌曲停止向分配器发事件。首次手动音符在清除旧声部后一拍送入，不会被 Panic 吞掉。`D0` 显式进入手动模式，`D1` 清除当前声部并从头启动演示曲。`M0/M1` 只控制数字静音。S2 仍调整速度，但在手动模式下不再清除手动演奏声部。

事件 FIFO 加入满载时同拍读写的可接受信号。播放器按该信号保持当前事件，直到 FIFO 真正接收，避免满载时静默丢 Note Off 或 Note On。模式切换、X 和演示重启同步清队列，防止旧歌曲事件在手动音符之后才被送出。UART Note Off 与 Note On 都优先于演示队列；Panic 优先于所有事件。

串口解析新增 `D0/D1`，只接受 `M0/M1`、1–127 的音符号和精确的参数长度。旧 `F` 命令、越界音符和非法参数明确产生 `ERR`。回复端加入 16 项顺序队列；极端持续灌入使队列溢出时，饱和计数器 `reply_drop_count` 记录丢失的回复，主机日常使用仍建议等待一条回复再发送下一条。PuTTY/Plink 发送脚本已允许 D0/D1。

仿真门禁九个测试台全部 PASS，包含新加的满队列同拍读写与顺序检查、播放器背压、真实 UART 字节到顶层模式控制的集成测试、非法命令及回复队列顺序。Gowin V1.9.11.03 Education 已成功综合、布局布线并生成位流。目标 GW2A-LV18PG256C8/I7：逻辑 4596/20736，寄存器 741/16173，BSRAM 4/46，DSP 宏块 6/24（报告内列 PADD18 4、MULT18X18 12）；27 MHz 约束下 Fmax 44.191 MHz，建立/保持违规端点均为 0。位流和完整日志归档于 `archive/FPGA-20261012-v0.6/`。

九项仿真通过后，使用 Gowin Programmer 操作 2 临时烧录 SRAM，读回 ID `0x0000081B`、新 User Code `0x00005633`、Status `0x00006020`。COM13 实测依次发送 N69、O69、D1、D0、N72、X、D1，全部收到 OK，最后停在演示模式。该串口实测能证明板上加载了新命令接口；目前没有用户耳机听感或示波器证据来独立确认模式切换后的声音。Flash 没有重写，重新断电上电会恢复此前验收的旧版本（User Code `0x0000FCF0`），因此 D0/D1 只在本次 SRAM 临时版本上可用。回退代码使用本轮前 Git 提交 `457e7a6`；硬件只需重新上电即可回到当前 Flash 版本。

调研时查看了[开源 FPGA Verilog 合成器](https://github.com/nishadsuresh/fpga-verilog-synth)，其 UART/MIDI 到四声部音频链路可作测试思路参考；这里没有复制外部代码。现有 Gowin 工程、板卡引脚和命令协议需要本项目自身的队列及模式控制实现。
