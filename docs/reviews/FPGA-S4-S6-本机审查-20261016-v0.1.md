# S4-S6 本机审查与测试样品完成度评估

日期：2026-10-16。对象：`codex/s4-s6-integration@40ef0128dadffdcbae221b79e7ee1bac11cf9ef0`。当前工作分支保留 `codex/s3-i2s-tx@17aff2d`，通过 Git archive 提取最新代码到独立目录。本轮未修改生产 RTL，未合并分支、未推送、未烧录、未运行完整门禁，也未重新综合/PnR。审查新增的测试台和脚本是独立证据，生产修复建议在下文给出。

## 1. 结论

S4 的 SPI 位对齐、S5 的定点运算和 S6 的同步 ROM/共享合成路径，已通过本机定向仿真，适合作为继续联调的基础。它距离可验收样品仍有三项直接缺口：压力值未作用于声音，双音色尚不能自由切换，默认构建/位流选取流程没有跟上集成版。优先修完这些可交付问题，再进行实物频谱、控制延迟和 Flash 启动验收。32 声部、效果器和 LED 引导属于随后争取拓展评分的工作。

此前项目 AGENTS 仍记载 MPR121 最低方案，但 10/13 的后续规划和采购记录已明确以 12 路 GPIO 为主、MPR121 备选。官方选题二允许任意自研交互方案，并未限定 MPR121。因此本报告和接线 PDF 沿用已确定的 GPIO + FSR + 弯音电位器路线，不把补触摸驱动列为必做。后续宜同步项目规则，避免再次分叉。

## 3. 应优先修复的问题

### P1-01：FSR 没有进入音频路径

定位：`rtl/top.v:437`、`455`、`508`、`529`。`pressure_bend` 的压力输出仅参与 `clip_fold`，引擎力度来自固定 GPIO/UART velocity，全局混合权重又是常量。标准档封装丢弃 `clip_fold`，综合器还可以连同不影响弯音的压力滤波支路一起裁掉。

本轮完整顶层 A/B：CH0 分别为 0/4095，滤波值为 0/4094，比较 512 个非零音频帧，差异帧数 **0**。这证明“ADC 和滤波已接入”不能作为“压力表情已实现”的完成标准。现有 `tb_top_s4s6` 只证明压力不改变音高，没有要求压力改变任何音频量。

建议把校准后的压力接到全局 VCA 或音色权重，并设旁路、死区与平滑；帧边界提交控制值。先使用全局表情而不是每声部重复乘压，成本低、行为容易验收。修复验收必须同时满足：持音时压力改变幅度或频谱、频率不变、包络不重起音、关闭压力后仍可演奏。

### P1-02：默认构建与位流选择仍是旧流程

定位：`build/build.ps1:36` → `build_instrument.tcl:16`；`program_sram.ps1:38`。默认 Tcl 没纳入四个集成模块与 pROM 依赖，仍以 `top` 和旧 CST 为入口，本轮展开已明确失败。新的调试/标准档 Tcl 虽各自存在，旧 PowerShell 包装器没有选择它们。

烧录脚本默认查 `source/impl/pnr/instrument.fs` 或随包旧 `artifacts/instrument.fs`，而新 Tcl 产物在各自的 `build/gowin_top_*` 工程目录下。这会让“刚构建集成版、脚本却取旧位流”成为实际可能，不必等烧录时才发现。

建议统一一个显式 `-Profile debug|standard` 入口，把顶层、源文件、CST/SDC、输出目录和位流路径绑定，并让烧录入口要求该构建产物。本轮未改这些公共构建参数；这是下一轮需要确认并落地的接口整理。当前临时做法是使用专用 Tcl 并显式传入位流文件。

### P1-03：双波表已存在，音色自由切换仍缺控制入口

定位：`rtl/top.v:455-456,508-510`。权重固定为 `8'h40`，只有一种固定混合音色。没有串口音色命令、旋钮路由或现场切换手势。两张表存在并不等于评委能操作两种音色。

建议先提供纯正弦、亮音色和连续混合三个可演示状态，控制值以 1-5 ms 短斜坡过渡，避免瞬间跳变产生点击音。两个表的谐波结构应在同音高的频谱中明显可辨。默认 255/256 权重和带来约 0.034 dB 衰减，不是当前高优先级问题。

### P2-01：头部余量不足，Attack 顶端仍可能削波

定位：`global_crossfade.v:23-29`，固定四路和后除二。独立整数分析以四声部同相、velocity=100、weight=64 扫描 512 个表相位：Sustain=45875 时最大绝对值 30920，未越界；env=65535 时峰值 **44173**，有 **258/512 个相位点**越过 16 位范围。这里是最坏相位覆盖，不是实际演奏时间的削波百分比。

现有饱和能阻止回绕，却不能消除音色失真。先给用户可调主音量/编译期保守增益；若要响度，之后再加带余量的软限幅。压力增益和效果器必须纳入同一个头部余量预算。用四个不同音高、最大力度和重按阶段记录饱和前峰值和削波帧数。

### P2-02：控制采样标称与顶层实际不一致

定位：`top.v:383-420`。2 kHz 是发起事务节拍，交替 CH0/CH1 后每通道只有 **1 kHz 新样本**；滤波器仍以 2 kHz 对重复值更新。标准档 SPI 实际 **245.76 kHz**，并非精确 250 kHz；这是整数分频的正常结果，19 拍耗时 77.31 µs。

模块自检 t90=2.5 ms 假设每个控制 tick 都有新输入，不能直接当作整机 FSR 响应。接入后应按完整“传感器变化 → 轮询等待 → 滤波 → 音频帧”的链路复测。需要提高响应时，可在一次 0.5 ms 周期内顺序采完两路，总 SPI 时间约 154.6 µs，仍有余量；这是调度修改建议，本轮未改实现。

### P2-03：弯音没有滤波、中心死区，旧精度描述偏乐观

定位：`pressure_bend.v:66-98,106-152`。弯音直接映射最新 ADC 值，压力滤波没有覆盖弯音，实体电位器和 ADC 噪声可能转成频率阶跃。Q8 半音步进约 **0.390625 音分**，是否可闻取决于噪声与变化速度；先测静止旋钮，再决定小死区/平滑，不要照搬压力的慢响应。

完整 ADC 码扫描发现相对理想连续 ±2 半音映射的最大误差约 **1.228 音分**（ADC=417），仅锚点间插值误差最大约 **0.935 音分**。旧注释“全范围不超过 0.8 音分”不成立。对原型演奏并不严重，应先订正文档；后续可用更准确锚点或小型低速比例表改善。

### P2-04：软复位保留旧 ADC 状态

定位：`top.v:387-421`。控制分频、`adc_sel`、`pressure_raw`、`bend_raw` 没有 `rst` 分支，只依赖配置初值。复位期间 ADC 主机被重置，顶层仍会轮换通道与发 start，原值寄存器保留旧值。本轮在弯音满量程后按 S3，观察到 `bend_raw=4095` 继续保留，释放后再采样恢复。

这不是持续失效，但下一次起音可能短暂使用旧弯音/压力，装配调试时容易误判。建议复位时回到压力无载/弯音中心并管理两路有效标志，拿到有效采样后再启用表情。不要据此新增复杂的外设断线推断。

## 4. 资源与计算预算

本轮资源基线引用队友同一提交内的 Gowin 标准档报告，并核对真实资源类型：Logic **3687/20736**、Register **1415/16173**、BSRAM **2/46**、DSP 宏块 **6.5/24**。DSP 内含 **1 个 MULT18X18 + 6 个 MULTALU36X18**；不能把 6.5 宏块写成“6.5 个 18×18 乘法器”。本轮未做新综合，不能给优化后节省多少 LUT/DSP 的实测结论。

### 已值得保留的实现

共享双 pROM、读邻点插值、全局交叉混合是正确方向，当前只用两块 BSRAM，没有 LUT 大表、没有 DDR 逐样本读取。84 拍固定完成四声部，标准档每帧 256 拍，余下 172 拍可供后续调度；这不等于已有 172 拍可直接容纳任意效果。

### 可直接减少浪费的候选

`pressure_bend.v` 正半程使用 32 位分子除常数 2047，位宽与一般除法形式可能造成不必要的组合逻辑。在默认中心 2048 时，令 `d=adc-2048`、`0≤d≤2047`，有严格等式：`floor(512*d/2047) = (d==2047 ? 512 : d>>2)`。负半程为 `-((2048-adc)>>2)`。本轮对全部 **4096 码验证完全一致**。这是不改变默认映射的低风险优化；若继续支持任意 ADC_CENTER，保留一般公式的参数分支即可。具体节省多少资源仍需后续小范围综合确认。

`shared_wavetable_engine.v:86-88,120` 用 32×32→64 位通用乘法器，每拍计算；实际操作数由 17 位差值×9 位小数、16 位样值×17 位正包络、16 位样值×8 位力度构成。可尝试统一成 **18×18→36 位**并显式符号扩展，保留中间结果的精确截位；先复用本轮独立 2048 组参考，再看综合映射。工具可能已按有效位宽优化，未测前不把它算成确定浪费。

四路弯音相位增量现在每路都有组合乘法，实际比率只在低速控制更新。进一步扩声部时，可把增量缩放移到控制调度或引擎共享乘法时隙，缓存结果；Note On 仍需在下一帧前更新。这会比复制 32 路宽乘法更有效。

`clk_params` 迁移仍漏了板载 S1/S2 的固定去抖计数：标准档变为 **85.33 ms**，调试档是 38.84 ms。它不是音符键 1 ms 的延迟，现场手感会变慢，应按时钟参数推导。已存在的宽 32 位 SPI 分频计数器也可缩到 `$clog2(HALF_DIV)`，收益小，排在声音控制之后。

### 32 声部应如何规划

当前 FSM 每声部 21 拍，串行 32 声部需 **672 拍**，超出 12.288 MHz / 48 kHz 的 256 拍预算。旧头注释“每声部 9 拍、整机 36 拍”已经过时，不能据它估计吞吐量。

建议保持标准音频时钟，采用 **4 条共享引擎，每条 8 个声部**，单引擎计算窗口约 **168 拍**，给提交与求和留 88 拍。双表 ROM 为 **8 块**，比逐声部复制 64 块可控；声部上下文按读写端口与包络布局预计再留 **2-4 块**，总 **10-12/46 块**。8 声部小步验证可先用一条引擎，但必须改上下文、累加位宽和分配器，而不是只改 VOICES。

乘法器规划按四条 18×18 共享数据通路预留 **4 个物理 MULT18X18**，低速弯音换算、全局混合与增益另预留 **6-8 个物理 18×18 等效单元**，合计暂按 **10-12 个**规划；同时要求 Gowin 报告 DSP 宏块低于 **16/24**，保留布线余量。这些是待验证的预算，不是由 6.5 宏块直接线性外推。若工具把较宽乘法映射到 MULTALU36X18，重新按报告核算。

32×48 kHz 的条件吞吐量为 **1,536,000 振荡器样本/秒**。必须交付 32 个独立相位/频率/包络状态、连续帧截止断言、32 个不同频率的可闻谱峰和对应资源报告；表中 16 次谐波不计 16 个独立波表振荡器。

延迟方面，本轮标准档“GPIO 原始边沿 → 第一个内部非零样值”为 **1048.541 µs**，尚未计 DAC、模拟链路或可听阈值。默认 Attack 满幅约 **9.77 ms**，Decay 约 25.60 ms，Sustain 释音约 19.92 ms；Attack 是音色特性，不能直接等同控制计算延迟，也不能在验收时忽略声音检测阈值。可加一个短 Attack 测试音色，用来测纯链路响应，再单独展示乐器音色。

PCM5102A 的 FLT 低延迟档可免增 FPGA 资源缩短滤波延时，建议安排 A/B。现有 FIR 是低通平滑库，而且没有进产品顶层，不能把它作为已完成“混响/延迟/合唱”的效果器。优先做 **4096×18 单声道短延迟**：48 kHz 下 85.33 ms，需 **4 块 BSRAM**，反馈/混合先预留 **2 个 18×18 乘法器**；若结合上述 32 声部计划，BSRAM 预算约 **14-16/46**、物理乘法器预算约 **12-14 个**，依然要求新综合确认后再承诺。先做有界反馈和旁路即可，不必一次实现混响网络。

亮音色含最多 16 次谐波，当前 C4-B4 与 ±2 半音区间在 48 kHz 下有余量；未来放宽到高音区要用分频段波表或限制谐波，否则过 Nyquist 的分量会混叠。不要为“24 位槽”把全链一律改成 24 位，当前主要瓶颈是控制功能、头部余量与实机证据，16 位链路已能形成完整样品。

标准档 `clip_fold` 被丢弃后，压力、削波和 ADC busy 没有对用户有用的诊断输出。与其再占排针引脚，先用低速 UART 读出原始/滤波压力、弯音、削波计数和活跃声部；这也能减少上板找问题的时间。UART 命令扩展属于协议变更，需另行确认后实施。

SDC 目前只有输入基准时钟，没有外部 I2S/SPI 的输出/输入延迟建模；内部 setup/hold=0 违例不能单独证明外设采样时序。首轮用逻辑分析仪确认 DIN 相对 BCK 和 ADC DOUT 稳定窗口，后续按数据手册补 I/O 约束。标准档已使用薄封装消除无约束端口，这项已有改进应保留。

## 7. 来源、复现和交付边界

官方规则已在本轮联网核对：[高云 2026 选题二](https://www.gowinsemi.com.cn/university/match2026)。其基础要求包括两维控制、四声部、HDL 实时生成与 ≤10 ms；拓展包含 32 复音/等效单元、三维表情、两音色、效果器、低延迟及反馈，评分按可闻独立振荡器×实际采样率。48 kHz、24 位槽是本项目的接口目标，官网正文并没有把它单列为基础硬门槛。

硬件依据：[Sipeed 官方资料](https://wiki.sipeed.com/hardware/en/tang/tang-primer-20k/primer-20k.html)、本机 Dock 3714 与 SOM-3961 原理图、[TI SLAS859C](https://www.ti.com/lit/ds/symlink/pcm5102a.pdf)、[Microchip DS21298E](https://ww1.microchip.com/downloads/en/devicedoc/21298e.pdf)。原理图和手册引脚表已先转 Markdown、再渲染核对；未把 OCR 直接当精确接线依据。
