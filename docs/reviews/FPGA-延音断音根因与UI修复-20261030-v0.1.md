# 延音断音根因与 UI 修复

用户补充现象为“踏板标识一直亮，但延音突然断”。本轮按当前32声部HDMI生产链排查了ADC采样、压力滤波/阈值、输入事件及来源管理、延音队列、所有全局清音来源、跨时钟域传输、声部调度/包络、主混音与UI状态来源。确定存在一条与该现象吻合、可在真实顶层复现的错误清音路径。未采集现场原始压力与声音，因此不能说现场所有异常均已排除。

## 确认的原因

CH9350L解析器 `ch9350_rx` 默认 `WATCHDOG_MS=2000`，从最后一次有效通知/报告开始计时。默认 `IdleOnly` 策略在没有物理持键时仍输出 `link_timeout`。松开琴键后踩踏板延音时，物理持键数已经是0，但延音模块的 `deferred` 和调度器的 `gate` 仍有效。

旧 `instrument32_top` 将 `hid_link_timeout` 无条件接到 `manual_flush` 和 `clear_events`。因此键盘静默约2秒后，`clear_events` 清掉待发事件、延音 `deferred`，并通过 `ram32_board_engine.clear` 复位计算域和声部。FSR检测本身不由 `clear_events` 复位，压力仍被识别为按住；UI随后再次显示PEDAL DOWN，听感就是踏板仍亮而余音被突然切断。它也可能切断串口来源的音符和正常释音尾音。

修复前真实顶层仿真输出：

```text
TIMEOUT_TRACE policy=1 held=0 pedal=1 clear=1 deferred=1 gate=1
FATAL: IDLE_TIMEOUT_CLEARS_SUSTAIN_WITH_PEDAL_DOWN
```

这说明上轮只针对短时压力低谷增加防抖，没有覆盖这个真正发生在控制清音链路的缺陷。此次保留原有防抖，不再加长压力时间窗口。

## 最小修改

32声部顶层新增 `hid_audio_timeout = (HOST_KBD_TIMEOUT_POLICY == 0) && hid_link_timeout`，仅把严格模式超时送往全局清音。默认IdleOnly超时仍清理HID本地状态，不复位乐器声音或延音。明确的0x86设备拔出通知、Esc/Space紧急清音、UART Panic、模式/音色/曲目切换和复位继续走原保护逻辑。

未改变ADC SPI、压力阈值、FSR2/40样本确认、延音算法、声部数、包络、波表或音频运算。没有新增BSRAM或音频乘法器。32声部用满后原有声部抢占仍可能使最旧音符结束，这是容量策略；本轮没有擅自改变分配架构。

## 验证

新增真实顶层 `tb_fsr_idle_timeout`，保留原ADC/音频核心/CDC/32声部和实际watchdog计数逻辑，只把超时缩短至4ms，并在已解码UART事件和稳定踏板边界注入测试信号，绕开逐字节串行等待与上电等待。修复前触发上述断言；修复后输出 `held=0 pedal=1 clear=0 deferred=1 gate=1`，踏板状态与音符均保持，真正松踏板后释音。另验证设备拔出仍清延音、HID Panic仍触发全局清音。

`tb_fsr_idle_strict` 以POLICY=0验证超时仍清音，输出 `held=0 pedal=1 clear=1`，通过。首次测试登记误把Strict条目指向IdleOnly文件，门禁按文件名选顶层而使其重复运行默认策略；此结果不作为Strict证据。现已分离Strict顶层文件并单独补跑，真实policy=0日志见归档evidence/strict。其余定向验证为FSR滤波与延音、延音背压/重复音、UI状态编码及文字布局；没有重跑无关历史Full或长时间生产曲目测试。

## UI 微调

真实RTL渲染确认，PEDAL DOWN原区域只能容纳8个字符；PRESSURE/VELOCITY原标签区不足8字符；状态值区域不足以显示GUITAR、MANUAL、PAUSED，采样率只能显示到46.87；底部MPR121说明与下一字段相挤。不是字体字库缺少这些字母。

微调文字区域：踏板行加宽；长标签和三位值错开列起点；普通状态值保留6个完整字符；采样率改用短标签FS以完整显示46.875 KHZ；顶部模式说明左移，保留右边距。底部按当前实际输入显示USB KEYBOARD。主面板、波形、声部矩阵、配色、字体ROM和像素流水线保持原样。

测试逐字符检查PEDAL DOWN、PRESSURE、VELOCITY、46.875 KHZ、GUITAR、MANUAL、PAUSED与USB KEYBOARD，并检查每个字符最后一列仍在显示区域；另外保留声部计数与矩阵像素自检。前后1024×600 PNG来自真实RTL逐像素PPM转换，不是重新绘制的示意图。受影响区域另以原字库做4736个字形像素采样对照，差异为0；脚本解析字库生成器的静态字形定义，不执行或改写字体ROM。
