# 第六项 32 声部原型审核

2026-10-21。结论：独立的 32 声部通用音色原型在修正后通过功能、已测帧预算与内部时序审核。审核发现并直接修复了四个错误；原先的 967 拍预算高估了余量，实际最后活动为第 992 拍。当前仍不是完整的 32 声部钢琴/吉他生产版本，生产 8 声部和用户确认的少表方案保持不变。

| 发现的问题 | 修改前证据与修正 |
|---|---|
| 排队事件干扰当前扫描 | 搜索时比较 `ev_q_note`，后续排队事件会改写它，导致重按 62 后出现两个同音声部、active=5 而预期 4。改为比较当前事件锁存的 `note_q` |
| 年龄计数回绕 | 满 32 路后重按最新声部会使最老声部年龄 31→0，下一次窃声错误地替换声部 1。改为 0..31 相对排序，仅移动比所选声部更新的排名；70 次重按后仍正确选择最老声部 |
| 配置背压丢失及负载竞态 | `cfg_pend` 不论 ready 都下一拍清零，负载还直接引用会继续变化的状态。改为锁存包络/力度/重触发，valid/data 保持至握手；旧事务等待期间的新重按保持 dirty，下一事务继续递送；避免配置摘除与音乐状态更新同拍竞争 |
| 力度截断为静音 | 8 位输入 128 直接取低 7 位，得到 0。现与第一项约定一致，将 128..255 饱和为 127 |

四个短用例在修改前均按预期失败，修改后均通过。测试已纳入门禁，默认执行全部四项，未把“成功复现失败”当作原功能通过。上述修正限于 `rtl/prototypes/voice_sched32.v` 内部逻辑，没有更改原型端口、生产顶层、波表或数据格式。

原 `tb_ram32_complete` 保留 32 路分配、包络、逐声部相位步进、最老声部窃取、同音重按、松键归零等断言；本轮新增独立 I2S 解码及真实帧尾计数后通过。解码了 151 个立体声帧，其中 148 帧低 8 位非零，左右声道与送入串行器的 24 位样本逐位一致，没有降为 16 位输出。该检查证明本原型的数字传输，未证明与生产钢琴/吉他音色相同。

原预算把配置当作每声部 3 拍，再与渲染相加，没有完整计入调度器请求和握手间隔。现在以最后一次音频结果或 RAM 配置写完成的实际沿计数，已测最晚 992 拍，小于测试上限 1016 拍；帧长 1024 拍下余量为 32 拍。它覆盖当前 32 路包络更新和所测事件，不能直接保证未来加入全部生产功能后的最坏预算，也不代表任意持续超出 ready 容量的源流量都能接受。

| 修正后独立原型 PnR | 结果 |
|---|---:|
| 计算时钟 / 采样率 | 49.152MHz / 48kHz |
| Logic / Register | 4635 / 2252，较初版增加 410 / 26 |
| BSRAM | 5/46：正弦 1＋通用明亮 3＋状态 RAM 1 |
| DSP | 报告 1/24，具体为 2 个 MULT18X18 |
| Fmax / 建立裕量 | 51.922MHz / +1.085ns |
| 保持裕量 / 负裕量端点 | +0.425ns / 0 |
| 最差路径 | `env_ptr` 到 `dirty` 使能，16 级 |

只对修正后的原型做了一次新构建。18 个原型输入构建前后 SHA256 相同，当前源码和保存位流均与凭据匹配；生产 `debug8usb` 的 192 个输入与位流仍匹配第五项凭据。新原型增加的资源换来了正确的事件与握手处理，时序仍满足本次计算时钟约束。

精度预算方面，RAM 核心把 16 位表提升为带 8 位小数的 24 位声部数据；包络 16 位、力度 7 位，32 路累加使用有符号 32 位。单路幅度不超过约 2^23，32 路总和不超过约 2^28，在累加器范围内；主路径按 32 声部归一化并输出 24 位，当前测试削波计数为 0。测试验证了低位仍被传输，没有追加的 16 位截断；单声部相对 8 路归一化路径更小的电平属于混音缩放，不能据此判断音质下降。

本原型输入是外部事件端口，使用正弦/通用明亮表，尚未接入钢琴 12 表、吉他 30 表、键控/阶段处理、生产滤波与控制链路。5 块 BSRAM 不能用来宣称生产音色的 32 路只需 5 块。若共享第五项全部波表并加当前状态 RAM，静态表块预算为 25＋1＝26/46，仍需针对新增状态、乘法调度、整体控制与时序重新评估；这里没有擅自实施集成。

49.152MHz 由测试和时序约束给定，原型没有产生该时钟的 PLL/时钟源；PnR 也没有板级 CST 和 IO 延时验收。现有单 lane 在 27MHz/46.875kHz 的 576 拍内放不下，49.152MHz 是验证过的一个方案，不是所有 32 声部实现唯一的时钟选择。接入板卡前应确定时钟、管脚及 IO 约束，再做完整产品验证；本轮没有烧录、完整长门禁或模拟听音。

更正前源码、失败/通过日志、一次新 PnR、输入指纹和位流在 `docs/evidence/FPGA-优化06审核-20261021-v0.1`；关键归档为 `archive/FPGA-20261021-v0.8`。临时仿真和 PnR 目录在关键报告及位流留存后按清单清理，工具环境及已有构建保留。使用 `audit_changes.patch` 或 `before/` 可回退本轮修正；回退后需重新仿真、构建，不能沿用修正后的位流。

检索参考了开源 [XLS32 时分复用声部引擎](https://github.com/kazunori279/xls32-fpga-synth/blob/main/README.md)，本项目已有 RAM 核心，本轮没有引入外部源码或新增运行依赖。
