# 第四项优化效果审核

2026-10-21。第四项“事件仲裁关键路径优化”审核通过。新增一拍事件暂存切开了 FIFO/仲裁到声部分配器的组合链；现有证据和本轮定向检查支持功能保持、时序改善。本轮没有修改生产 RTL，没有重新综合或烧录。

审核核对了同一 `debug8usb` profile 的前后报告、输入指纹和位流。两次构建的输入差异只有 `rtl/top.v`，约束、ROM、构建入口和 HID 审核修正相同；当前 222 个输入均与成功凭据内容一致，整组摘要、位流 SHA256、工具版本也匹配。第四项代码相对第三项归档仅增加事件寄存器并调整分配器输入。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| Fmax（同为 27MHz 约束） | 31.938MHz | 39.408MHz，增加 23.4% |
| 最差建立裕量 | +5.727ns | +11.662ns，增加 5.935ns |
| 最差保持裕量 | +0.319ns | +0.318ns |
| 最差路径逻辑级数 | 23 | 20 |
| 建立/保持负裕量端点 | 0/0 | 0/0 |
| Logic / Register | 11537 / 3689 | 11668 / 3705，净增 131 / 16 |
| BSRAM / DSP | 40/46，1.75/24 | 不变 |

暂存增加一个音频时钟周期，在 27MHz 下约 37ns。分配器每拍均能接收事件，连续流可以每拍递送一次；`clear_events` 同时禁止源消费与暂存事件递送，下一拍 valid 归零，因此清音不会重放旧事件。Note ownership 在暂存前顺序处理，保留不同来源共享同一音高时的松键保护。

原实现已有 14 台定向通过日志，本轮检查其覆盖范围，没有重复运行。新增并运行 `tb_event_prefetch`：使用实际顶层、实际手动 FIFO、仲裁、归属逻辑、事件寄存器和分配器，只在源边界注入事件，填充阶段暂停消费。30 个预期事件严格按序递送，检查模式切换首键仅发声一次、共享音高的 Note Off 抑制、满 16 项队列同拍替换、17 个连续 Note On、连续 Note Off，以及 Panic/模式切换取消已暂存事件。全部断言通过，运行退出 0，约 2.43ms 仿真时间。测试已加入现有门禁。

审核直接修正了原说明的统计和结论：131 是 Logic 净增量，不能写成 131 个 LUT，更不能把寄存器混入其中；16 个寄存器是全设计综合净变化，RTL 暂存声明为 17 位。约束未改变，不能把映射差异解释为换了时序约束。当前最差路径仍是事件寄存器到分配器选择逻辑，说明该路径仍限制全设计 Fmax，只是裕量已经足够。面积继续优化是否影响时序，需要测量，不能提前下结论。
