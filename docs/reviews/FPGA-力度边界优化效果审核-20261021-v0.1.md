# 第一项优化效果审核

2026-10-21。审核结论：**力度边界修复有效，第一项可以标记为功能完成。** 未发现这次改动引入的实现回归。本轮只生成审核材料，没有修改生产实现或原测试台。

`shared_wavetable_engine.v` 在增益乘法前把大于 127 的输入饱和到 127。最大增益字段为 `127×256=32512`，落在 15 位无符号数范围内；合法力度 0..127 直接透传，原来的乘法、舍入和调度保持不变。原测试中的力度 128 从内部样值 0 修复为 66017，与该固定相位、满包络条件下的力度 127 相同。这个数值是内部测试样值，不是声压或 dBFS 指标。

| 审核项 | 确认结果 |
|---|---|
| 原缺陷对照 | 同一边界台在 `2d3db6c` 引擎上因力度 128 静音退出 1，新引擎通过 |
| 合法力度兼容 | 当前引擎与旧引擎直接逐位比较，合法力度使用相同输入；越界力度的旧引擎参考输入取 127，结果相同 |
| 独立覆盖 | 768 帧、2304 组双分量有符号结果；4/8 声部、本地/外部共享乘法、0/2 额外小数位、钢琴/吉他/通用与键控旁路；包含负样值和帧内力度变化 |
| 相关短回归 | `tb_velocity_bounds`、`tb_key_gain`、`tb_frame_velocity` 均通过；独立比较同时检查有效时刻、乘法请求和操作数 |
| 构建内容对应 | 优化后凭据的 222 个输入 SHA256 全部匹配当前文件，位流 SHA256 匹配原文件 |
| 资源与时序 | 前后均为 Logic 11379、寄存器 3686、BSRAM 40/46、DSP 1.75；Fmax 31.039MHz，setup +4.820ns、hold +0.214ns |

`tb_generic_bright`、`tb_piano_engine`、`tb_piano_morph` 的失败在旧、新引擎上均复现，原因一致。第一台仍期待旧的 108 拍/40 次乘法，实际为加入键控增益后的 120 拍/44 次；后两台仍要求钢琴表号 42/46，与现有 36 表布局不符。它们是已有测试维护问题，不影响本项效果确认，本轮不扩展处理。

这次优化完成的是非法力度输入的边界保护，正常演奏范围的音色、音高与响度保持原状。按用户要求，效果确认后停止扩测，不重新运行完整长门禁或重复 PnR，也没有烧录。可继续优化路线的第二项“构建内容绑定与可复现生成”。
