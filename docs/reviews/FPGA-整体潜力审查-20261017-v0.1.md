# FPGA 整体潜力审查与高指标路线

日期：2026-10-17。生产基线：`4512edff7c4992053db293439ff6240f37368378`。本轮检查当前生产代码、综合报告和官方赛题，补充实际 RTL 捕获与引脚级 ADC 探针，不修改生产 RTL、不运行完整门禁、不烧录。音频、控制和竞赛要求由三个独立审查任务交叉核对。

当前架构已经节省了大量计算资源，但仍是固定四声部，且存在整机控制滤波、重按瞬态和低电平精度问题。要明显超出比赛要求，建议把目标定为 **64 个独立可闻声部、真实 48 kHz 输出、低混叠、平顺控制与可证明的延迟**。先建立可靠音质，再提高有效吞吐量。64 声部属于待实现目标，不能用现有综合余量代替实现证据。

## 已确认的现状与新证据

[高云官方选题二页面](https://www.gowinsemi.com.cn/university/match2026)规定基础至少四声部、两个独立演奏维度、纯 HDL 逐样本合成、I2S 至 DAC 和不超过 10 ms 的控制响应；拓展包括至少 32 路独立声部或等效合成单元，以及更丰富的表情和反馈。评分核心为同时活跃、可闻的独立振荡器数乘实际输出采样率，内部过采样不单独计分。48 kHz、24 位和本报告提出的音质阈值是项目自定目标。官方没有强制使用 MPR121；本项目已采用 GPIO 键盘主路线，旧最低实现文档仍需统一。

当前生产配置实测综合为 Logic 4408、FF 1738、BSRAM 2、MULT18X18 1；四声部完整计算 81 拍，每个标准音频帧 256 拍。综合资源报告不是布线后时序报告。标准 I2S 槽宽为 24 位，`top.v:560-563` 仍是 16 位声音补八位零，不能称为 24 位有效音质。

新增音频探针捕获七组音高及弯音条件，每组 8192 帧，共 **57344 帧**。当前 RTL 的相位、两条波形分量和最终音频，与独立定点模型逐样本零差异。探针加快帧之间的等待，DDS 频率字按 48 kHz 解释；它验证算法数值，串行输出时钟仍由前轮真实顶层 I2S 测试覆盖。证据为 `evidence/2026/10/FPGA-整体潜力审查-20261017-v0.1/ceiling.csv`、`metrics.json` 和 `simulation.log`。

| 优先级 | 问题 | 当前依据 | 下一次验收应证明什么 |
|---|---|---|---|
| P0 | 压力滤波重复消费旧采样 | 真实 top + MCP3208 引脚模型：只有一笔 CH0=4095 毛刺，滤波输出达到 3071 | 单笔异常新采样被中值抑制；阶跃与最坏相位响应单独测量 |
| P1 | 重按、窃声、数字静音会硬切波形 | `adsr.v:39-46` 清零旧包络，`shared_wavetable_engine.v:163-166` 重置相位；`top.v:539` 直接静音 | 全相位事件注入；瞬态高频残差比现状降低至少 20 dB，新增响应不超过 1–3 ms |
| P1 | 高音区缺少随音高带限 | 固定 16 谐波表，而 UART 接受 MIDI 1..127；实际 RTL 捕获与谱模型一致 | 全音域与全弯音范围，非预期混叠分量目标低于 -70 dBc；跨表无突变 |
| P1/P2 | UART 与 GPIO 的同音所有权缺失 | `voice_alloc.v:54-58,117-120` 合并同音、任一来源的 NoteOff 均撤销 gate | 两来源先后按同音，松开任一来源，另一方仍能保持；最后松开才释音 |
| P2 | 低压力与尾音量化明显 | 多次缩至 16 位；独立定点模型的低电平残差如下 | 保留保护位，统一最终量化，输出低位真正携带结果；不要仅扩大槽宽 |
| P2 | 弯音噪声与帧内参数一致性 | 原始弯音无平滑；音高、比例已按帧快照，力度在声部计算中才读取 | 静止小抖动不造成调频；快速扫动额外响应不超过 2 ms；事件扫满 256 个帧相位 |

压力问题的原因是 `top.v:391-397` 以 2 kHz 节拍交替读两路，每路新数据实际为 1 kHz；`pressure_bend.v:90-93` 却每个 2 kHz tick 都推进三点中值历史。一笔毛刺会在历史中占据两次，输出轨迹为 `0 → 2047 → 3071 → 1535`。现有模块测试假设每 tick 都是新样本，因此没有覆盖这个整机组合。新增探针的 PASS 表示缺陷成功重现，不表示产品已通过抗毛刺验收。

建议每 500 微秒顺序完成两路采集，再分别以新样本有效信号推进各自滤波。当前一笔 SPI 约 77.31 微秒，两笔约 154.62 微秒，占控制周期约 31%，有调度空间。预计无需增加 DSP 或 BSRAM。若只把滤波改成 1 kHz 新采样更新，压力响应也会变慢，必须重测；不能沿用前一轮 2.90 ms 的结论。该结论原本也是固定相位的内部增益响应，并未测最坏相位或模拟 DAC 输出。

弯音探针交替输入 2047、2049，实际比例在 65532、65540 之间每毫秒切换，约 0.211 音分峰峰值，完整调制周期为 2 ms。这证明原始 ADC 波动没有被平滑，并未证明实机必然出现可听噪声。当前数值比例误差仅约 0.033 音分，继续增加插值段数的收益小于处理传感器噪声和中心校准。

亮音色在 48 kHz 下的最高谐波从 MIDI91 开始超出奈奎斯特频率，满幅正弯音会使起点提前到 MIDI89。下表是当前源波表中越界谐波的能量占总交流能量比例，用于估计折叠风险，不是 DAC THD、SINAD，也不是从输出 FFT 中直接分离得到的混叠能量。

| 音高条件 | 实际基频约 Hz | 源表越界能量 dB |
|---|---:|---:|
| MIDI60 | 261.625 | -97.16，仅表量化底噪级别 |
| MIDI71 | 493.883 | -96.05，仅表量化底噪级别 |
| MIDI89，+2 半音 | 1567.987 | -26.08 |
| MIDI91 | 1567.981 | -26.08 |
| MIDI96 | 2093.001 | -17.80 |
| MIDI108 | 4186.003 | -11.18 |
| MIDI127 | 12543.846 | -4.33 |

建议按弯音后的实际相位增量选择 16/8/4/2/1 谐波表，并在边界过渡。保持正弦和亮音色同时读出的保守方案，一路引擎约需四块 BSRAM，较当前增加两块，仍可复用乘法器。这里需要解决跨表连续性，不能只把 ROM 地址拼接一下。当前 GPIO 的 C4–B4 音域没有明显谐波越界，此项主要改善 UART 高音和后续更宽音域。

同一独立定点模型，以约 440 Hz 正弦、力度 100、当前固定余量，拟合去除基波和 DC 后测残差 SNR：满包络、单位压力为 **83.20 dB**，最低压力为 **71.82 dB**；包络降到 256 时分别为 **35.34 dB、23.60 dB**。这是稳态数值模型，未包含模拟噪声。它说明尾音和弱奏值得优化。应先研究至少 18 位内部有效结果、宽累加和统一舍入，必要时复用 DSP 拆积；最终让 24 位传输低位承载有效结果。是否保留一个乘法器应由周期、音质和交付成本共同决定。

## 能够明显超出要求的实现路线

建议把 32 声部作为架构验证台阶，把 **64 声部 × 48 kHz = 3.072M 独立振荡器样本/秒**作为后续主目标，相当于目前四声部吞吐量的 16 倍、32 声部拓展门槛的两倍。每路必须保持独立相位、频率和包络，并在测试模式下实际同时可闻。只增加数组长度或不可闻的计算单元不能算达标。

| 声部数 | 延用当前核心的帧拍数下界 | 最低计算频率 MHz | 相对当前单音再衰减量 dB |
|---:|---:|---:|---:|
| 4 | 81 | 3.888 | 0 |
| 8 | 157 | 7.536 | 6.02 |
| 12 | 233 | 11.184 | 9.54 |
| 32 | 613 | 29.424 | 18.06 |
| 64 | 1221 | 58.608 | 24.08 |
| 128 | 2437 | 116.976 | 30.10 |

这是 `19×声部数+5` 的算术推导，不包含新增状态 RAM、事件、保护位和跨表调度，不能当作完成时限。衰减列按实际声部数精确归一化计算；12 声部若采用向上取整的除以 16 移位，单音还会相对当前额外下降 12.04 dB。8 声部在现有 256 拍中有研究空间；12 声部只剩 23 拍，不适合继续叠加去爆音或更多精度。扩大声部时按声部总数固定衰减会降低单音输出，因此宽精度必须与扩声部一起设计，不能单独追数量。

优先研究 **49.152 MHz 的两条共享计算通路，各处理 32 声部**，保留真实 48 kHz 输出，不增加外部器件。时钟候选由已有 12.288 MHz 音频时钟经 FPGA PLL 产生，仍需检查 PLL 配置和布局布线。每通路每音频帧可用 1024 拍，原计算约 608 拍；余量分配给状态存取、ADSR、宽精度和短尾处理。它比直接假定单通路能跑到高频更容易留出实现余量。设计预算暂定 2–4 个 18×18 乘法器、总 BSRAM 不超过 16 块、Logic 不超过 70%；这是预算，不是综合结果。双通路采用独立 ROM 端口、状态 RAM 分银行，避免读口争用；所有高精度与去爆音开销都必须重新排表。

目前综合估算中，弯音寄存器至比例快照存在约 20.8 ns、25 级逻辑的路径，49.152 MHz 周期约 20.35 ns。需要先把低速系数计算分拍并注册结果，再重新综合和 PnR。现有报告的默认 10 ns 分析关系及负 slack 不是当前 12.288 MHz 的布线结论，也不能用于承诺升频可行。

若优先避免 PLL 改动，可先采用多条较小共享核完成 32 声部。若坚持一个 DSP，则可研究缓存弯音后的相位增量：比例只随控制更新，没必要每帧重复四拍；但必须解决背景计算、音符事件冲突和整帧原子提交。两者均应在实现前确认架构，不能把推导当作已可部署方案。

建议的自定验收目标为：全音域非预期混叠低于 -70 dBc；约 440 Hz 正弦、满包络、力度 100、单位压力增益下，数字残差 SNR 不低于 92 dB；重复按键和窃声高频瞬态残差下降至少 20 dB；正常按键到模拟音频起音目标不超过 3 ms，压力 90% 响应目标不超过 3.5 ms。数字事件接受后，输出提交抖动限制在一个采样周期内。异步物理按键不能承诺绝对零抖动，应该报告最大值、分布及采集条件。上述音质和延迟均为待验证目标。

扩展测试需证明 64 路状态独立、64 个测试基频谱峰实际可见、每帧更新全部包络，并在最坏事件突发、弯音跨表和复音结束条件下无丢帧。串口按需查询帧超时、事件丢弃、削波和活动声部数，不持续发送逐样本数据。音频效果器与演奏指引可在这些指标稳定后作为单独项目补齐。

## 执行次序、复现和边界

建议下一项首先修复压力新采样与滤波的配合，同时完善弯音采样状态；随后处理重按/窃声和静音过渡、帧内力度快照及多来源同音。第三步实现带限波表与宽精度。最后统一参数化声部、状态 RAM 与计算调度，依次通过 8、32、64 声部验证。每一项完成后单独报告，保留可回退提交。

本轮可复现入口如下，使用包含 numpy 的 Python 和既有 Icarus 工具，不依赖新增第三方工程：

```powershell
python tools/audit_system_ceiling.py
python tools/audit_system_ceiling.py --reuse-capture
python tools/audit_system_ceiling.py --control-only
```

第一个命令重新捕获 RTL，第二个只分析已有捕获，第三个重现当前控制缺陷。修复后第三个观察用例应替换成正向验收。生产代码仍为本报告开头基线；新文件仅为审查工具、探针及证据。全部相关临时编译文件在证据归档后清理；运行时工具环境、此前源码及用户未提交文档保留。
