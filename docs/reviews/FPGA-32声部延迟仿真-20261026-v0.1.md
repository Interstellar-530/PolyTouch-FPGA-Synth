# 32 声部延迟仿真

本次实测没有发现 32 声部造成明显数字响应延迟。相同架构下，8/32 声部的单音首个非零 I2S 样本延迟均为 67.668..83.293 µs，满载换音后首次输出变化均为 62.460 µs。32 声部增加了逐帧计算量及突发事件分配时间，但仍在一个采样周期内完成计算，没有出现跨帧积压。

## 测试范围与数据

使用当前源码中的 ram32_clocked_top，12.288 MHz 参考时钟、73.728 MHz 计算时钟、48 kHz/24 位 I2S，保留默认 Attack=140、Decay=16、Release=48、Sustain=45875。8 声部对照是同一 RAM 核心的 VOICES=8 配置，不是板上现用 shared_wavetable_engine 的完整 8 声部工程。波表使用真实内容的行为模型，PLL 不建模模拟抖动或亚稳态。

| 观测项 | 同架构 8 声部 | 32 声部 |
|---|---:|---:|
| 单音请求至首个非零 I2S 样本，4 个不同采样相位 | 67.668..83.293 µs | 67.668..83.293 µs |
| 满载后请求换音至首次 I2S 输出差异 | 62.460 µs | 62.460 µs |
| 从空闲突发输入直到全部声部分配 | 2.582 µs | 15.536 µs |
| 从突发开始到每个声部均产生过非零混音贡献 | 43.640 µs | 49.825 µs |
| UART 首个起始位至首个非零 I2S 样本 | 1020.710 µs | 1020.710 µs |
| 包络到达峰值 10% | 979.119 µs | 979.119 µs |
| 包络到达峰值 90% | 8791.603 µs | 8791.603 µs |
| 观测到的最大逐帧计算尾部 | 161/1536 拍，2.184 µs | 617/1536 拍，8.369 µs |
| 对应计算周期余量 | 89.52% | 59.83% |
| 已接收事件跨域至调度器 | 0.042..0.049 µs | 0.042..0.358 µs |

满载测试为每个配置建立两台相同核心，先输入完全一致的背景音并核对两个 I2S 输出一致，再只向其中一台输入新音符。第一次样本差异证明满载状态下新的按键已影响数字输出；该差异也可能包含被窃取旧声部的衰减，不能直接称为新音符独立声学起音时间。所有声部产生贡献通过核心累加器实际变化观察，并非仅检查 active_count。

UART 测试通过真实 kbd_uart_rx、CH9350L 解析器和当前 hid_keymap 输入 11 字节键盘帧，波特率为 115200，未强制内部事件。理论串行传输时长约 0.955 ms，是约 1.021 ms 数字链路测量中的主要部分。起点不包含实体键盘扫描、USB 轮询及 CH9350L 模块内部处理，终点也没有包含 PCM5102A 模拟滤波和耳机响应。

默认起音包络到 90% 需要约 8.79 ms；它是有意设置的幅度渐变，不代表声音直到此时才开始。首个非零样本仅代表数字起点，听觉阈值仍取决于力度、混音增益、负载与输出电路。4 个事件相位和一组满载音符属于定向观测，不能替代所有情况下的最坏延迟证明。

## 竞赛含义与边界

[官方规则](https://www.gowinsemi.com.cn/university/match2026)要求控制至音频输出不超过 10 ms，拓展目标为不超过 5 ms。本次测得的核心数字响应及包含 UART 的数字路径均低于 5 ms，但未覆盖整机输入到模拟输出，不能据此宣称整机已经通过竞赛延迟验收。

这组结果支持继续集成 32 声部：逐帧计算增加约 6.185 µs，没有使已测音频输出多等一个采样周期。当前板上仍为 8 声部；规划中的 27 MHz→54 MHz、46.875 kHz 板级版本没有在本次测试中实现或验证。

只新增 tb_ram32_latency、结果提取工具和测试登记，没有改变音频 RTL。测试执行一次，63.90 秒通过，未运行 Quick/Full，未综合或烧录。归档为 archive/FPGA-20261026-v0.9，保留原始日志、完整输入清单及 SHA256 绑定；临时仿真程序在归档核对后清理。
