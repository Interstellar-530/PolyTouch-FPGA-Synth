# 零外设可执行任务（2026-10-12）

当前条件是 Tang Primer 20K Dock 3714、USB-JTAG Type-C、板载 PT8211 与耳机可用，外接 MPR121、FSR/MCP3208、PCM5102A 和 12.288 MHz 晶振尚未到手。本机已验证 COM13 可打开并收到旧 Flash 程序的 `ERR` 回复。GitHub `main` 有四声部 RTL，但板上仍是旧 Flash 测试程序；四声部代码在板上可用尚未经验证。10 月 10 日的[旧版零外设规划](../../planning/零外设可实施功能与设计-20261010.md)中“当前单声部”“串口尚未确认”的状态已过期。

现阶段最有价值的工作是把数字合成核心做到能仿真、能布局布线、能通过板载耳机和 UART 演示。每次修改生产 Verilog 后，先运行 `output/handoff_milestone2_20261008/source/sim/run_simulation.ps1` 并使新增测试自检通过，再决定是否烧录 SRAM。Flash 只在稳定版本完成后更新；所有拟新增声部、波表和效果先重算 BSRAM、18×18 乘法器及 DSP 宏块预算。

| 优先级 | 现在可做的工作 | 计划团队工时 | 没有外设时的完成标准 |
| --- | --- | ---: | --- |
| P0 | 修复 ADSR 松键后卡在 RELEASE 的缺陷，定义重新触发、快速重复同音、声部窃取和归零行为 | 8–12 h | 新增逐周期自检覆盖 ATTACK、DECAY、SUSTAIN 松键、释放归零和重按；原仿真门禁全部通过 |
| P0 | 清理事件 FIFO 满载、Note Off/Panic 优先级、演奏/演示模式隔离和串口控制台旧 `F` 命令 | 8–12 h | 注入满队列及非法命令均有确定回复或计数；自动曲目不抢手动声部 |
| P0 | 将修复后的当前四声部主分支烧录到 SRAM 做板载回归 | 4–6 h | 耳机与 LED、COM13 的 `N/O/X/M` 指令均经实测；断电后原 Flash 基线仍可恢复 |
| P0 | 实现四条流水线、每条八个独立声部的 32 声部内核及 512 点双音色 ROM IP/原语 | 32–44 h | 32 个独立相位与包络同时活跃；帧截止断言、最坏混音、PnR 资源和时序通过；板载 PT8211 能演示多音 |
| P1 | 统一混音增益、饱和与 clip 计数，给现有滤波提供旁路，再加可旁路短延迟 | 8–12 h | 最大同相输入和最大反馈不回绕；数字采样差异可复算，耳机能听到开关效果 |
| P1 | 先以虚拟器件完成标准 I2S、MPR121 I2C 和 MCP3208 SPI 控制器/输入适配器 | 8–12 h | 仿真核对 I2S 位对齐、LRCK/BCK 帧宽、I2C ACK/IRQ、SPI 采样和断线异常；标记为“数字接口已验证” |
| P1 | 从 RTL 捕获 PCM 样本，生成多音频谱、频率误差、削波与每帧周期证据 | 4–6 h | 证据可由脚本重复生成，并与对应 Git 提交、测试日志和构建报告绑定 |

前四项约需 52–74 团队工时，可以在等外设期间推进；P1 再需约 20–30 小时。估计值应随第一轮实测调整。若新增工时有限，先完成 P0 前三项并给传感器接线、外部时钟和实际延迟测量保留联调时间；32 声部可先以仿真/PnR 验证核心，不应为了赶声部数挤掉四声部整机验收。

板载 27 MHz 时钟和 PT8211 足以做合成算法、复音、UART 与听感回归。拟议的 12.288 MHz / 48 kHz 正式链路可以先用仿真时钟做数字协议测试，但没有外接晶振和 PCM5102A 时，不能声称板上已达到真实 48 kHz I2S 输出。MPR121/FSR 可以先用行为模型送事件，不能证明触摸灵敏度、压力标定或物理操作到模拟输出不超过 5/10 ms。没有外部测量设备时，也不能给板级底噪、模拟频谱、时钟质量或端到端延迟出实测结论。

当前四声部构建实测使用 4/46 BSRAM、12/48 个 18×18 乘法器、6/24 DSP 宏块，27 MHz 建立/保持检查无违规。32 声部目标采用四条时分流水线共享波表和乘法器，预计基础配置约 24 块 BSRAM、乘法器不超过 24 个；这是预算，实施后必须重新综合、布局布线并检查音频帧截止。直接复制现有四声部结构到 32 路会超出乘法器容量。

外设到货后再做 J14 时钟实物连通/电压检查、触摸与压力标定、PCM5102A 模拟音频检查、物理触发到声音的延迟统计。具体引脚、库存与预算见同包的审查报告和 Excel 清单。
