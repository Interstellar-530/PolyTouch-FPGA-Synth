# 第七项优化：CH9350L 长按与断线策略

2026-10-22。第七项“长按与断线策略”的软件侧已经完成，实体帧定案和 10 秒硬件长按仍待外设到位。当前默认策略不再让持键期间的 2 秒静默超时清音，同时保留严格模式和 0x86 立即拔出清音。

## 修改依据与实现

原实现把 `ch9350_rx.link_timeout` 直接送入 `hid_keymap`，只要 2 秒没有完整帧就清空所有按键。若 CH9350L state 2 在长按期间不周期发帧，这会把正常长音截断。新增 `TIMEOUT_POLICY` 后，默认 `1` 只允许无持键时的静默超时通过；`0` 保留旧行为。`held_count` 由现有键位状态机提供，策略只增加一个可综合 mux，不修改协议、音频链路或外部端口。

顶层增加 `HOST_KBD_TIMEOUT_POLICY` 编译期参数并传到 `host_kbd_input`。`0x86` 的 `device_notify` 仍直接清键，不经过超时策略。

## 验证

三台定向仿真通过：`tb_host_kbd_timeout` 覆盖 5 秒无心跳持键、strict 兼容、0x82 心跳和 0x86 拔出；`tb_host_kbd` 覆盖原键位与控制行为；`tb_top_host_ctrl` 覆盖 `HOST_KBD_ENABLE=1` 顶层路径。`standard27` 与 `debug8usb` 均完成 Gowin 综合和 PnR，负裕量端点为零。

`debug8usb` 当前 Logic 11378、Register 3702、BSRAM 25/46、DSP 1.75/24，Fmax 35.885MHz，setup +9.171ns、hold +0.319ns。相对 v2.1.0 公布的同一档位，Logic 少 14、寄存器不变，时序仍为正裕量；最差路径是原有事件队列到声部分配器，不在本项新增逻辑上。

## 证据与边界

证据在 `docs/evidence/FPGA-优化07-长按断线策略-20261022-v0.1`，包含测试与构建日志、资源时序 JSON、两档报告和复现脚本。关键文件归档到 `archive/FPGA-20261022-v0.1`，含源文件、目标位流、说明、MANIFEST 和 SHA256。原始 Gowin run 与临时仿真目录已清理，位流本体保留在归档 `artifacts/`，可用复现脚本加 `-RunBuild` 重建。

本项没有实体 CH9350L，未完成 10 秒硬件长按、真实空闲/拔线帧捕获，也未烧录或运行完整门禁。若实物不提供心跳且拔出也不发 0x86，持键拔出仍存在粘音风险；此时需要抓帧后再决定是否启用严格模式或增加外部断线检测。回退方式为设置 `HOST_KBD_TIMEOUT_POLICY=0`，或撤回 RTL 修改并重新构建。
