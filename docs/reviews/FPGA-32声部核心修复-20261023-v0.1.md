# 32声部核心修复与验收

本轮接续 `67a9aaf` 及其未提交构建修复，范围是完成32声部核心的构建、音频自检和延迟验证。板级档、灯光、合唱不在本轮范围。归档为 `archive/FPGA-20261023-v0.8`，正常源码入口仍为 `output/handoff_milestone2_20261008/source`。

## 修复

Gowin将 `14'd4096?13'd4096` 中的问号继续解析为数字未知位，导致EX3132/EX3863；加括号和空格后编译正常。控制前级的音量曲线仅作为头文件引入，构建脚本为生成工程复制相同目录结构，避免把函数定义当作独立模块源。

首次真正PnR显示计算域只有40.657MHz，72个setup违例。关键路径从音高查表直接经过32×17位弯音乘法、舍入与饱和。本轮将三个步骤寄存分隔，配置在有效数据完成前保持等待，背压时保持整包稳定。随后将压力/音量合成、增益斜坡及包络变化到脏标记的控制路径拆拍，关闭剩余时序违例。没有放宽时钟约束或新增多周期/假路径。

主混音增加两拍内部延迟，原有两次共享样本乘法和定点运算不变。复位首帧静音时，组合过程可能因输入保持初始化值而未计算，已改为连续组合赋值。旧 `ram_audio_compute` 将新增音量端口显式接为256单位增益。相关背压和固定周期测试更新为包含流水延迟的边界，原有数据断言保留。

## 验收证据

最终Gowin报告：73.728MHz约束下Fmax75.564MHz，setup最差+0.330ns，hold最差+0.337ns，setup/hold违例均0；Logic6243/20736、Register2929/16173、BSRAM26/46，3个MULT18X18及1个MULTALU36X18，厂商报告DSP利用量2.5/24。DSP原语数和厂商占用单位不是同一口径，不将二者混写。

Ram32专项5项通过：旧完整核心、ROM、控制前级、调度器背压/窃声/重按和新增完整音频引擎。新增测试用真实波表模型，独立按64位有符号运算核对2135帧，覆盖197帧精确零与1938帧非零；32音最大力度不削波，压力、音量、静音、弯音及复位后恢复通过。最大帧尾617/1536拍，计算余量59.8%。宽混音8192帧测试核对3589次真实饱和削波，不回绕。Quick18项和旧8/32/64路RAM音频兼容专项4项通过。未运行Full长回归。

延迟在12.288MHz参考与73.728MHz计算域的RTL仿真中打点：输入接受至调度器0.042至0.283µs；单音事件至首个非零I2S样本83.293µs；32事件全部分配15.543µs，突发开始后125µs检查点已验证32声部进入音频路径。测试使用Attack65535/帧、Sustain65535以单独测数字流水；正常默认Attack140/帧、外部UART传输和上游队列等待均不能算进这组数字，也未被这组数字验收。

## 交付与边界

归档包含修改前副本、最终完整源码、真实实现报告和原始门禁结果。`tools/verify_ram32_core_release.py` 核对归档源码与三组门禁的逐文件SHA256，检查时序违例并生成 `validation.json`。回退时只恢复 `source/before/` 对应文件，不覆盖其他任务改动。

该实现仍是无实体引脚绑定的32声部核心原型，位流仅作为实现证据，不能直接烧录。尚未完成的任务是32声部正式板级CST/SDC、外设集成和灯光；模拟音频、晶振、线路和真实键盘延迟待实物验证。
