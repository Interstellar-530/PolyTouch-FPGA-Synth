# PolyTouch v1.0.0 源码导读

本导读对应用户选择的 SRAM `0x5633` 功能基线。生产源文件位于 `source/rtl/`，电脑控制端位于 `tools/serial_keyboard/`。阅读顺序建议为 `top.v` 的模式与事件仲裁，接着看 `voice_alloc.v`、`poly_voice.v` 和 `adsr.v`，最后检查采样节拍、歌曲队列与 UART。注释解释已有实现，不把后续外设规划当作可运行功能。

## 数据如何从音符变成声音

演示链路是 `song_player → event_fifo → top 仲裁 → voice_alloc → 四路 poly_voice → mixer → pt8211_tx`。手动链路从 `uart_ctrl` 输出事件，经过同一个顶层仲裁器，进入同一个声部分配器。它没有先进入歌曲 FIFO；FIFO 当前只缓存演示事件。`tools/serial_keyboard/keyboard.ps1` 把电脑键盘按下与松开转换成 N/O 串口命令，没有生成音频。

音符事件是 16 位 `{on, note[6:0], velocity[7:0]}`：bit 15 表示按下/松开，bits 14:8 是 MIDI 音符号，bits 7:0 是力度。`ev_valid` 是一个 27 MHz 时钟周期的有效脉冲，分配器在这一拍接收事件。`gate` 是持续状态，表示声部是否仍按住；`v_start` 是每次接受 Note On 的单拍重触发标记。这三者不能互相替代，也不能把保持数百个时钟的电平当成一次采样脉冲。

| 模块 | 输入、输出与关键职责 |
| --- | --- |
| `top.v` | 电源/按键复位，演示与手动状态，事件清理和仲裁，四路声部接线与 LED |
| `uart_ctrl.v` | UART 位接收、ASCII 命令解析、音符/模式单拍事件、静音状态和 OK/ERR 回复队列 |
| `song_player.v` | 根据采样节拍推进旋律与和声，把一个最多 8 项的事件组逐项交给 FIFO |
| `event_fifo.v` | 默认 16×16 位环形队列，输出空/满及 `wr_ready`；当前地址宽度固定为 4 |
| `voice_alloc.v` | 同音复用、空闲选择、释放声部复用及最老声部窃取，输出各声部 gate/note/velocity/start |
| `note_phase_inc.v` | MIDI 音符转 32 位 DDS 相位步进值；12 个基频常数按八度左移 |
| `poly_voice.v` | 保持重触发请求至采样拍，组合 DDS、ADSR 与力度乘法，输出 16 位有符号样本 |
| `dds_osc.v` | 512 点正弦表查找、相邻点线性插值、相位累加与重置 |
| `adsr.v` | Idle/Attack/Decay/Sustain/Release 状态机，输出 16 位幅度和真正空闲信号 |
| `mixer.v` | 四路相加、主电平缩放、有符号饱和、5 抽头 FIR 平滑 |
| `pt8211_tx.v` | 1.5 MHz BCK 和 PT8211 专用字格式，发送左右相同样本，产生单拍 `sample_tick` |

`song_roms.vh` 是曲谱事件常量，由 `source/tools/gen_song_rom.py` 等生成；`wave_sine.hex` 是实际音频波表。这两类 ROM 用途不同，不能因曲谱常量使用小型 `case`，就用大 `case` 实现后续音频波表。历史综合确认当前波表占用 BSRAM，后续双音色和扩容应按项目要求使用 Gowin BSRAM ROM IP 或原语并重新计算资源。

## 顶层模式和复位的含义

`por` 在配置后计数 65535 个 27 MHz 时钟，约 2.43 ms 后释放；`pa_en` 只跟随这一路电源复位。S3/D7 同步后产生设计复位 `soft_rst`，与 `por` 合成 `rst`，清零声部、UART 和模式状态；设计复位后重新进入演示。和声选择与速度寄存器仅在 `por` 中初始化，不能假设按 S3 会把所有调试选择都恢复到上电档位。S1/S2 两级同步后按约 38.8 ms 的按下稳定时间处理，S1 切换和声，S2 依次选择 1×、2×、3×、4× 时长；默认速度索引 1 即 2×。

`demo_mode` 是持续模式状态。D0 和首次 N/O/X 使它变为手动；D1 使它变为演示并重启歌曲。手动时 `song_player` 被保持复位，不再生成歌曲事件。`clear_events` 在模式变化、X 或演示内重启时清掉 FIFO，并令声部分配器执行 Panic，把旧声部门控置低。Panic 不是同步强制把所有包络和混合样本清零：一般仍会有 Release 尾音，数字静音 M0 才在输出处直接选零。

从演示切换到手动的首条 N/O 事件先进入 `pending_word`，下一拍通过 `pending_valid` 重新送出，防止它与清理动作同拍时被 Panic 优先级吞掉。普通手动事件直接参与仲裁。顺序为清理优先，接着暂存的首次手动事件、UART 直接事件、演示 FIFO。UART Note Off 和 Note On 使用同一优先级，不允许歌曲事件延后覆盖手动松键。手动模式按 S2 可以改变速度选择，但不会清理当前手动声部。

`uart_muted` 是独立的持续状态，M0/M1 不切换模式。顶层 `final_sample` 在设计复位或数字静音时为零；PT8211 时钟不因普通设计复位停止，发送器自身仅跟随电源复位。这种分离用于保持输出串行时序，不等同于模拟噪声或开关声的实机保证。

## 采样、包络与声部回收

主时钟为 27 MHz。PT8211 每个 BCK 半周期 9 个主时钟，BCK=27 MHz/18=1.5 MHz；一个左右帧为 32 BCK，因此采样率为 46,875 Hz，`sample_tick` 每 **576 个主时钟**出现一次，宽度只有一拍。`note_phase_inc` 使用 `round(f × 2^32 / 46875)`；未来改成 48 kHz 外时钟音频路径时，必须同步更新频率常数和时间参数，不能只换串行发送器。

`dds_osc` 的相位高 9 位 `[31:23]` 选择 512 点表，`[22:14]` 提供 9 位插值小数；下一点索引在 511 后回到 0。两个 16 位有符号表值作差后乘小数，舍入并加回当前值。相位只在采样拍推进，查找与插值输出寄存器每个主时钟更新，以分开插值和包络乘法的组合路径。插值改善波表离散误差，不消除超带宽谐波的混叠或模拟底噪；本轮没有进行新的噪声测量。

`voice_alloc` 接收一次 Note On 后，输出一拍 `v_start`。音符事件通常不落在采样边界，`poly_voice.start_pending` 将请求保持到下一采样拍，使相位和包络一起重新开始。若在采样前已松键，`restart_sample` 被 gate 阻止，不会再起音。Note Off 仅降 gate，ADSR 从 Attack、Decay 或 Sustain 在下一采样拍转入 Release。曾经的缺陷是在 gate 低时每拍重复设置 Release，导致其减法分支无法执行；现条件排除已处于 Release 的状态，使包络持续递减。

包络用 16 位无符号线性步进，默认 Attack=140、Decay=16、Release=48、Sustain=45875，约为满幅 70%。这些参数是每采样拍的步长，改变采样率会改变实际时长。Idle 表示包络已归零；释放阶段 gate 已低但仍在发声。`voice_alloc.v_busy` 当前直接等于 `v_gate`，它不是“仍有尾音”的检测量，回收判断应结合 `voice_idle`。

分配顺序为同音且仍按住的声部、包络已零且 gate 低的声部、最老释放声部、最老仍按住声部。年龄用 0 到 VOICES−1 的相对排名，0 最新，最大最老，避免普通累计时间戳长期溢出。重复同音不会创建重复占用；满四声部的新音则重用选定声部并重新起音。被窃取旧音随后收到 Note Off 时，只匹配仍按住且音符号相等的声部，不会把已经换成不同音符的新声部松掉。

每声部的幅度乘法是波形×包络，再×力度；加上 DDS 插值共 3 个乘法，四声部历史报告为 12 个 MULT18X18、6 个 DSP 宏块。`mixer` 先把四路样本按 18 位相加，默认主电平除 2，再限幅到 −32768…32767，最后按 `(1,4,6,4,1)/16` 作 5 抽头平滑。除 2 仍可能让四个同相满幅音发生饱和，不能称为任意和弦都不会削波；饱和与平滑也不能替代后续音频测量和抗混叠设计。

## 事件队列与串口状态机

`song_player` 的基础单位计数仅由 `sample_tick` 推进，`tick_pulse` 必须同时满足采样拍和计数终点。旋律时长与和声时长分别维护，最多 8 项的事件组先安排全部 Note Off，再安排 Note On，避免先抢占本来就要释放的声部。`bactive/bidx/bmask/bdata` 保持当前组状态：有效项在 `ev_ready=0` 时保持原内容与索引，禁用项可跳过；时序表不是标准 MIDI 文件播放器。

FIFO 的 `wr_ready = !full || (rd_en && !empty)`，允许开始时满但同拍被读取的队列接收新项，确保连续事件顺序。写接受条件是 `wr_en && wr_ready`，读接受条件是 `rd_en && !empty`；每项只能在真正接受后前进。指针额外高位区分空和满；当前 `AW=4` 固定，所以虽然接口暴露 `DEPTH` 参数，不能直接只把 DEPTH 改为任意值并假设仍正确。16 项事件 FIFO 与 16 项 UART 回复队列是两套独立缓冲，不能混用它们的背压信号。

UART RX 按 Idle/Start/Data/Stop 收取 8N1 字节，接收线经过两级同步。解析状态区分 Note、Mute、Demo、Panic；行结束后校验参数，再输出单拍 `ev_valid/panic/demo_on/demo_off`。UART Note On 固定使用 DEFAULT_VEL=100，不是实时压力输入，也不是二进制 MIDI 协议。TX 按 Idle/Send/Wait/Done 把回复拆成字节；回复队列存储每条是 OK 还是 ERR，按顺序输出，溢出只计数，不提供主机侧硬件流控。

`sample_tick`、`ev_valid`、`v_start`、`panic`、`demo_on/demo_off` 和 `tick_pulse` 均属于单拍控制；`gate`、`demo_mode`、`muted`、`bactive`、`tx_busy` 是持续状态；`ev_ready/wr_ready` 是当前拍是否能接收的握手条件。扩展 GPIO、ADC 或第二音色时应先明确属于哪种语义，再连接到这个边界，避免重现采样使能被误当作脉冲的历史错误。

## 仿真与构建入口

从仓库根目录运行 `source/sim/run_simulation.ps1` 的实际完整路径，命令见[发布说明](v1.0.0.md#复现运行与回退)。脚本先以 Icarus `-g2012` 编译，再运行 `vvp`，九个测试台全部成功才退出 0；任何编译失败或自检 `$fatal` 都阻止烧录。

| 测试台 | 验证重点 |
| --- | --- |
| `tb_tick_rate` | 采样拍间隔符合 576 个主时钟的预期，当前测试容差为 ±1 |
| `tb_song_timing` | 一轮旋律/和声的 Note On 总数和采样时长 |
| `tb_adsr` | 各阶段松键、归零、释放中快速重按 |
| `tb_voice_retrigger` | 同音重按、满声部窃取、释放声部复用 |
| `tb_voice_order` | 长期演奏后的相对年龄与最老选择 |
| `tb_event_fifo` | 环绕、空满保护、满队列同拍读写和顺序 |
| `tb_song_backpressure` | FIFO 暂停接受时保留歌曲事件，恢复后不丢失 |
| `tb_mode_uart` | 真实串口字节到顶层事件、模式切换、非法命令与回复顺序 |
| `tb_poly` | 顶层复位、默认速度和板上按键行为 |

`tb_pt8211_tx.v` 也存在于历史目录，但不在当前九项门禁清单；不能将“目录有文件”当作“默认已执行”。tb_tick_rate 在 v1.0.0 修正了旧 Hz 显示公式，打印约 46,875 Hz；计数/容差断言不变。tb_mode_uart 强制加速 sample_tick，不能作为真实节拍音频捕获。Python render_preview 也是参考试听工具，不是 RTL 等价证明。开发者增加测试须更新门禁列表并让断言失败返回非零；模拟电气和外设实测另行验收。

`source/build/build_instrument.tcl` 创建或打开 Gowin 工程，指定器件和顶层，加入 11 个 RTL 模块、CST/SDC 后运行综合与布局布线。`build.ps1` 可自动发现 Gowin，也可指定 `-GwSh`。`program_sram.ps1` 默认先运行仿真门禁，然后操作 2 写入指定 FS；没有指定文件时优先取本地最新构建，所以要复现历史 `0x5633` 应显式传入版本化历史位流路径，不默认为新构建就是同一文件。本次发布不执行该烧录步骤。
