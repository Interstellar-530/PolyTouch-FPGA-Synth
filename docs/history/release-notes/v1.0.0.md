# PolyTouch v1.0.0：四声部演示与电脑演奏基线

本版本整理用户确认的 SRAM 模式修复版（历史板上 User Code `0x5633`），为现有代码补充注释、源码导读、复现入口和版本化位流。它作为第一个正式代码主版本发布，功能及 ASCII 协议沿用已验收实现；本轮不增加外设功能，不重写 Flash，也不重新烧录开发板。此次本机未枚举到 COM13，发布基线由用户指定，不能据此声称已实时读回当前板内配置。

生产工程继续保留在 `source/`，避免维护两份会分叉的 RTL。模式修复对应 Git 提交 `057d78c` 后的生产逻辑；电脑端演奏窗口是配套控制程序，声音仍全部由 FPGA 生成。唯一非注释的测试台修改是修正 tb_tick_rate 的 Hz 打印公式：半周期 18.5185 ns 改为完整周期 37.037 ns，不改时钟、计数或断言。模块、状态与事件时序见[源码导读](v1.0.0-code-guide.md)，本轮验证结果由 [v1.0.0-validation.json](v1.0.0-validation.json) 记录。

## 已有功能

当前实现为四声部，每声部独立 32 位 DDS 相位累加器、512 点正弦波表、线性插值、ADSR 包络和力度缩放。同音重按复用原声部并重新起音；声部用尽时优先使用空闲声部，其次最老释放声部，最后窃取最老按住声部。松键在 Attack、Decay 和 Sustain 阶段均可进入 Release，包络归零后才成为可完全空闲的声部。

演示模式自动播放《兰花草》，S1 切换两组和声，S2 切换四档速度并从头重启演示。歌曲事件通过 16 项队列送到声部分配器，满队列时播放器保持尚未接收的事件；同拍读写满队列也可接受新事件。`D0` 清理演示事件并进入手动等待，`D1` 清理原声部并从头演示；`N`、`O`、`X` 也会自动进入手动模式，首次手动音符不会被模式清除动作吞掉。

串口为 115200、8N1、无流控，ASCII 命令以 CR 或 LF 结尾，命令字母不区分大小写。电脑演奏窗口支持真实按下/松开、和弦、自动重复抑制、失焦和关闭时全松键。映射为 `A W S E D F T G Y H U J K` 对应 MIDI 60–72，即 C4 到 C5；`A/D/G` 是 C 大三和弦，`H` 是 A4。第五个同时按下的音会触发四声部窃取，电脑键盘本身的多键识别也可能限制组合。

| 命令 | 行为 |
| --- | --- |
| `N1`–`N127` | Note On，默认力度 100；进入手动模式 |
| `O1`–`O127` | 松开对应音符；进入手动模式，保留 ADSR 释放尾音 |
| `X` | 所有声部门控置低并进入手动模式；释放尾音仍按包络衰减 |
| `D0` | 清除演示队列与原声部门控，进入手动等待音符 |
| `D1` | 清除原声部与队列，从头启动演示 |
| `M0` / `M1` | 数字静音 / 解除静音；不改变演示或手动模式 |

合法命令回复 `OK\r\n`，非法命令回复 `ERR\r\n`；空换行不回复。音符号 0、越界参数、旧 `F` 命令，以及 `D01` 等不符合参数长度的命令会被拒绝。回复端有 16 项队列；极端连续灌入可以溢出，`reply_drop_count` 饱和计数记录丢失回复。电脑端应等上一条应答再发送下一条，不将 `OK` 解释为模拟音频已经验收。

## 硬件及版本边界

目标是 Tang Primer 20K Dock 3714，GW2A-LV18PG256C8/I7、版本 C。板上 27 MHz 时钟通过 PT8211 发送器生成 46.875 kHz 采样节拍，BCK 为 1.5 MHz，左右声道发送相同的单声道混合结果。PT8211 是板载调试路径，采用其专用右对齐格式，当前发送器不能当作 PCM5102A 的标准 I2S 驱动。

该基线没有 GPIO 琴键、MPR121、ADC/FSR/电位器、外部 PCM5102A 标准 I2S、12.288 MHz 外时钟驱动，也没有双可选波表音色、32 声部、显示或效果器。因此 v1.0.0 是可复现的当前阶段基线，尚未完成竞赛最终硬件要求。没有使用软核 CPU；Dock 的 USB-UART 桥只提供串口数据通道，不参与声音合成。

历史模式修复构建使用 Gowin V1.9.11.03 Education，报告为逻辑 4596/20736、寄存器 741/16173、BSRAM 4/46、DSP 宏块 6/24（其中 MULT18X18 12/48）。27 MHz 约束下历史 Fmax 为 44.191 MHz，建立/保持违规端点均为 0。这些是[事件模式调试日志](../logs/2026/10/FPGA_DEBUG_LOG_20261012_EVENT_MODE.md)中的既有构建证据，不能替代未来功能扩展的重新综合，也不是本轮新运行 PnR 的结果。

本版本收录的 [instrument_sram_0x5633.fs](../../../releases/2026/10/FPGA-20261013-v0.1/target/instrument_sram_0x5633.fs) 来自 `archive/FPGA-20261012-v0.6/deliverables/event_mode_fixed.fs`，SHA256 为 `2C7C7001DD3EABF24D2A4ABC2FC93BE1DD441D76812E248B3B84A235DBD22675`。这是历史已烧录、读回 `0x5633` 并通过串口模式检查的位流。重新综合得到的文件字节与 User Code 不保证相同，不应为了凑 User Code 而替换源代码或把新构建当作原始位流。

SRAM 配置掉电失效。Flash 中旧程序历史读码为 `0xFCF0`，可冷启动播放《兰花草》，但不支持 `D0/D1`；从此旧 Flash 冷启动后需重新配置本版本到 SRAM，才能使用电脑演奏窗口的模式按钮。旧 Flash 写入曾出现 Gowin `SPI Verify failed`，虽已通过用户断电播放与串口验收，全量逐字节校验仍未通过；此问题不能用进程退出码 0 掩盖，详见[Flash 冷启动日志](../logs/2026/10/FPGA_DEBUG_LOG_20261012_FLASH_BOOT.md)。

## 复现、运行与回退

在 Windows PowerShell 5.1 中进入仓库根目录。Icarus Verilog 是开发期仿真器，不在 FPGA 上运行；Gowin 只在综合与配置时使用。九项自检测试应全部通过，失败时退出码非零，禁止烧录。下面的 `-GwSh` 为本项目历史环境路径，其他电脑需换为自己的安装位置；脚本也支持自动发现或 `GOWIN_GW_SH`。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\source\sim\run_simulation.ps1 -Iverilog 'C:\iverilog\bin\iverilog.exe' -Vvp 'C:\iverilog\bin\vvp.exe'
if ($LASTEXITCODE -ne 0) { throw 'Simulation gate failed' }

# 需要重新综合时执行；仅构建，不会连接或配置开发板。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\source\build\build.ps1 -GwSh 'E:\Gowin\Gowin_V1.9.11.03_Education_x64\IDE\bin\gw_sh.exe'
if ($LASTEXITCODE -ne 0) { throw 'Gowin build failed' }

Get-FileHash -LiteralPath .\releases\2026\10\FPGA-20261013-v0.1\target\instrument_sram_0x5633.fs -Algorithm SHA256
```

构建 TCL 指定 `GW2A-LV18PG256C8/I7`、器件版本 C、顶层 `top`；输出在 `source/impl/pnr/instrument.fs`，并生成资源和时序报告。源码导读中的相对波表路径依赖工程根目录，已有脚本会设置正确运行位置，不宜从随机目录直接调用单个测试台。

实机重新配置属于操作者主动步骤，本次发布不执行。先关闭占用串口的窗口，用 `source/build/scan_jtag.ps1` 扫描当次 Cable/Channel/Location；设备重连后这些值可能变化，不沿用历史扫描位置。确认唯一目标板后，使用 `source/build/program_sram.ps1 -FsFile .\releases\2026\10\FPGA-20261013-v0.1\target\instrument_sram_0x5633.fs`；该脚本默认再次执行完整仿真门禁，使用操作 **2（SRAM Program）**。有多条 JTAG 连接时应在 Programmer 中选择正确的目标与操作，不盲用默认设备。操作 4 不作为这块板的默认流程，Flash 擦写也不是本次发布内容。

配置后用当前实际 COM 口启动电脑界面，关闭 PuTTY 等占用端口的程序。电脑端不需要 Python，使用系统 WinForms 和 SerialPort；下述自检不访问实机，界面启动则会访问串口。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\serial_keyboard\keyboard.ps1 -SelfTest
if ($LASTEXITCODE -ne 0) { throw 'Keyboard self-test failed' }
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\tools\serial_keyboard\keyboard.ps1 -Port COM13
```

`COM13` 是此前端口示例，设备枚举变化时改为当次端口。界面连接后进入手动状态并解除静音；最小实机检查为 D0、N69、O69、D1、X 各收到 OK，再确认按住/松开及三音和弦声音。已有用户确认这些电脑演奏操作正常，实际输入到模拟输出延迟尚未测量；历史 `M0` 静音后底噪基本不变，模拟供电、接地与输出链路仍需测量，不由本版本注释更新解决。

代码回退可检出发布前的已知提交，再按同一仿真门禁重建。仅加载 SRAM 时，断电会恢复板内原 Flash；要保持本版本断电自启动，须另做经过授权和完整验证的 Flash 发布，不能把 SRAM 发布等同于 Flash 验收。当前源码、历史位流与本轮证据分开保留，便于追踪和恢复。
