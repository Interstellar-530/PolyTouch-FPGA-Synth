## 二、上午：单声部链路（修订一到修订十一）

这一段解决的是"能不能出声、出得对不对"。

时钟与复位方面，确认核心板 27 MHz 晶振经 R20 送到 H11，并把 S1、S2 用作音高切换、S3 用作同步复位。烧录方面确认命令行读到 `ID Code 0x0000081B`，图形界面失败多半是电缆或器件没选对、两个编程器抢线、或用了会报读回校验错误的操作四类原因。码流后来写进板载外部 SPI Flash，掉电与按 S4 重配置都会自动加载。

噪声方面分出三条线索并逐条处理。先是配置格式：PT8211 用日式右对齐格式，原先 WS 相位差一个位，DAC 按错位的符号位重组字，听感是叠加在音调上的严重失真，按官方例程改写帧结构后正常。再是算法本身：查表时丢掉相位小数带来阶梯误差，加线性插值并补一级 (1,4,6,4,1)/16 平滑后，带内误差降到 -94.8 dBFS。最后是底噪：按住 S3 保持复位时"虫鸣"仍在，说明它不来自数字信号，后续只查供电与板级。

控制方面加入 115200 的 UART 频率控制接口，并发现先前把串口引脚记成 N6/N7 是读原理图读错的，正确的是 M11（TX）与 T13（RX），属于 Bank 2 的 3.3 V 调试串口。

## 三、下午：从单声部到可演奏的复音测试链路

### 1. 零外设条件下的规划

先盘点物料边界：手头只有核心板、底板和一根耳机线。Dock 3714 自带 PT8211、耳机功放和 3.5 毫米耳机座，所以"算声音并听结果"这条链路的硬件全在板上。据此写出三份清单：零外设可实施的功能与设计、需要示波器或逻辑分析仪或独立电源的调试任务、可以自行采购的外设与耗材；另外把 Git 通信检查与回退办法也写成一份文档。同时核实本机与 GitHub 的读写通道正常，并在当时可用的固件状态上打了 `v0.4-20261010` 回退标签。

### 2. 四声部复音与测试曲

把单声部扩成四声部：每声部独立的相位累加器、ADSR 与力度，四路求和后统一做饱和、平滑与主音量。新增歌词事件总线，事件字是 `{on, note[6:0], velocity[7:0]}`，播放器与 UART 都往这条总线写，将来 MPR121 触摸键盘只要驱动同样的信号即可接入。测试曲选《兰花草》，依据两份公开简谱转写成 G 多利亚调，并配两套和弦。

### 3. 三轮听感反馈带来的调整

第一轮反馈"太快、听不出旋律、音符之间没有间隔"。于是降速、加入气口（每个音提前释放）、拉开旋律与和弦的力度差。第二轮反馈"依然很快"，于是改按原谱重划节奏并加入 1 到 4 倍的现场调速档位。第三轮反馈"播一小段就重复、闪烁灯间隔只有零点几秒"，这一次没有再改参数，而是装了仿真器直接跑 RTL。

### 4. 三个由工具发现而不是由推理发现的问题

第一个是混音削波。四路相加后先做饱和再乘主音量，和弦被削平，峰值卡在 8192；改成先求和、再乘音量、最后饱和后恢复正常。这个问题是 Python 金模型先暴露的。

第二个是歌曲表被综合成内部存储器，初始化是否完整无法确认。改成由脚本生成常量 `case` 函数，彻底绕开存储器推断。

第三个，也是今天最关键的，是 `tick_pulse` 电平当脉冲用。`tick_cnt` 只在 `sample_tick` 到来时更新，到达顶值后会保持整整一个采样节拍（576 个 27 MHz 时钟），所以该信号是电平而非单周期脉冲；播放器按脉冲使用它，在一次事件突发后的约 570 个时钟里把音符时值计数器连减数百次，旋律一口气跑完整圈。这解释了前面两轮"降速无效"的原因。用 `sample_tick` 限定后恢复正常，仿真复验两圈间隔正好等于标称值。

### 5. 仿真成为强制环节

把"任何 Verilog 改动烧录前必须先过 RTL 仿真"写进项目 `AGENTS.md`，并由 `sim/run_simulation.ps1` 执行、`build/program_sram.ps1` 拦截。门禁上线当天就抓到两个问题：`reset_cnt` 缺上电初值导致仿真里上电复位永不完成；以及文档里的档位指示灯表写反了。

### 6. 收尾优化

按谱把每句统一为 14 个十六分音符，保留原谱三类句型；和弦由每句一个改为每句两个，A 套自然小调力度 30、B 套多利亚明亮色彩力度 46，进行与响度一起变；主音量提升约 6 分贝。现场认定合适的速度是 L14 亮、L16 灭，按真实逻辑即 2 倍档，已设为上电默认。

## 五、验证方式汇总

三种手段互相补位。Python 金模型按 RTL 逐模块等价重写，可以渲染出可试听的 WAV，并用 Goertzel 逐音比对音高与气口残留；RTL 仿真用 Icarus Verilog 直接跑源码，三个测试台分别量采样节拍、曲子长度与音符事件数、顶层连线与按键；Gowin 构建报告提供资源与时序数据，器件回读确认码流真的写进去了。
