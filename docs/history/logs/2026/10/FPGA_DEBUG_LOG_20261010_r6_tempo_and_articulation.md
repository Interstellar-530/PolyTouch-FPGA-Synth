# 调试日志：速度、气口与力度调整（2026-10-10 修订十三）

## 反馈

试听修订十二之后有三条意见：整体播放过快；复音各声部响度一致，听不出哪条是旋律；音符之间没有明显间隔，一句唱下来糊成一片。

## 分析

第一条是节奏参数问题。原来一个节拍单位是 3821 个采样点，每个音占 4 个节拍单位，也就是 326 毫秒一个音，而且是连续不断地往下走，听感相当于每分钟 92 拍上的一串八分音符。

第二条是配比问题。原来旋律力度 96、和弦力度 56，和弦有三个音叠加，实际能量和旋律差不多，加上伴奏是延音而旋律也是连音，两层糊在一起。

第三条是发音方式问题。原来一个音结束的同一刻下一个音就开始，加上 29 毫秒的释放段，等于没有间断。

## 改动

速度方面把四分音符降到 66 BPM，节拍单位变成 5327 个采样点（114 毫秒），每个音的槽加长到 6 个节拍单位。全曲由 23.5 秒变成 36.8 秒。

气口方面让播放器在槽位结束前两个节拍单位（约 227 毫秒）就发关音事件。实现上是在播放器里加了一个提前量判断，旋律计数器走到还剩两个节拍单位时先发一次关音，走到尽头再发下一个音的开音。因为关音和开音分别落在不同的节拍单位上，一次事件突发里仍然是所有关音排在开音前面，分配器不会误抢声部。

力度方面把旋律 ROM 的每一项从十六位重新划分成三位力度码、七位音高、六位槽长。播放器用一张八项表把力度码还原成具体力度值，每句第一个音取 127 作重音，其余取 104。和弦统一降到 32。

## 验证

金模型按同样的规则重写后重新渲染，两套和弦的峰值分别是 -9.2 与 -8.2 dBFS，没有触到饱和。逐音校验除了原有的音高比对，还加了一项：在同一个音的气口处用 Goertzel 测该频率的残留，要求低于发声段的 35%。41 个音的音高与气口检查全部通过，说明气口确实把音断开了，而不是只在参数上写了两个数。

综合与布局布线无警告，资源 4526 逻辑单元、780 寄存器、4 块 BSRAM、6 个 DSP，Fmax 37.880 MHz，零建立与保持违规。码流 SHA256 `a37094e1238a9f2c313bfbb4021ab1924dcd52f7c5afefe8334ec7fc32c4fe96`，User Code `0x00007F46`，已写入 SRAM 并回读确认。

## 还没验证的

66 BPM 与 227 毫秒气口是否合适、旋律是否已经能和和弦分开，仍然要人耳判断。如果还嫌快，可以继续降 BPM；如果嫌气口太长，把 GAP_TICKS 从 2 改回 1，改一个参数重新构建即可。
