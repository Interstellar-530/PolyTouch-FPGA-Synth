# FPGA 8声部候选修正说明（2026-10-23 v0.1）

本次修正关闭第二项审核发现的两个问题：原外设 SDC 只有主时钟，无法证明 I2S 与 MCP3208 的端口路径；历史候选说明建议用 `-Ptop.HOST_KBD_TIMEOUT_POLICY=0` 回退策略，但 `top` 是子实例，该参数写法不会可靠改变生产根模块。

## 修正结果

`top_std27_build` 与 `top_dbg8usb_build` 现在公开 `HOST_KBD_TIMEOUT_POLICY` 参数并向 `u_top` 传递。构建入口增加 `-HostTimeoutPolicy IdleOnly|Strict`，默认 `IdleOnly`；脚本按策略生成本次包装器，分别保存普通收据与 `.strict.json` 收据。烧录入口要求策略、生成包装器 SHA256、全部输入和位流同时匹配，否则在调用烧录器前拒绝。正确入口如下：

```powershell
& '.\output\handoff_milestone2_20261008\source\build\build.ps1' -Profile standard27 -HostTimeoutPolicy IdleOnly
& '.\output\handoff_milestone2_20261008\source\build\build.ps1' -Profile standard27 -HostTimeoutPolicy Strict
```

SDC 对六个动态输出设置 0至20ns 路径包络，对 `adc_miso` 设置 20ns 最大路径上界。`adc_miso` 不添加人为最小路径约束；该约束曾在 Strict 布局中产生 −0.261ns 的伪保持违例，且不能代替外部 MCP3208 的保持时间分析。端到端预算、资料边界与现场待测项见[接口预算](../hardware/standard27-interface-budget-20261023.md)。

## 验证证据

为避开共享工作区中其他 Agent 同时修改 32 声部源码造成的输入漂移，最终验证在 `archive/FPGA-20261023-v0.7/source/candidate/` 的不可变候选副本内完成。该副本是本次修正的精确验收对象，不自动覆盖随后出现的共享源码修改。

IdleOnly 与 Strict 均由 Gowin V1.9.11.03 Education 完成综合、布局布线和位流生成。两者 setup 与 hold 违例端点均为 0，内部 `clk_27m` 实际 Fmax 为 38.557MHz。资源为 Logic 11406/20736、Register 3674/16173、BSRAM 25/46、MULT9X9 1、MULT18X18 1、MULTALU36X18 1。IdleOnly 位流 SHA256 为 `87d5172c68f90dc60b2e403ff5ea2fdf295b46869fd1ed7cd998089f3e8f3f4f`，Strict 为 `cda471e27344eed654b7eba9ea93cb6e5ad73ac4dd24163ecf059e4fe6bc3b5e`。

六个策略传播用例通过，覆盖两个静态根模块和两份真实生成包装器。接口延迟仿真通过；预算中 I2S 建立/保持剩余 115.185/78.148ns，ADC 最小剩余为 CS 禁用间隔 470ns。烧录负例确认策略不匹配和包装器被篡改都会返回非零，模拟烧录器未被调用。Quick 门禁此前在同一候选基线上通过 18 项检查；SDC 最终变更不影响 RTL，最终两套实现另行完整通过。

## 边界与回退

本轮没有连接开发板、没有烧录，也没有宣称 PCM5102A 模拟输出或 MCP3208 3.3V 波形已实测。3.3V 下使用 800ns DOUT 有效时间和 500ns SCK 高低脉宽作为保守工程假设，硬件到位后仍须示波器验收。回退时恢复归档中 `source/before/` 的构建、包装器和约束文件；不应修改历史 v0.4 归档来伪造当时状态。
