# PolyTouch v2.0.0：USB 键盘调试档与 8 声部音频合流

发布日期 2026-10-21。本版把 GitHub 上最新的推送并入本线：基线是本机 `codex/s4-s6-pressure`（`6e8926e`，2026-10-20 22:04），并入 `origin/codex/guitar-preview-ddr3-20261020`（`1fd865a`，2026-10-21 00:29，含 `33d29af` USB 键盘/F SR 调试档、`754fc08` 演示模式松键与捕获门禁、`1fd865a` 音频门禁收敛与精确静音）。

两条分支同源于 `16f9c32`、工作区各自同步后独立提交，因此它们不是快进关系：远端是“USB 键盘档 + 静音修复”的一条线，本线是“8 声部音色 + 键控响度 + 24 位主链路”的一条线。本版按“保留功能超集、移植远端修复”的方式合流。

## 测试台重新基准化

本线的键控响度级给每个声部增加 **3 拍** 和 **1 次共享乘法**。四个按旧调度写死常量的测试台因此更新（断言值由实测得出，不是放宽判定）：

| 测试台 | 旧 | 新 |
|---|---|---|
| `tb_architecture_equivalence` | 60 拍 / 24 次乘法 | 72 拍 / 28 次 |
| `tb_shared_bend_equivalence` | 76 拍 / 32 次 | 88 拍 / 36 次（弯音共享省 8 拍已不足以抵消，比基线 84 拍慢） |
| `tb_bandlimit_engine` | 108 拍 / 40 次 | 120 拍 / 44 次 |
| `tb_timbre_top` | 114 拍 / 42 次 | 126 拍 / 46 次 |

同时 `tb_architecture_equivalence` 补上远端遗漏的 `note0..7`/`KEY_GAIN_ENABLE` 连接，并与 `tb_shared_bend_equivalence` 一起把随机力度约束到产品的 0..127 范围。

## 已知问题

1. **力度大于 127 会回绕。** `key_a` 只有 15 位，`C=256` 时 `vel*256` 在 `vel≥128` 处溢出：`vel=128` 变成静音、`vel=255` 回到约 1.0。当前所有输入源（CH9350L、GPIO、电脑界面）都固定 `VELOCITY=100`，所以现存音色不受影响；但外接 MPR121 或后续压力/力度映射必须先钳到 0..127，或把 `key_a` 与幅度通路加宽。
2. **`tools/gen_piano_prom.py` 不能复现入库的 `gowin_prom_piano_bank.v`。** 该脚本对应 10/20 之前的 hex 布局；当前波表请用 `tools/gen_epiano_bank.py` 生成，并用 `tb_piano_bank` 逐地址校验。
3. **`run_simulation.ps1` 现在会跳过“缺失的测试台”并计数**（远端改动）。这与“任何失败即退出 1”的严格口径有出入；恢复全量门禁前需要确认是否保留。
4. **资源与时序数字尚未按本次合流重测。** 归档证据里的 `debug8usb` 构建（Logic 11202/20736、Register 3596/16173、BSRAM 40/46、1×MULT18X18＋1×MULT9X9、setup +5.893 ns、hold +0.211 ns、位流 SHA256 `9F2A26E6…`）来自合流前的远端树，只能作为同档位参考。
