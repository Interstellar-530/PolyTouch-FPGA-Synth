# FPGA 算法、论文与开源参考（2026-10-13 v0.1）

当前工程已具备四个独立相位/包络声部、ADSR 重按和窃取处理、UART 音符接口、演示/手动隔离及板载 PT8211 音频。应保留这些已经仿真和实机验证的部分，先接入 GPIO 琴键、压力与标准 I2S，再用共享数据通路扩声部。查到的项目有可用的测试和架构思路，板卡、协议、采样节拍和 ROM 实现都需要按本机工程适配。本轮电脑演奏窗口使用现有 ASCII 协议，是独立编写的 Windows 控制端，没有复制外部项目源码。

## 2. 近期接入到哪些本地模块

GPIO 输入层建议新建 `gpio_keyboard.v`：两级同步、12 路独立消抖、按下/松开变化掩码、逐个事件输出。先处理 Note Off，再处理 Note On；满队列保持未发送位，Panic 和模式切换优先。现有顶层的首个手动事件延后一拍逻辑针对稀疏 UART，不能直接承接连续多键突发；需要手动来源 FIFO/握手后再接入。进入手动、从演示返回、Panic 时按键仍按住，以及四键同拍变化，都应有顶层回归。

SPI ADC 建议新建 `mcp3208_spi.v` 和 `control_filter.v`。FSR→CH0，B10K→CH1，先按约 250 kHz SPI、1～2 kHz 控制采样验证。ADC 事务跨多个音频帧独立运行，音频引擎只读最近完成的控制值，不能每帧阻塞等待 ADC。压力可先采用三点中值加一阶 IIR：`y = y + ((x-y) >>> 1)`；在 2 kHz 下响应时间作为起始预算，再按实测调整。不要一开始用很慢的平滑滤波挤占延迟指标。

压力先作为全局表情/双音色混合量，降低逐声部运算开销；无压力时保留可演奏的基础音量，避免仅按琴键却无声。机械按键是选音维度，FSR 是力度/表情维度，电位器可作第三维音色/效果参数。ADC 读到 0 或满量程不能单独证明断线，必须结合通道、接线和控制使能判断。

输出层建议新建 `i2s_tx.v`，按 12.288 MHz 生成 48 kHz LRCK、3.072 MHz BCK，标准 I2S 一位延迟，输出帧使用稳定样本寄存器。UART 的 CLK_HZ、DDS 频率字、曲目 UNIT_SAMPLES、ADSR 增量要随正式采样率一起调整。每个控制值在音频帧边界提交，音频序列器连续运行。当前 S1 改的是伴奏和弦组，不是第二张音色波表。

验证方法可化用 nishadsuresh 的 PCM/FFT 流程：从本机完整顶层捕获四音和弦，检查四个独立基频、松键归零、峰值和削波；软件生成的波形图不能代替 DAC 实测。所有新 Verilog 仍通过 `sim/run_simulation.ps1` 门禁，再做 Gowin PnR 和板上回归。

## 3. 扩声部与混叠的可行预算

本机已验证四声部报告是 4 块 BSRAM、6 个 DSP 宏块，报告内列 12 个 MULT18X18；宏块数和乘法器实例数不能混为同一指标。32 声部可参考时分共享思路，继续使用四条流水线，每条保存八个独立相位、频率字和包络状态。借鉴 xls32 的状态/引擎分离，不直接导入其 HLS 工具链或 Xilinx ROM 外壳。

以下是本项目的实现预算，**不是已经生成的 32 声部硬件结果**：每声部预留 16 周期，每条处理八声部，共 128 周期；再给混音、表情、控制提交与保护约 80 周期，合计 208/256，余 48 周期。每条两张 512×16 位 BSRAM 表，保守计八块 ROM；状态和小效果再另计块数。每条可先预算两只共享 18×18 乘法器，四条共八只，再加全局压力和简单效果约三只，共十一只，低于项目采用的二十四只保守上限。同步 ROM 延迟、乘法器流水线和有效标记必须纳入调度，帧截止断言要逐周期验证。

一张正弦表加一张限制谐波的亮音色表可先完成两音色。若只需当前 C4～C5 范围，亮表先限制为 16 个谐波，在 48 kHz 下最高谐波仍低于 Nyquist；离线生成 `.hex`，硬件用 Gowin BSRAM IP/原语。扩展到更高音区时再按频率选择带宽不同的表，增加表前重算 BSRAM。表内插值减少查表误差；表间缓慢混合减少音色切换突变；两者都不等于新增独立声部。DDR3 不放逐样本波表。

PCM5102A、GPIO 和压力联调完成后，再决定增加延迟、滤波或更多声部。每次扩展保留旁路和固定参数测试，先核对削波/数值回绕、同步状态与每帧周期，再听感比较。已经确认“数字静音后底噪基本不变”，这部分仍需硬件供电与模拟链路测量，混叠论文不能替代这些证据。
