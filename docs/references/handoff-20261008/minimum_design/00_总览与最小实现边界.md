# 最小实现算法设计总览

## 1. 目标与边界

本项目在 Tang Primer 20K Dock 3714 上实现一台可演奏的实时复音电子乐器。第一轮最低实现只追求稳定闭环，不把 32 复音、显示、蓝牙和完整效果器作为必须项。

| 项目 | 最低实现指标 | 说明 |
| --- | --- | --- |
| 复音数 | 4 声部 | 满足赛题 ≥4；代码用 `VOICE_COUNT` 参数化，后续可扩到 8/32 |
| 演奏维度 | 12 路电容触摸 + 1 路 FSR 压力 | 触摸负责选音/触发，压力负责力度或总表情 |
| 合成方式 | 单周期波表 + DDS + ADSR | 不播放预录 PCM，每个声部独立相位、频率和包络 |
| 音色数 | 2 种 | 每个声部用一个 1K×18 BSRAM 块装两个 512 点波表 |
| 采样率 | 48 kHz | 由外部 12.288 MHz 时钟整数分频得到 |
| 输出 | 标准 I2S 到 PCM5102A | 板载 PT8211 作为调试通路，不作为比赛 I2S 证据 |
| 延迟 | 目标 ≤5 ms，最坏 ≤10 ms | 主要延迟来自 MPR121 扫描和去抖 |
| 资源 | 4 个声部乘法器 + 1 个总增益乘法器 | 远低于 GW2A-18 的 48 个 18×18 乘法器 |

## 2. 算法逻辑

最小系统的算法主线是：MPR121 检测触摸键，MCP3208 采样 FSR，输入层生成 `NOTE_ON/NOTE_OFF/VELOCITY/Pressure` 事件；声部分配器把事件分配到 4 个声部；每个声部用 32 位相位累加器做 DDS，用 512 点单周期波表查表，用 16 位 ADSR 包络控制幅度；4 个声部在 48 kHz 采样 tick 上并行求和，做 2 的幂归一化和饱和裁剪；最后通过 I2S 发送器输出 24 位数据到 PCM5102A。整条音频路径只使用 FPGA HDL，不使用软核 CPU 或 BL702。

## 3. 例程参考

主要参考 Sipeed `TangPrimer-20K-example` 中的 `PT8211` 例程、`UART` 例程和 Dock 引脚约束；高云官方文档重点参考 SUG100、SUG284、SUG285、SUG935、SUG940、SUG949、UG285、UG286、UG289；音频器件参考 TI PCM5102A、Princeton PT8211、NXP MPR121 和 Microchip MCP3208 数据手册。

## 4. 函数解释

最小设计建议保留以下综合友好函数：`sat16()`/`sat24()` 做有符号饱和；`mix_add()` 做加法树饱和相加；`note_phase_inc()` 用 12 个半音频率字加八度移位；`env_next()` 做 ADSR 饱和步进；`iir_update()` 做压力平滑；`clk_ce()` 产生 48 kHz 采样使能。所有函数必须是纯组合、无浮点、无除法、无大循环。

## 5. 后续优化方向

第一层优化是把 `VOICE_COUNT` 从 4 改到 8，资源变成 8 个波表块和 9 个乘法器；第二层优化是改用 4 个共享 BSRAM bank 的 TDM 波表读取，把 32 声部的波表块压到 4 块；第三层优化是加入共享延迟/合唱、双操作 FM、MIDI 输入和 Lissajous/频谱可视化。逐声部滤波、逐声部插值、逐声部混响和并行 FFT 在 32 声部配置下不进入最低实现，避免超出 BSRAM 和 DSP 预算。

## 6. 硬件与软件/配置关系

| 层面 | 负责内容 | 最低实现中的边界 |
| --- | --- | --- |
| FPGA RTL | I2C、SPI、事件、DDS、ADSR、混音、I2S、UART | 全部实时逻辑；音频路径不使用 CPU |
| PC 脚本 | 生成 `.mi` 波表、频率表、测试向量；解析综合报告 | Python 只在开发阶段运行，不参与演奏 |
| Tcl/Gowin | 建工程、加文件、综合、PnR、码流、IP 生成 | `gw_sh` 可重复构建，Gowin GUI 负责 ROM IP 和 Programmer |
| 外部器件 | MPR121、MCP3208、PCM5102A、PT8211 | 只通过 I2C、SPI、I2S 和 GPIO 与 FPGA 连接 |
| BL702 | JTAG 下载和 UART 串口 | 不参与演奏、音频计算或实时控制 |
| 软核 CPU | 最低实现不使用 | 后续若加入，只能做界面/参数管理，不能进入音频链 |

当前项目的 MCP 配置和 `gw_sh` 构建已经通过最小工程验证，证据在 `evidence/2026/10/gowin-mcp-smoke.json`；受管 Codex 策略暂时禁用自定义 MCP，实际工作流用 VS Code 编辑、`gw_sh.exe` 构建、Gowin GUI 生成 IP 和下载。

## 7. 资源与延迟预算

| 资源 | 最低实现估算 | GW2A-18 上限 | 余量 |
| --- | ---: | ---: | --- |
| LUT4 | 约 3,000～5,000 | 20,736 | 充足 |
| FF | 约 1,500～2,500 | 15,552 | 充足 |
| BSRAM 块 | 4 个波表 + 1 个事件 FIFO + 1 个可选延迟 ≈ 6 | 46 | 充足 |
| 18×18 乘法器 | 4 个声部 + 1 个总增益 = 5 | 48 | 充足 |
| PLL | 0（外部 12.288 MHz 直接使用） | 4 | 充足 |
| 外部 I/O | 约 15～20 根 | Dock PMOD + 固定音频口 | 需确认 PMOD Bank 电压 |

| 延迟环节 | 预算 |
| --- | ---: |
| MPR121 扫描 + 两次去抖 | 2～4 ms |
| I2C 读取 + 事件编码 | ＜0.5 ms |
| 等待下一个 48 kHz 采样 tick | ＜0.021 ms |
| DDS + ADSR + 混音流水线 | ＜0.01 ms |
| PCM5102A 数字滤波 | 低延迟约 0.073 ms；普通约 0.42 ms |
| 合计 | 约 3～5 ms，满足 ≤10 ms |

## 8. 关键函数接口

| 函数 | 输入 | 输出 | 行为 |
| --- | --- | --- | --- |
| `clk_ce(sys_cnt, boundary)` | 8 位计数器和边界值 | 1 位使能 | 在固定计数值产生单周期采样/翻转使能 |
| `note_phase_inc(semitone, octave)` | 0～11 半音、八度偏移 | 32 位频率字 | 查 12 项半音表并按八度移位 |
| `env_next(env, step, up, sustain)` | 16 位包络、步进、方向、保持值 | 16 位包络 | 饱和加减，防止回绕 |
| `sat16(x)` / `sat24(x)` | 32 位有符号数 | 16/24 位有符号数 | 超过上下限时钳位 |
| `mix_add(a, b)` | 两个扩展位宽有符号数 | 扩展位宽和 | 加法树中做不溢出的相加 |
| `iir_update(y, x)` | 16 位历史值、16 位新值 | 16 位平滑值 | `y + ((x-y)>>>K)` 移位平滑 |
| `voice_alloc(active, release_level, age)` | 声部状态 | 声部索引 | 空闲优先、释放中最弱、最老偷取 |
| `i2s_slot(sample24)` | 24 位样本 | 32 位槽数据 | 标准 I2S 左对齐和槽填充 |
