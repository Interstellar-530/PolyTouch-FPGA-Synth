# 7 寸触摸屏快速验证（30 分钟出结论）

目标：在写任何触摸 RTL 之前，用最少的器材把“屏亮不亮、触摸动不动、模块认不认”三件事分开验掉，
每一步都有明确的通过/不通过判据，任何一步不通过都不会污染下一步的判断。

## 0 路线

| 步 | 做什么 | 用时 | 器材 | 验的是什么 |
|---|---|---|---|---|
| 1 | 屏 + 触摸都接电脑 | 10 min | HDMI 线、屏电源、数据线 | 屏本身和触摸硬件是否好的，触摸属于哪类 HID |
| 2 | 屏接 FPGA 看仪表盘 | 5 min | 现成 HDMI 位流 | 视频链路（这一步与触摸无关，先排除它） |
| 3 | 模块 + USB-TTL 抓串口帧 | 10 min | USB-TTL 一个、杜邦线两根 | **模块到底认不认这块屏**（决定后续全部工作） |
| 4 | 板上探针位流 | 1 h | 无（要新构建） | 触摸事件在 FPGA 里能不能变成可见效果 |

第 1、3 步就能定生死。第 4 步在新方案里最容易被跳过、也最不该跳。

## 1 步：屏 + 触摸接电脑（10 分钟）

接法：

| 屏上的口 | 接到 | 注意 |
|---|---|---|
| HDMI | 电脑 HDMI（或 DP 转 HDMI） | 电脑上先选“复制/扩展”到这块屏 |
| POWER | 屏自带的 5 V 电源 | 别用电脑 USB 口供电，背光容易掉电闪 |
| CTOUCH | 电脑 USB-A | **必须是数据线**；随屏附的那根常常只有电源脚 |

判据（三条都要记下来）：

1. **画面**：能显示，且在“显示设置 → 高级显示”里能读到一个推荐分辨率。记下这个数——
   它才是面板原生分辨率，不是 1280×720。顺带记下它接 1280×720 时是否满屏、字是否发虚。
2. **触摸**：手指按上去，光标**跳到指尖**（= 绝对鼠标）或出现触点圆点（= 触摸屏/digitizer）。
   如果光标是“相对漂移”而不是跳到指尖，也记下来——这说明屏内部报的是相对位移。
3. **HID 类别**：设备管理器 → 人体学输入设备，看是 `HID-compliant mouse` 还是
   `HID-compliant touch screen`。这一条直接决定第 3 步能不能成。

不通过时：

| 现象 | 先查 |
|---|---|
| 黑屏 / 无信号 | 屏的输入源选择；换 HDMI 线；确认 POWER 单独供电 |
| 画面有但触摸完全没反应 | 线是充电线；插的是 POWER 口不是 CTOUCH 口；换一根确定能传数据的线 |
| 设备管理器完全不出现新设备 | 同上，加一个 OTG 转接头（若屏是 Type-C 母口） |
| 指纹/触点位置整体偏移 | 正常，记下偏移方向，后面做坐标映射时要 |

## 2 步：屏接 FPGA 看画面（5 分钟）

用现成的 HDMI 位流，不要为这一步重新构建：

- 位流：`output/handoff_milestone2_20261008/source/build/gowin_top_hdmi/runs/<近一次>/instrument/impl/pnr/instrument.fs`
- 烧写：`source/build/program_sram.ps1`（SRAM，掉电丢失）或 `program_hdmi_flash.ps1`（写外部 flash，长期保留）

判据：仪表盘满屏、四边文字不被裁、S1 切曲时画面跟着变。

**这一步先别插触摸**，避免把“画面不对”和“触摸干扰”混在一起。

若第 1 步在电脑上能显示、第 2 步在黑屏：问题在 720p 时序兼容性，不在触摸。此时可以先
把屏当“只显示”，触摸暂缓，别两头一起查。

## 3 步：模块 + USB-TTL 抓帧（10 分钟，最关键）

目的：把“模块认不认这块屏”变成屏幕上一串十六进制字节，不用碰 FPGA。

接线：

| 模块 | 接到 | 说明 |
|---|---|---|
| TXD | USB-TTL 的 RXD | 单向，模块只发不收 |
| GND | USB-TTL 的 GND | 必须共地 |
| RXD | GND | 保持手册 4.x 的单向发送接法，别悬空 |
| 下层 USB-A | 屏的 CTOUCH | 上层留给键盘 |
| 供电 | 按模块丝印 | 不凭排针位置猜正负 |

拨码：先保持现状（`SEL=1`、`BA1=1`、`BA0=1`、`S1=1`、`S0=0` = state 2、115200）。

串口助手：115200 8N1，**HEX 显示**，打开后先看有没有东西。

判据：

| 看到什么 | 结论 | 下一步 |
|---|---|---|
| 上电就周期出现 `57 AB 82 xx` | 模块活着、波特率对 | 继续测触摸 |
| 手指点/拖/抬 → 出现 `57 AB 02 ...`（4 字节载荷） | 模块认了，报的是**相对鼠标** | 可改进 state 3 拿绝对坐标 |
| 手指点/拖/抬 → 出现 `57 AB 04 ...`（7 字节载荷） | 模块认了，报的是**绝对坐标** | 最理想，直接进第 4 步 |
| 有键盘帧（插键盘试）但没有鼠标帧 | 模块认键盘、不认这块屏 | 走 I2C 直取或外挂 MCU |
| 一片安静，连 `82` 心跳都没有 | 接线/波特率错 | 查 TXD 是否接反、GND、模块供电 |

如果拿到的是 `0x02`（相对），把 4 号拨到 0、5 号拨到 1（state 3），**断电重开**，再点一次，
看帧命令字是否变成 `0x04`、坐标是否随手指位置单调变化。

记录表（每行都要有）：

| 动作 | 帧命令字 | 载荷（十六进制） | 备注 |
|---|---|---|---|
| 手指按住不动 | | | |
| 手指从左划到右 | | | |
| 手指抬起 | | | |
| 不碰屏 10 秒 | | | 有没有周期性帧 |

## 4 步：板上探针位流（1 小时，可选）

只有第 3 步拿到 `0x02/0x04` 才值得做。做法：

- 新 top 只实例化 `kbd_uart_rx` + `ch9350_rx`（补 `0x02`/`0x04` 分支）+ 4 个 LED + 串口回显十六进制；
  **不接 HDMI、不接音频、不动 CST**（继续用 `L9`/`N8`）。
- LED 含义建议：`LED0` 收到任意 `57 AB` 帧、`LED1` 键盘帧、`LED2` 坐标帧、`LED3` 按下沿。
- 串口把原始字节按十六进制打印，和 PC 上抓到的帧逐字节对得上。
- 按 `AGENTS.md` 的仿真门禁，必须先过 `tb_ch9350_touch`（喂已知帧，断言坐标与按下沿，
  不满足 `$fatal`）再烧。

判据：手指按在左上角时 LED2/LED3 亮且有稳定坐标；按右下角坐标变大；抬手 `LED3` 灭。

## 5 判据汇总

| 第 1 步 | 第 3 步 | 结论 | 后续 |
|---|---|---|---|
| 触摸正常 | 有 `0x02`/`0x04` | 全通 | 直接做热区 + X/Y 弯音（半天） |
| 触摸正常 | 无鼠标帧 | 模块不认 digitizer | I2C 直取，或 RP2040 当 USB 主机（1–2 天） |
| 触摸正常 | 无任何帧 | 接线/波特率 | 先修第 3 步的接线，别怀疑屏 |
| 触摸无反应 | — | 屏/线问题 | 先解决第 1 步，后面全部暂停 |
| — | — | 屏显示都不行 | 只当显示器用，触摸本阶段放弃 |

## 6 容易白跑一趟的坑

- 用随屏的“充电线”接触摸口，永远没有数据。
- 屏的 POWER 和 CTOUCH 都是 micro-USB，插反了会以为触摸坏了。
- 模块 TXD/RXD 接反：串口一片安静，看起来像模块坏。
- 改完拨码不断电：状态不生效，白测一轮。
- 把 `BA1/BA0`（2、3 位）当状态位改：波特率变成 300000，收到的是乱码。
- 第 2 步带着触摸一起测：出问题分不清是视频还是触摸。
