# 7 寸 HDMI 触摸屏接入当前系统的方式

商品：“树莓派显示屏4b显示器7寸屏幕HDMI 液晶屏 IPS带外壳 创客教育”，带触摸、带边框。
淘宝短链（`https://e.tb.cn/h.j5GsfdJt8FkwnA4`）本次抓取只得到空页面，没有读到参数表；下面的
屏幕侧描述以**用户目视确认的丝印（HDMI / POWER / CTOUCH）**为上限，其余一律标为待实测，
不套用同尺寸其它品牌屏幕的参数。

## 0 结论

| 通道 | 当前系统状态 | 接入方式 | 剩余风险 |
|---|---|---|---|
| 视频 | **已实现**：`dvi_tx` + `hdmi_720p_timing`，1280×720@60，74.25 MHz 像素时钟 | HDMI 线直连 Dock 板载 HDMI 口，不占 PMOD、不用 DSI/RGB 排线 | 面板是否接受 720p 输入、是否下采样导致文字发虚 |
| 供电 | 无 | 屏幕自己的 POWER 口，按标签电压电流给独立电源 | 电压/电流标签未确认；**不许**从 PMOD 3V3 或 GPIO 取电 |
| 触摸 | **未实现**，且系统里没有任何 USB 主机 | 见第 3～6 节：先做 5 分钟判据测试，再在 A/B/C 三条路里选 | 触摸设备枚举成什么 HID 类别，决定只有一条路能走通 |

关键事实：FPGA 板这边**没有 USB 主机**。CH9350L 是“USB HID → UART”的桥，它就是现成的
唯一入口；它能不能转发这块屏的触摸，取决于屏幕触摸口在 PC 上枚举成“鼠标”还是“触摸屏
（HID digitizer）”。这一步不改任何代码，插上电脑看一眼就能判，**必须放在所有设计之前**。

## 1 屏幕侧已知与未知

| 项目 | 结论 | 依据 |
|---|---|---|
| 视频口 | HDMI（标准 A 口，随屏附线） | 用户目视丝印 |
| 供电口 | POWER，独立供电 | 用户目视丝印 |
| 触摸口 | CTOUCH，独立数据口 | 用户目视丝印 |
| 触摸电气形态 | 极可能是 USB HID 设备（这类 HDMI 触摸屏的通用做法） | 待 PC 枚举确认 |
| 原生分辨率 | 未知（同类多为 1024×600） | **不得**按同类推定 |
| EDID / 支持时序 | 未知（同类常接受 640×480～1920×1080 并缩放） | 待 PC 读取 |
| 触摸点数 | 未知（单点或 5 点） | 待 PC 枚举确认 |

## 2 系统侧现状

- 视频链路已完整，见 `source/rtl/video/`：`hdmi_720p_timing.v`（CEA-861 1280×720@60，
  H_TOTAL=1650、V_TOTAL=750）、`dvi_tx.v`、`hdmi_dashboard.v`、`dashboard_renderer.v`。
- 触摸链路为零。`source/rtl/audio/ch9350_rx.v` 只对 `0x01` 键盘帧输出 8 字节报告，
  `0x02`（相对鼠标）和 `0x04`（绝对鼠标）目前在 `SKIP` 状态里被丢弃。
- 时钟域：触摸 UART 与音频同在 27 MHz 域（`clk_27m` = H11），不需要 CDC；
  HDMI 侧另有 74.25 MHz 像素时钟域，触摸状态只做单 bit 同步后读。
- 空闲/可复用引脚：`N9`（J5-7，空闲）、`T6`（J14-11，空闲）、`N8`（J5-6，现为
  `kbd_uart_tx`，固定在空闲高电平）。`T9`（J14-6）与板载 WS2812 数据线并联，不用。
- RTL 里**没有 I2C 主机**（MPR121 方案从未落地），走 I2C 直取要新写一个。

## 3 判据测试（先做，5 分钟，不改任何东西）

把 CTOUCH 用数据线接到 Windows 电脑，看设备管理器：

| PC 上看到什么 | 含义 | 能走的路 |
|---|---|---|
| “HID-compliant mouse” / 人体学输入设备里的鼠标，光标能随手指定位 | 屏内部把触摸转成了**绝对鼠标** | A 有希望；B 可做 |
| “HID-compliant touch screen”，属性里 5 点或 10 点 | 标准 HID digitizer（Usage Page 0x0D） | A 基本不通；走 B 或 C |
| 完全没反应 | 口是假口、线是充电线、或需要 VBUS 反灌 | 先排除线材与供电 |

判据测试同时顺手做两件事：在“显示设置”里读一次该屏的推荐分辨率；用 HDMI 接电脑看
1280×720 能不能满屏显示。

## 4 路径 A：复用现有 CH9350L（先试，零新增器件）

依据：本地 CH9350 手册 V2.3 副本 `archive/FPGA-20261022-v0.3/evidence/wch/CH9350DS.md`
第 3.3～3.5 节、4.3 节。要点：

- 状态是**上电（或复位）时按配置脚采样**决定的，所以改完拨码必须断电重开才生效。
  手工册第 5 节引脚表，配置脚到状态的编码是：

  | 拨码位（正面从左到右） | 引脚 | 编码 | 含义 |
  |---|---|---|---|
  | 1 | SEL（45） | 1 / 0 | 1 = 下位机（默认），0 = 上位机 |
  | 2、3 | BAUD1、BAUD0（37、38） | `11` / `01` / `10` / `00` | 115200（默认）/ 57600 / 38400 / 300000 |
  | 4、5 | S1、S0（5、4） | `11` / `10` / `01` / `00` | state 0·1（默认）/ state 2 / state 3 / state 4 |

  `S1|S0 = 10` 就是现在键盘在用的 state 2；`01` 是 state 3，`00` 是 state 4。
  模块背面那张表只写了"S1/S0 = 工作状态设置"，没写编码，编码来自手册引脚表。
- state 2 鼠标帧：`57 AB 02 | Button | dX | dY | Wheel`（4 字节，**相对**位移）。
- state 3/4 鼠标帧：`57 AB 04 | ID(0x01) | Button | Xlo Xhi | Ylo Yhi | Wheel`
  （7 字节，**10 bit 绝对坐标**，0x0000～0x03FF）。
- 手册明写：下位机 state 2/3/4 **只支持标准键盘和鼠标**，不支持多媒体“和其它 HID 类设备”。
  触摸屏若枚举成 digitizer，大概率被拒（state 0/1 会回 `0x81` 设备属性不匹配帧）。

需要立刻注意的一点：state 3/4 的“绝对坐标”是**模块把相对鼠标累加**出来的（配套命令
`57 AB 12 ... FF FF 01/02/20` 清 X/Y、`0F` 开自动清零，用于多屏切换）。所以：

- 屏幕若报**相对鼠标** → state 3 能把位移累加成 10 bit 绝对坐标，正好是我们想要的。
- 屏幕若报**绝对鼠标** → 模块怎么处理未定义，可能出现坐标飞到边界不动，必须实测。

拨码改法（1 = 拨到 ON 一侧，0 = 拨到数字一侧）：

| 目标 | 1 SEL | 2 BA1 | 3 BA0 | 4 S1 | 5 S0 | 要动的位 |
|---|---|---|---|---|---|---|
| 现状：state 2、115200（键盘在用） | 1 | 1 | 1 | 1 | 0 | 基线 |
| **state 3、115200（推荐先试这个）** | 1 | 1 | 1 | 0 | 1 | 4、5 两个都翻 |
| state 4、115200（备选） | 1 | 1 | 1 | 0 | 0 | 只把 4 翻下来 |

改完必须**断电重开**（状态只在上电/复位时采样）。2、3 两位**不要动**：改成 `00` 会变
300000 波特率，FPGA 的 115200 收不到；`01`/`10` 是 57600/38400，同样对不上。

现在模块 RXD 是接 GND 的（手册 4.x 的单向发送接法），所以**没法用串口命令
`57 AB 40 03` 切状态**——要走命令切换，得先把 RXD 从 GND 挪到 `N8`，而 `N8` 现在是
`kbd_uart_tx` 且固定高。这一轮就用拨码，不动线。

接线（沿用现有键盘那条）：

| 屏幕/模块 | 接 FPGA | 说明 |
|---|---|---|
| CTOUCH（USB） | CH9350L 的**下层** USB-A（HM/HP，第 2 口） | 上层丝印 `上层USB DM DP` 是第 1 口，留给键盘；触摸是鼠标类设备，走第 2 口 |
| CH9350L TXD | `L9`（J5-5，`kbd_uart_rx`） | 115200 8N1，与键盘共用同一条串口 |
| CH9350L RXD | 接 GND（单向模式） | 手册 4.x：RXD 接地即单向发送 |
| GND | 共地 | 必须 |

该模块是**双层 USB-A（上下两个口）**，不是单口：CH9350L 本身在下位机模式就有两组
USB（`DM-DP` = 第 1 口、`HM-HP` = 第 2 口），模块把两组都引了出来。所以键盘和触摸可以
**同时插着**，共用一条 115200 串口，FPGA 侧靠命令字区分（`0x01` 键盘 / `0x02`·`0x04` 坐标），
不需要第二块模块。唯一要注意的是：两个口都只认标准键鼠，触摸能不能被认下来仍是第 3 节的
判据测试要回答的问题。

判据顺序：先确认键盘现在插在哪个口 → 触摸插另一个口（优先下层）→ 没帧就换到上层再试一次。
两个口都没帧，说明是 HID 类别不匹配，不是插错口。

工作量（若判据通过）：`ch9350_rx.v` 增加 `0x04`/`0x02` 分支输出坐标 + 新写
`touch_map.v` 做区域判定，约 1 个晚上（含测试台）。

## 5 路径 B：绕过 USB，直接取触摸控制器的 I2C（最“FPGA”）

这类屏的触摸 FPC 通常接到一小块转接板，板上是 GT911 / FT5x06 / ILI2511 之类的电容触摸
控制器，再加一颗 USB 转 I2C 的桥。若能找到控制器的 SDA/SCL（转接板测试点、上拉电阻旁、
或 FPC 焊盘），就可以完全不要 USB：

| 信号 | 接 FPGA | 说明 |
|---|---|---|
| SCL | `N9` 或 `T6` | 3.3 V，4.7 kΩ 上拉到 3V3 |
| SDA | `T6` 或 `N8` | 同上，双向，需要 IOBUF |
| RST / INT | 另一空闲脚（如 `N8`） | GT911 用复位时 INT 电平选地址 0x5D / 0x14 |

- GT911 读坐标的通用流程：读 `0x814E` 状态（bit7 缓冲就绪、低 4 bit 点数）→ 读
  `0x8150` 起的点表 → 写 `0x814E = 0` 清标志。寄存器 16 位地址、8 位数据。
- FPGA 侧要新写 I2C 主机（约 100～150 行）+ 控制器初始化状态机，比路径 A 多 1～2 天。
- 风险：开壳改线、保修、控制器型号未知、转接板可能由 USB VBUS 给触摸供电（拔掉 USB 后
  触摸部分直接没电，这条路就作废）。**必须在动手前用万用表确认供电来源。**

优点：延迟最低（一次读约 1～2 ms）、不怕 HID 类别、不占 USB、天然单点绝对坐标。

## 6 路径 C：外挂一颗 MCU 当 USB 主机（最稳、可复制）

RP2040（pico-sdk 自带 TinyUSB host HID 例程）、CH32V203、ESP32-S3 任一，做：

```
CTOUCH(USB) → MCU(USB host, 解析 HID 报告) → UART 115200/1 Mbps 自定义帧 → FPGA
```

建议的紧凑帧（FPGA 侧照抄 `ch9350_rx` 的状态机即可，避免再学一套协议）：

| 字节 | 内容 |
|---|---|
| 0 | `0xA5` 帧头 |
| 1 | 事件：`0x01` 按下 / `0x02` 移动 / `0x03` 抬起 |
| 2-3 | X（0～1023，小端） |
| 4-5 | Y（0～599，小端） |
| 6 | 校验：前 6 字节异或 |

成本 30～60 元，固件一个晚上，RTL 半天；延迟比 A/B 多 2～5 ms。**A/B 都不通时的默认选择**，
也是唯一能同时保住键盘和触摸的方案（RP2040 可接 USB Hub，或直接双口）。

## 7 不推荐

- **用板载 USB3317（ULPI PHY）+ RTL 写 USB 主机栈**：USB2 OTG 口确实经过 USB3317，
  但 ULPI 收发器 + 枚举 + HID 解析在 GW2A-18 上是周级工作量，还会抢走时序裕量。
- **电脑转发**：屏幕触摸进 PC、PC 用串口转给 FPGA。能演示，但破坏“独立上电演奏”的
  立项前提，演示现场多一个失败点。
- **动 BL702**：它是 JTAG + 串口桥，刷固件等于自断下载和调试通道。

## 8 接进来之后怎么用（决定值不值得做）

延迟预算（按 CH9350L/USB 全链路估）：

| 环节 | 典型值 |
|---|---|
| 面板扫描 + 控制器 | 10～20 ms |
| USB HID 轮询（全速，1 ms 间隔） | 1～8 ms |
| CH9350L 转发 + 115200 串口（11 字节） | 1～2 ms |
| FPGA 解析 + 区域判定 | < 1 µs |
| **合计** | **约 15～30 ms** |

结论：**只能做界面和连续量，不能做音符触发**。音符仍走 CH9350L 键盘（同样 USB，但按键
事件本身对延迟不敏感）和 GPIO 键。

可做的两件事：

1. **触控热区**：切曲、暂停/继续、音色、音量、测试模式，与现有 S1/S2、键盘 F7/F8 并存；
   按下沿触发一次，抬起再武装，避免长按连发。
2. **X/Y 当 ribbon controller**：Y 轴 → 弯音（±2 半音或大二度），X 轴 → 音色权重/亮度。
   这是这块屏唯一能明显加分的地方，且 15～30 ms 对滑音够用。

硬约束（来自 `AGENTS.md`）：触摸解析必须是独立 always 块，**不许**用阻塞等待把
`sample_tick` 停住；事件通过既有 `event_fifo`/`voice_alloc` 的旁路进入，不改 DDS/ADSR/混音。

## 9 RTL 改动清单（判据通过后再做）

| 文件 | 作用 | 估计资源 |
|---|---|---|
| `rtl/audio/ch9350_rx.v`（改） | 增加 `0x02`/`0x04` 输出，`x[9:0] y[9:0] btn` | +约 60 LUT |
| `rtl/ui/touch_hit_test.v`（新） | 10 bit 坐标 → 热区编号 + 按下/抬起沿 | 约 120 LUT |
| `rtl/ui/touch_glide.v`（新，可选） | Y 轴 → 弯音增量，带一阶平滑 | 约 80 LUT，1 个 18×18 乘法器 |
| `top.v`（改） | 新增 `touch_rx/touch_tx` 端口，接到热区与弯音 | — |

- BSRAM：**0 块**（纯寄存器）；18×18 乘法器：0 个（路径 A/B），路径 C 的平滑若用乘法则 1 个。
- 新增后仍需按 `AGENTS.md` 重新核对 26 块 BSRAM 的余量，并在报告里给实测值。
- 仿真门禁：新增 `tb_ch9350_touch.v`（喂 `0x04` 帧，断言坐标与按下沿，不满足用 `$fatal`）、
  `tb_touch_hit_test.v`（边界坐标、抖动、长按），跑
  `source/sim/run_simulation.ps1` Quick 全过后才允许烧录。

## 10 未确认项（按重要性）

1. CTOUCH 在 PC 上枚举成鼠标还是触摸屏——**决定一切**。
2. 面板原生分辨率、EDID、是否接受 720p。
3. CH9350L 模块的固件版本与它是否真的认这块屏（手册 V2.6 声称“新增对部分触摸屏的支持”，
   本地只有 V2.3 副本，未见具体帧定义）。
4. 触摸转接板供电是否来自 USB VBUS（决定路径 B 是否可行）。
5. 屏幕 POWER 口的电压/电流标签（决定电源选型）。
6. 触摸口是 micro-USB 还是 Type-C，是否需要 OTG 转接。
