# FPGA：S2 GPIO 琴键与手动事件仲裁

2026-10-14 按《缺件期间仿真与算法任务》顺序执行第二项。S0、S1 已完成，本轮做 S2：新增 gpio_keyboard、手动来源 FIFO 与顶层模式仲裁，并补两台自检台。生产代码基线为 `b559237`（v1.01，原生音频验收与 Flash 基线），本轮改动在该提交之上，工作分支 `codex/s2-gpio-keyboard`，尚未合并回 main，也尚未烧录。代码中所有本轮新增段落都带 `[S2-AI]` 标记，便于其他智能体复查、审核和修补。

## 交付内容

新增 `source/rtl/audio/gpio_keyboard.v`：12 路独立输入的同步、消抖与音符事件生成。每路两级同步后独立消抖，默认按下 1 ms、松开 3 ms（27 MHz）；边沿只在消抖后的稳定值真正翻转时产生，因此按住不放不会重复起音。每路带一个 2 深度事件队列，同一个提交轮次内先送 Note Off 再送 Note On；下游未 ready 时事件留在队列里不丢。`flush` 用于 Panic 和模式切换，清空未发送事件并重新武装，已经按住的键必须松开再按才会重新起音。

新增 `source/sim/tb_gpio_keyboard.v` 与 `source/sim/tb_gpio_top.v`，并在 `sim/run_simulation.ps1` 中注册，门禁从十台增至十二台。既有三台顶层台（tb_poly、tb_mode_uart、tb_audio_capture）只补了新增端口 `gpio_key_n` 的连线，断言未改。

顶层把 GPIO 事件接到一个独立的 16 项手动 FIFO（复用既有的 `event_fifo`），再与 UART、演示曲事件汇合到同一仲裁器。仲裁优先级为：清理（Panic / 模式切换）> 首事件暂存 > UART > GPIO 手动 FIFO > 演示 FIFO。弹出条件与优先级一致，清理那一拍不消费事件，所以由 GPIO 触发的那次"退出演示"不会把触发它的事件一起丢掉。

## 接口改动记录

依据：S2 任务要求把 GPIO 琴键接入顶层并做顶层模式测试，硬件接线与引脚表已在 `docs/hardware/FPGA-硬件连接与演奏操作-20261013-v0.1.md` 第 4.1 节和 `docs/hardware/FPGA-pinplan-20261013-v0.1.csv` 中定稿。

影响范围：`top` 增加一个输入端口 `gpio_key_n[11:0]`，三个既有顶层测试台必须同步补连线才能编译；CST 增加 12 条引脚约束。音频数据通路（dds_osc、adsr、poly_voice、mixer、pt8211_tx、uart_ctrl）和曲目播放器没有改动。

设计取舍：顶层原先只有 UART 一个手动来源，靠一拍暂存处理"退出演示的第一个事件"。GPIO 是连续突发来源，直接复用那条单拍通路会撞车，所以改为给手动来源配独立 FIFO 并保留 ready 握手。演示模式下只接收按键（Note On）事件：进入演示时已经清空声部，此时的松键没有可关闭的音符，如果把它排进队列反而会挡住后面真正的按键事件，所以按设计丢弃，并已由顶层回归覆盖。

验证方式：十二台 Icarus Verilog 门禁（`source/sim/run_simulation.ps1`），退出码 0；再加 S1 的离线 PCM/FFT 分析确认音频无回归（见下一节）。

回退方式：本轮改动全部在工作分支上，且没有烧录。`git checkout main` 即可回到 v1.01 基线；CST 中的 12 条约束单独成段，删除该段即可回到不接 GPIO 的引脚状态。

## 未验证事项

仿真通过不等于实物验收。12 路按键的触点上拉、共地、长线串扰和实际去抖时间需要板子到货后按硬件文档实测；CST 新增引脚尚未做 Gowin 综合与布局布线复核，Bank 电压和引脚冲突要等 PnR 报告确认；本轮没有重新统计 BSRAM 与 18×18 乘法器占用，新增的是一个 16×16 事件 FIFO 和 12 路消抖计数器，预计主要落在寄存器和分布式 RAM，具体数字以 PnR 报告为准。弯音、压力、标准 I2S、双音色仍属后续任务，本轮没有触碰。
