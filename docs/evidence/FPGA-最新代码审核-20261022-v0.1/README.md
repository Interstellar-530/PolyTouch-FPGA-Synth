# 最新代码隐患审核与修复记录

日期：2026-10-22。审核对象是 `codex/v2.1.1-integration-20261022` 分支在 12.288 MHz 外部参考时钟、73.728 MHz 计算时钟档下的最新代码。本轮按要求只做能确认效果的定向测试，没有运行耗时较长且与改动无关的全量门禁，也没有烧录板卡。

## 发现与修复

第一处隐患在 32 声部波表引擎。原 16 周期流水线提前一个时钟读取同步 pROM 输出，并把银行混合、正弦幅度和亮音色幅度的乘法结果错位消费。普通“有声音”测试不会发现这种问题，但会改变音色和幅度。修复后明确保留 pROM 的一拍读延迟，补齐最后一次银行读的片选，恢复包络后再乘速度的原始舍入顺序。最终调度为 19 周期/声部。

第二处隐患是 `instrument` 与 `piano_tone` 作为多位控制量直接经过两级同步器，位同时变化时可能被计算域观察为组合撕裂值。现在参考时钟域先锁存三位控制束，计算域两次观察一致后才提交。事件请求、应答和音频帧桥的同步寄存器补充了 `ASYNC_REG` 属性，仿真中增加请求、结果、应答以及帧编号连续性检查。

第三处隐患是音符数组选择和 `note_phase_inc` 串成 21 级组合路径。最终实现曾出现 33 个 setup 违例端点，Fmax 只有 62.473 MHz。现在先寄存一份完整配置快照，再计算相位增量和音色参数；音色切换时将轮询指针复位，避免刷新窗口漏掉低编号声部。构建脚本固定使用 Gowin 的时序优先布局与布线选项。

第四处隐患是 PLL 参数对非法倍频值没有显式阻断。仿真配置现在仅接受 4、6、8 三档，错误配置会直接失败。

## 验证结果

`tb_voice_sched32_review` 的五组调度器用例全部通过，覆盖排队重按、年龄回绕、背压、速度钳位、钢琴/吉他音色映射。`tb_ram32_complete` 通过 32 声部、独立音高、窃取、重按、释放和帧预算检查；实际渲染末周期为 672，含配置的最坏末周期为 702。其 161 个输出样本与流水线改造前参考逐样本相同，最大绝对差为 0，因此本次修复没有降低音色或音质。

`tb_ram32_clocked` 在 MULT=6 下通过，测得计算时钟周期 13.5640 ns，完成 120 帧，帧号连续到 119，32 声部全部激活。测试同时覆盖三位慢控制束、事件握手、音频帧请求/返回平衡、立体声一致性和 I2S 解码。

Gowin V1.9.11.03 对 GW2A-LV18PG256C8/I7 版本 C 完成综合和布局布线。73.728 MHz 约束下 setup/hold 违例端点均为 0，实际 Fmax 为 74.451 MHz。资源占用为 5361/20736 Logic、2627/16173 Register、26/46 BSRAM、2 个 MULT18X18 和 1 个 rPLL。

## 已知限制

本机 Icarus Verilog 编译器在生成可运行的 `.vvp` 后返回 Windows 异常码 `-1073741819`，生成物随后由 `vvp` 正常运行且所有上述自检通过。这是本机编译器进程异常，仍需后续更换或修复 Icarus 环境。当前布局布线工程只用于时序和资源验证，没有完整板级引脚约束，生成文件不得直接用于烧录。外部 12.288 MHz 晶振到位前，硬件频率、抖动和音频实测仍未完成。
