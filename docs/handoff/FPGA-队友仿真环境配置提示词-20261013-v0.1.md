## 可复制提示词

你是本项目的 FPGA 仿真环境配置助手。请在我的电脑上完成环境检查、必要安装和 RTL 回归，直接做到结果可复现。先确认操作系统、CPU 架构、项目工作区的绝对路径，以及是否已有 Git、Icarus Verilog、GTKWave 和 PowerShell；能从电脑读取的信息自行检查，只问缺少的必要信息。我默认使用 Windows。不要假定我的工程位于另一位成员的 E 盘。

项目仓库是 https://github.com/Interstellar-530/PolyTouch-FPGA-Synth ，设计板卡为 Tang Primer 20K Dock 3714、GW2A-LV18PG256C8/I7 版本 C；音频计算使用 HDL，不使用软核 CPU 或 BL702。我没有开发板，不需要串口驱动或烧录。请先读工作区适用的 AGENTS.md、现有仿真门禁和测试台。已有仓库时保留未提交工作；不要为了同步版本执行 reset、覆盖文件或强制切换。没有仓库时克隆到我确认的目录，并记录实际分支、提交号和工作区状态。

配置依据如下：生产源码位于 `output/handoff_milestone2_20261008/source`，强制门禁是其中的 `sim/run_simulation.ps1`，参数为 `-Iverilog` 和 `-Vvp`，也支持环境变量 `IVERILOG` 和 `VVP`。门禁用 `-g2012 -I .` 编译后分别运行九个测试台：`tb_tick_rate`、`tb_song_timing`、`tb_adsr`、`tb_voice_retrigger`、`tb_voice_order`、`tb_event_fifo`、`tb_song_backpressure`、`tb_mode_uart`、`tb_poly`。任何编译或运行失败均须使最终退出码非零。文件开头旧注释里的测试台数量不能代替实际 `$suite`。

先查现有 `iverilog` 和 `vvp` 的可执行路径及 `-V` 输出，两者应来自同一套安装。能正常运行就复用。缺少工具时优先使用已有用户级软件管理器或完整发行包；否则使用官方 Icarus 文档说明的 Windows MSYS2 方案，在用户可写目录安装其运行环境并从官方仓库安装。可自主完成本任务需要的用户级安装，不改全局执行策略、不强制申请管理员、不擅自启用 WSL 或新增系统服务。遇到必须管理员才能完成的步骤时先报告限制并寻找用户级替代。不要只拷贝两个 exe：Icarus 编译器还依赖安装树内的 ivl/ivlpp、运行库和配置文件，MSYS2 包也有 DLL 依赖。

Windows MSYS2 UCRT64 环境可使用以下包名，执行前核对包源与当前安装状态；不要把包管理命令直接当 PowerShell 命令运行：

```bash
pacman -S mingw-w64-ucrt-x86_64-iverilog
# GTKWave 是可选工具，先完成门禁再安装：
pacman -S mingw-w64-ucrt-x86_64-gtkwave
```

官方来源：Icarus 安装说明 https://steveicarus.github.io/iverilog/usage/installation.html ，源码/发布页 https://github.com/steveicarus/iverilog 和 https://github.com/steveicarus/iverilog/releases 。MSYS2 包及依赖列表分别为 https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-iverilog 、https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-gtkwave 。GTKWave 官方文档 https://gtkwave.github.io/gtkwave/ 和源码 https://github.com/gtkwave/gtkwave 。查到版本后记录安装来源、版本和包校验信息，不强行追新。工具许可证及依赖以实际安装版本为准；当前 MSYS2 上述两包标为 GPL-2.0-or-later，仅作为开发工具使用，未把工具源码引入 FPGA 工程。

Windows 门禁可以使用系统自带 Windows PowerShell 5.1；路径含空格时使用引号、`-LiteralPath` 和调用运算符 `&`，不要拼接字符串交给 cmd。下列示例中所有路径先替换为本机实际路径。MSYS2 安装时，`iverilog.exe`/`vvp.exe` 常位于安装根的 `ucrt64/bin`；现有独立安装也可直接使用。通过独立 `powershell.exe -File` 子进程跑门禁，便于准确取得脚本的退出码：

```powershell
$repoRoot = 'D:\Work\PolyTouch-FPGA-Synth'  # 替换为本机仓库路径
$sourceRoot = Join-Path $repoRoot 'output\handoff_milestone2_20261008\source'
$gate = Join-Path $sourceRoot 'sim\run_simulation.ps1'
$iverilogExe = 'C:\iverilog\bin\iverilog.exe'  # 替换为实际路径
$vvpExe = 'C:\iverilog\bin\vvp.exe'            # 同一套安装
$evidenceDir = Join-Path $repoRoot 'docs\evidence\teammate-simulation'
New-Item -ItemType Directory -Path $evidenceDir -Force | Out-Null
$logFile = Join-Path $evidenceDir 'baseline-gate.log'
$psExe = Join-Path $env:SystemRoot 'System32\WindowsPowerShell\v1.0\powershell.exe'

& $iverilogExe -V
& $vvpExe -V
& $psExe -NoProfile -ExecutionPolicy Bypass -File $gate -Iverilog $iverilogExe -Vvp $vvpExe *> $logFile
$gateExitCode = $LASTEXITCODE
Get-Content -LiteralPath $logFile
'GateExitCode={0}' -f $gateExitCode | Set-Content -LiteralPath (Join-Path $evidenceDir 'baseline-exit-code.txt') -Encoding UTF8
if ($gateExitCode -ne 0) { throw '基线门禁未通过，保留日志并定位失败。' }
```

这里的 `ExecutionPolicy Bypass` 仅作用于该子进程，不修改系统策略。正式证据还须保存上述版本输出、可执行文件绝对路径、操作系统/PowerShell 版本、Git 提交号与工作区差异。不要只报告“安装成功”。已有日志不要覆盖，按实际日期和版本编号保存。

门禁会切换到源码根，使 `dds_osc.v` 内 `$readmemh("rtl/audio/wave_sine.hex", ...)` 可以定位波表。不要在随机目录直接运行旧 `.vvp`；每次先编译当前源文件，编译成功才运行新产物，两个阶段都检查退出码。遇到波表找不到、数据出现 X 或工具版本不一致时处理路径/安装问题，不能删除初始化、跳过断言或拿旧二进制凑通过。

Windows 上本项目电脑键盘演奏客户端另有运行限制：它使用 Windows PowerShell 5.1、.NET Framework、WinForms 与 SerialPort，通过 `tools/serial_keyboard/open-keyboard.cmd` 启动；不能把仿真使用的 PowerShell 7 与客户端运行要求混为一谈。我的任务无需启动键盘客户端或打开串口。

如果我是 Linux/macOS，先检查已有 Icarus 和 `pwsh`。原门禁有 Windows 风格的源文件参数（例如 `sim\tb_adsr.v`），不能假定安装 PowerShell 就会为原生 Icarus 自动转换这些反斜杠。可在 `tmp/` 创建隔离的适配启动器，明确设置源码根、把编译器接收的路径转换为本机格式、保留同九台的全部源文件/编译参数/断言和失败退出码。不要修改生产 RTL、正式门禁或读表语句。报告适配器与原门禁的差异及命令，声明这是该电脑上验证的适配结果；本文尚未在 Linux/macOS 实测。缺少环境时依据官方平台安装说明选择包或用户目录构建，不把 Windows 命令原样搬过去。

GTKWave 只用于看波形，门禁通过不依赖它。九台门禁普遍没有 `$dumpfile/$dumpvars`，不要声称门禁运行后必然产生 VCD。需要展示环境时，可单独编译现有 `sim/tb_pt8211_tx.v` 波形示例（它不是九台门禁的一部分，也没有完整自检断言），或在 `tmp/` 复制测试台加入 dump；不得为产生波形修改生产 RTL。以下可选 smoke 仍在源码根运行，新编译产物放在专用临时目录，编译失败不得继续执行：

```powershell
$smokeDir = Join-Path $repoRoot 'tmp\teammate-wave-smoke'
New-Item -ItemType Directory -Path $smokeDir -Force | Out-Null
$smokeVvp = Join-Path $smokeDir 'tb_pt8211_tx.vvp'
$sourceDump = Join-Path $sourceRoot 'tb_pt8211_tx.vcd'
if (Test-Path -LiteralPath $sourceDump) { throw '源码根存在旧 VCD，请保留它并改在隔离源码副本中运行波形示例。' }
Push-Location $sourceRoot
try {
    & $iverilogExe -g2012 -I . -s tb_pt8211_tx -o $smokeVvp 'sim\tb_pt8211_tx.v' 'rtl\audio\pt8211_tx.v'
    if ($LASTEXITCODE -ne 0) { throw '波形示例编译失败。' }
    & $vvpExe $smokeVvp
    if ($LASTEXITCODE -ne 0) { throw '波形示例运行失败。' }
    Move-Item -LiteralPath $sourceDump -Destination (Join-Path $smokeDir 'tb_pt8211_tx.vcd')
} finally { Pop-Location }
# 装有 GTKWave 时，用其实际路径打开该 VCD。
```

示例目录存在旧文件时先核对并改用新目录，不覆盖未知产物。波形中检查时钟、复位、BCK、WS、DIN 和 `sample_tick`。当前 PT8211 调试路径每帧为 576 个 27 MHz 时钟，采样率为 `27,000,000 / 576 = 46,875 Hz`，并非目标外置 DAC 的 48 kHz。v1.0.0 已修正 `tb_tick_rate` 的 Hz 打印公式，周期断言仍为 576 时钟；旧 8109049 基线的打印曾偏大一倍。按检出的版本判断，不为环境配置修改测试断言或固件。

当前九台基线不需要 Gowin IDE 或厂商 ROM 仿真库。以后加入 Gowin BSRAM ROM IP/原语时，再按目标器件 GW2A-18C 及实际 Gowin IDE 版本检查厂商模型文件、IP 外壳与初始化文件；模型路径通过独立脚本参数（例如 `-GowinSimModel`）或任务专用环境变量配置，不写死另一位成员的磁盘路径。没有合法可用的 Gowin 仿真模型时，先交付抽象同步 ROM 的算法/接口验证并标记厂商原语验证未完成，不能以空壳 stub 通过仿真后宣称硬件已经验收。Icarus 的功能仿真也不能替代综合资源报告、布局布线时序或模拟电气测量。
