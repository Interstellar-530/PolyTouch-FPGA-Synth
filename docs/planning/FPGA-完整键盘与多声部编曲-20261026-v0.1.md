# 完整键盘与演示曲目扩展

本轮实现键盘映射扩展，保留当前 8 声部引擎；下面的编曲及 32 声部内容是后续方案，没有修改播放器接口、替换音频架构或烧录。已有曲目工作区修改完整保留。

## 当前听感及本轮键位

板上上次烧录版本只有 24 个演奏键，忽略 Boot 报告的 modifier 字节，普通键报告最多提供 6 个键码。声部数是音源可同时发声的数量，映射数是可选音高的数量，两者分别计算。实体键盘自身可能在某些组合下发生冲突，6 个槽也不能保证任意六键无冲。耳机直插 PCM5102A 的驱动能力及单声道混音，也会影响听感，增加键位不会改善模拟输出驱动。

本轮把标准完整键盘的 88 个物理键映射为默认 MIDI 21..108，即 A0..C8，全部唯一；左右 Ctrl、Shift、Alt、Win 使用报告中的 8 个独立位，不占用六个普通键槽。报告最多表达 6+8=14 个音符来源，当前音源同时保持 8 个不同音高，第九个按现有最老声部规则窃取。真实键盘若没有右 Win、锁住 Win、把右 Alt 合成为 Ctrl+Alt，或不能上报相应组合，实际能力会下降。不能将这些数字宣传为 CH9350L 支持普通键 NKRO 或 88 声部。

| 键位组（从左到右逐半音） | 默认 MIDI | 用途 |
|---|---|---|
| Z S X D C V G B H N J M | 48..59 | 保留原下排 |
| Q 2 W 3 E R 5 T 6 Y 7 U | 60..71 | 保留原上排 |
| I 9 O 0 P [ = ] \ | 72..80 | 延伸上排 |
| 左Ctrl、左Shift、左Alt、左Win、右Ctrl、右Shift、右Alt、右Win | 40..47 | 独立低音键 |
| 小键盘 0..9、点、加、减、乘、除、Enter | 24..39 | 低音组，需键盘上报 KP 键码 |
| A F K L ; ' , . / ` 1 4 8 - | 81..94 | 补充高音 |
| Insert Home Delete End Left Right | 95..100 | 辅助高音 |
| Tab CapsLock Backspace Enter | 101..104 | 极高音 |
| F9 F10 F11 F12 | 105..108 | 极高音 |
| PrintScreen ScrollLock Pause | 21..23 | 极低音，特殊键是否上报由键盘决定 |

全部 104 键中的其余键用于控制：F1..F5 音色、F6 钢琴/吉他、F7 手动/自动、F8 暂停/继续、Up/Down 音量、PageUp/PageDown 八度，Esc 和 Space 紧急清音，NumLock 及 Menu 不发音。修饰键在本硬件中用来发音，不再视为电脑快捷键；电脑端串口演奏工具仍保持原布局。

PageUp/PageDown 继续整体移调，范围 base 36..84；按下时保存实际音高，松开沿用保存的音高。移调后超出 MIDI 1..127 的新按键不发音，不会发生有符号回绕。88 是默认移调位置下的映射覆盖，不是新增 88 套采样；极端音区的音色自然度未做听音验收。

先切到手动并松键，再试 Q、E、T、I、P、] 加左 Ctrl、右 Shift，这八个音在默认音区互不重复。若某个组合少音，可先逐个确认键位，再替换普通键组合，以区别实体键盘冲突和 FPGA 分配问题。仿真使用六个普通键加左 Ctrl、右 Win，验证 8 路非零音频贡献及 I2S；尚未更新实物位流。

## 演示曲目先用好八声部

当前 song_player 仅有旋律流及三音和弦流，持续 gate 通常最多 4 个，转场时旧音 Release 才占用其余声部。统一音色、左右相同的输出也会减少声部层次感。只把和弦叠得更厚，容易掩盖旋律。

八声部下先安排 1 路主旋律、1 路低音、最多 3 路分解和弦、1 路句尾应答，留 2 路给释放尾音。这是同时在用的上限安排，分解和弦通常只需 1..2 个 gate，应答仅在主旋律留白时进入。主旋律力度建议 85..110，低音 65..85，分解和弦 45..70；它们是试听起点，需按当前音色响度调整。和弦选择转位，避免低音区密集三度；低音与主旋律错开八度。和弦音起点可错开 5..15 ms，长句设置轻重拍及留白，避免每个声部完全同起同落。

这些可先在生成器中安排独立时值、力度和休止；现有两条流不能完整表达六个独立声部的节奏，需要增加轨道或合并为按时间排序的事件流。此处只给方案，不覆盖正在修改的曲目数据。当前音色选择是全局状态，不能直接宣称主旋律钢琴、低音贝斯、伴奏吉他已能同时发声。

## 三十二声部集成方案与预算

复用已验证的 voice_sched32、instrument_ram_audio_compute 和共享 ROM，不为每个声部复制波表。既有 32 声部原型在 73.728 MHz 下使用 26/46 块 BSRAM、3 个 MULT18X18 及 1 个 MULTALU36X18，Fmax 75.564 MHz，setup/hold 违例为零。它的输入参考是 12.288 MHz，尚不能当作当前 27 MHz 板级工程的结果。

建议板级方案先研究板载 27 MHz 经 PLL 倍频至 54 MHz，保留 46.875 kHz 采样率，每帧 1152 个计算周期，不增加外部晶振。既有测试最大帧尾是 617/1536 拍，说明该方向值得实现；617 不是所有编曲、所有新效果器的最坏上界，54 MHz 新配置仍须通过完整 32 音更新、事件突发及布局布线检查。复用已有锁相、复位等待及配置背压机制，尽量让键盘、曲目、调度和音频运行在同一计算域；若保留 27 MHz 控制域，必须增加明确的事件及参数 CDC 握手。

建议按 1 路主旋律、1 路副旋律、1 路低音、最多 4 路分解和弦、最多 4 路铺底分配共 11 个持续发声位置，剩余 21 个为释放尾音、踏板和装饰音的共享余量。声部槽动态分配，不让铺底或尾音先于主旋律窃取资源；32 是允许的峰值，不要求每拍都填满。初版先保持全局音色，将编曲听感做稳定，再实现每声部音色和声像。

多音色版需要在按下时锁存每声部音色、声像、轨道身份，不能继续只按 MIDI 音高归属 Note Off。否则不同轨道的同音会被一起释放。主旋律优先级、尾音释放、暂停、F7/F8、压力和弯音都要通过统一事件仲裁保留。拟议曲目事件可采用 32 位：delta_tick[11:0]、part[2:0]、on、note[6:0]、velocity[6:0]、flags[1:0]；这是后续接口设计提案，没有修改当前 16 位事件格式。

| 项目 | BSRAM 预算 | 18×18 乘法资源 |
|---|---:|---|
| 现有 32 声部核心及共享波表 | 26 | 已实现：3 个 MULT18X18 + 1 个 MULTALU36X18 |
| 最多 2048 条、每条 32 位的事件 ROM | 4 | 0；按 512×36 配置计算 |
| 双声道各 2048 样本、16 位的短延迟缓冲 | 4 | 目标复用共享乘法，新增 0，须重新核对调度 |
| 键盘、板级控制及对齐预留 | 4 | 暂预留 1 个 MULT18X18，不作为已实现占用 |
| 规划合计 | 38/46 | 目标 4 个 MULT18X18 + 1 个 MULTALU36X18，待实际报告 |

2048 样本在 46.875 kHz 下约 43.69 ms，适合轻微延迟/合唱的存储范围，不能当作长混响。双声道声像先做静态分配，再添加低电平短延迟；当前工程两声道相同，不能只改两个 I2S 接口名字便称为立体声。短延迟、反馈和声像的额外乘法次数必须纳入每帧调度；若放不下，先关闭效果，保留干声 32 声部。BSRAM 38 是按明确容量和额外预留估算，整机实现后仍可能调整。

不建议此时直接承诺 64 声部：新板级时钟、调度器位宽、帧期限和效果预算都没有对应验收。当前最有依据的推进目标是“完整键盘输入、8 声部全部可触发”与“正式集成已有 32 声部核心”，听感收益优先来自编曲、独立音色和合理混音。
