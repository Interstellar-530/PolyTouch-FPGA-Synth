## 1. 本周的交付目标

周五交付能直接用于周末组装的演示固件：USB 键盘经 CH9350L 直接演奏，FSR 控制持续表情，旋钮独立弯音，电钢琴/吉他可在键盘上切换，PCM5102A 正式输出，RGB 灯跟随演奏，彩屏显示实际状态。你负责音频核心、合并与板卡；队友负责输入控制、可视化和演示操作。AI 用于有边界的实现、检查和参数搜索，机器用于并行仿真、音频渲染和综合。

评分冲刺目标为完整 32 声部，但不让它阻塞 8 声部整机展示。周四晚决定 32 声部是否进入周末固件；周五做集成与演示准备，不继续换音源、换接口或重构整个工程。64 声部、长混响、HDMI、大型 FFT、无线联动留到周末后。

本轮按用户最新要求压缩门禁和稳定性测试。旧 AGENTS 的全量门禁政策保留为历史默认，本周以本轮明确要求为准：不要求先修完所有旧测试才推进展示，保留改动相关短仿真、实际顶层 PnR 和一次上板展示检查。本文件只制定方案，没有修改门禁脚本、RTL、公共接口或板卡内容。

## 2. 当前可复用基础与需要纠正的判断

最新使用的是 8 声部调试版，已有双音色切换、键控高音衰减、公共 24 位低通、音量控制及软限幅。10 月 20 日最新归档报告为 10778 Logic、3398 寄存器、40/46 BSRAM、1×MULT18X18＋1×MULT9X9，27MHz 约束下 Fmax 31.386MHz、setup/hold 违规为零。它是 `debug8` 的结果，不能直接写成加入键盘、压力、显示后的 `standard27` 资源报告。

`standard27` 现有封装已设 8 声部、CH9350L 输入、标准 I2S 和压力通路。`hid_keymap` 只提供音符、F1—F5、移调与清音等控制；F6 切钢琴/吉他和音量调节目前在电脑端实现，尚未完整贯通 Host 键盘。顶层上电仍默认演示模式；已知 `tb_gpio_top` 模式切换失败虽然不要求修复所有旧 GPIO 行为，但“第一次 HID 按键不能被吞、脱机能进入手动演奏”必须定向解决。

10 月 17 日的 32/64 路 RAM 引擎、宽乘法器、状态 RAM、I2S 和跨时钟桥可以复用。原型缺少完整事件分配/ADSR/重按控制，且当时使用 12.288MHz 外部参考产生 49.152MHz，不能直接套到现在的 27MHz 板载时钟。当前共享引擎内部仍固定为 4/8 路，单把 `VOICES` 改成 32 不会得到 32 声部乐器。

历史 SNR 和带限频谱来自当时指定算法与测试配置，新波表、新滤波后的数字指标需要重新测需要引用的那一项，不要求重新做全部研究。未经本次测量，不在答辩中套用历史数字。

## 3. 哪些工作最值得投入

| 顺序 | 工作 | 评分/展示收益 | 本周处理 |
|---|---|---|---|
| 1 | CH9350L 独立演奏＋FSR＋旋钮 | 形成可演奏作品与三个独立输入维度 | 必须交付 |
| 2 | 32 个完整独立声部 | 直接提高核心吞吐量指标 | 独立分支冲刺，周四定去留 |
| 3 | 两种可辨识预设＋短合唱 | 两种乐器表现与 FPGA 硬件效果 | 双音色必须，合唱优先于继续增加波表 |
| 4 | RGB 灯＋小彩屏 | 观众能看到输入、包络和状态变化 | 灯必须，屏可降级 |
| 5 | 多音测试与端到端延迟证据 | 让已完成能力可被评委核验 | 周五备工具，周末采实物数据 |
| 6 | 继续堆波表、64 路、长混响、大屏 | 潜力存在，短期集成成本高 | 本周不占主线时间 |

官方以“同时活跃可闻独立振荡器数×实际采样率”为核心依据；波表中多个谐波不能算多个振荡器。8×46875=375000，32×46875=1500000；32 声部是 8 声部的四倍，升到 48kHz 仅增约 2.4%。这些是按规则计算的设计值，不是得分预测，也不是实测成绩。[官方规则](https://www.gowinsemi.com.cn/university/match2026)

FSR 同时控制音量和亮度只算一个物理表情输入。增加独立弯音旋钮后，选音、压力和弯音构成三个可独立操作的维度。电脑键盘固定力度不能包装成每键真实测速力度。保留自己设计的压力垫结构、映射、滤波与演奏操作，说明自研交互贡献。

## 5. 输入与控制：优先补齐脱机操作

建议把 HID 与电脑串口最终都转换为同一组内部控制事件，再修改乐器状态。不要为 HID 另写一套增益、音色和效果状态寄存器。对原 UART `I0/I1`、`V0..V100`、`D0/D1` 等保持兼容；新增内部控制端口按下表一次确定，具体位宽在实现时统一。

| 操作 | 周末目标行为 | 当前情况 |
|---|---|---|
| 两排琴键 | Z S X D C V G B H N J M；Q 2 W 3 E R 5 T 6 Y 7 U | 已有；检查首键与松键 |
| PageUp/PageDown | 八度变化，已按住的旧音仍能正确释放 | 已有 |
| F1—F5 | 当前乐器的音色/亮度预设 | 已有入口；需核对两个乐器的实际效果 |
| F6 | 电钢琴/吉他切换，并正确清理旧声部 | **Host 路径待补** |
| ↑ / ↓ | 主音量每次 ±5%，边界 0—100 | **Host 路径待补** |
| F7 | 硬件合唱开关，界面同步显示 | **待实现** |
| F8 | 现场多音验证模式开/关，退出清声部 | **待实现**；测试音先降音量 |
| F9 | 演示序列开/关，首轮用无预录 PCM 的音符事件序列 | **待实现** |
| Esc | 全部松键、清事件；不依赖电脑窗口焦点 | 已有，做一次集成检查 |
| 上电 | 正式演奏档默认手动待机；演示由 F9 主动启动 | **待改**；旧调试档可保留旧默认 |

控制事件只在按下边沿生效，不能因 CH9350L 重发或键盘重复而连续切音色。切换音色、测试模式、演示模式时采用统一清理路径；注意不能让首个音符随清队列丢失。硬件键盘同音、UART 调试输入和测试音源需要确定优先级，正式演示时关闭不必要的第二输入来源。

CH9350L 按安装文档改为单向 state 2 接法：RXD 接地、N8 留空。原厂手册仅对部分模式描述状态通信，不保证 state 2 的固定周期心跳。把现有 2 秒静默超时拆成可配置策略，首版不使用无依据的静默清音；周末抓取真实长按/空闲/拔线报告后再启用可靠断线判断。保留 Esc 和 S3 作为手动清音方式，公开记录未实现自动拔线清音的情况。不能一边缺心跳，一边用 2 秒超时截断长音。

“不再跑旧 GPIO 全量回归”不等于忽略其暴露的共用模式问题。只保留一项新的真实 Host 顶层测试：上电→首键→和弦→松键→切音色→清音，确保周末操作路径正确。

## 6. 压力、预设和效果：让差异听得出来

FSR 首轮使用一个归一化值 `pressure_q`，在无压/舒适重压两点标定后，保留现有去毛刺与平滑。声部音高不受压力干扰；旋钮弯音围绕中点 ±2 半音。量化结果在采样边界统一提交，视觉只读快照。压力的功能要能用“按住和弦，再逐渐加压”一次演示清楚。

本周固定两套正式预设，不再增加音色库：电钢琴突出起音、自然尾音和温和合唱；吉他突出拨弦起音与较短衰减。为避免大声掩盖音色区别，用同一段事件序列、相同控制值分别渲染，先比电平再试听。波表已接近存储上限，优先调包络、现有频谱阶段和小范围增益。

短合唱作为新增硬件效果首选：一个单声道 2048×16 环形缓冲，容量约 43.69ms，计划使用 2 块 BSRAM；首版延迟在约 12—24ms 缓慢调制，深度约 ±2—3ms，湿声比例从 1/8 或 1/4 起步，干声直通。无反馈，旁路时仍维持缓冲读写，开关时渐变湿声，避免切换爆音。缓冲可用 16 位，主音频保留 24 位；读取位置用小数插值，候选代价 1—2 个额外 18×18 乘法器，需实际综合。

首版只实现这个效果，不同时做前瞻压缩、长混响和多个箱体模型。两种音色可以共享效果硬件但使用不同深度。湿声延迟不是干声演奏延迟；测低延迟时明确测量干声起点，不能只报计算核心耗时。

## 7. FPGA 资源安排与 32 声部冲刺

资源利用率的目标是获得可听、可见、可测的功能，不是把每一块 RAM 占满。现有瓶颈是 40/46 BSRAM 和完整顶层时序，乘法器资源尚未充分使用。增加少量独立效果运算和寄存器流水，可能比继续挤压一个共享乘法器更容易按时完成。

| 功能 | BSRAM 计划 | 额外 18×18 乘法器计划 | 说明 |
|---|---:|---:|---|
| 当前 8 声部双音色调试基线 | 40 | 基线 1 个，另有 1 个 9×9 | 实测历史值；正式档仍需重新综合 |
| 16 灯及状态快照 | 0 | 0 | 16×24=384bit 颜色寄存器，50Hz 更新 |
| 彩屏字体/波形 | 最多 1 | 0 | 小字体用逻辑 ROM，波形历史用一块 RAM；不存整屏 RGB 图 |
| 短合唱 | 2 | 1—2 | 2048×16，实际原语布局和插值资源待综合 |
| 8 声部展示目标合计 | 43 | 总计候选 2—3，另保留 9×9 路径 | 余 3 块 BSRAM，不视为保证值 |
| 32 路状态与双银行增量缓存 | 候选再加 2 | 依选定宽乘法通路，整体预算先控制在 4—6 | 单通路方案，必须避免复制整套 40 块 ROM |
| 32 声部＋灯屏＋合唱候选 | 45 | 目标≤6 | 剩 1 块，仅是规划；超出先去合唱/波形缓存 |

32 路候选的一块状态 RAM 可按 512×32 组织，32 路各 8—16 字，最多正好 512 字；事件分配元数据先用小寄存器表，避免争抢同一端口。另一块缓存放双银行 128 音高增量，帧边界换银行。最终状态布局、读写端口、ROM 访问次数和包络更新尚未落实，因此不能仅凭比特数就宣称资源一定够。

当前每声部约 30 拍的估计下，8 路为 240 拍，27MHz 每帧有 576 拍；32 路约 960 拍，不能直接运行在原时钟。候选是保留 27MHz I2S/控制域，内部 PLL 产生 54MHz 计算域，每帧 1152 拍；960 拍仅为声部处理估算，尚需加 RAM 访问、事件/包络、主混合和跨域开销。把完整计算目标设为不超过约 1050 拍，给交付留时间；超出必须改变调度，不能只修改断言阈值。

按这个顺序做，避免同时重写所有部分：

1. 从现有 RAM 原型抽出可复用通路，先用 8 路接入真实 Note On/Off、ADSR 和清音，保持输出正确。
2. 将新双音色 ROM、阶段和键控增益接入；不复制每声部波表，不复制两套 40 块银行。
3. 扩到 32 路，保留独立相位、频率、包络、松键和窃声行为；检查音高和满负载帧周期。
4. 用 Gowin 工具生成合法 27→54MHz PLL 配置，新增实际时钟约束；用现有 frame bridge 思路做保持总线与握手，I2S 继续留在 27MHz 域。
5. 对真实集成顶层做一次布局布线。历史 31.386MHz 调试顶层不能直接超频到 54MHz，历史 69.611MHz 原型也不能作为新顶层证明。

周四 20:00 的去留条件只看三个结果：能由事件控制的 32 路样本、完整帧按时提交、实际集成顶层资源和时序通过。满足再合入；不满足保留成果，周末使用 8 路。只有 16 路也已实际完成时才作为中间档，不临时增加第三个未验证版本。若 32 路需要额外表复制，应先回到单通路复用或缩减经试听证明冗余的表，不能把 72 块 ROM 硬塞进 46 块器件。

本周不使用 DDR3 做逐样本查表，也不为显示引入 DDR3 控制器。已购外部晶振暂不成为 32 路任务依赖，49.152MHz 旧原型只作为参考。

## 8. 视觉模块：直接服务演奏

RGB 灯用 12 个位置显示音级、4 个位置显示压力。灯的颜色区分乐器，亮度来自实际包络或按键状态；削波短闪红。按固定 50Hz 快照发送，16×24bit/800kHz≈0.48ms，加复位低电平后仍很短，不阻塞音频。复位低电平先按较保守的 ≥300µs 设计，并以所购灯型号的时序范围为准；颜色顺序现场确认。

彩屏以 6.75MHz SPI 为起点，128×160×16bit 的整屏像素约 48.55ms，不含命令开销；实际 10—15Hz 加局部更新足够。整屏 RGB565 缓存为 327680bit，按 18Kbit 块约需 18 块 BSRAM，当前不能采用。使用屏幕自带显存，只画文字、小条形图和波形窗口；小字体与彩色区域按坐标实时生成。

显示快照建议包含：乐器、八度、主音量、归一化压力、带符号弯音、实际活动声部数、声部上限、效果状态、削波事件、128 点波形。常规 8 路版与控制同在 27MHz，可在刷新开始锁存；32 路版的活动数和音频样本跨域时使用握手快照或已有桥，不逐位双触发器同步多位总线。

暂不显示 FFT；屏幕明确标“波形”。FFT 放电脑离线分析用于评分证据更划算，避免与音频争资源。灯屏驱动各自使用时钟使能，不能通过阻塞等待把音频 sample_tick 停住。

## 10. 精简后的验证与烧录流程

本周取消：每个小改动重跑全部历史套件、所有旧波表黄金向量重建、长时间老化、多轮重复频谱/时序测量、只为记录而记录的资源扫描。保留下面几类短检查，具体运行哪些由修改范围决定，同一源码和参数已通过就不重复。

| 改动范围 | 最小检查 | 为什么保留 |
|---|---|---|
| Host 控制 | 首键、按松、F6/F7、移调持音、5 秒无心跳输入、Esc | 直接防止周末不能演奏或长音被截断 |
| 音量/滤波/混音 | 单位增益、正负峰值、静音、8 音和弦、I0/I1 | 最近发生过 −12dB 定标错误，短数值检查即可捕获 |
| 32 路/时钟 | 独立频率和包络、最坏帧、PLL锁定/复位/跨域、真实顶层 PnR | 保证扩展出来的声部真的能同时工作 |
| 合唱 | 旁路一致、缓冲回绕、输出不溢出、开关短音频 | 避免效果模块破坏干声 |
| RGB/LCD | 发一次完整灯帧/像素窗口，核对时序和边界 | 不做几小时显示老化 |
| 周五候选 | 一次实际操作路径短回归、一次正式顶层 PnR | 避免模块各自通过但接在一起失败 |
| 周末上板 | 一遍约 10 分钟演示、一次冷启动 | 确认能脱机重复展示 |

短测试须自检，失败返回非零；不要只打印 PASS。旧 GPIO 路径失败只在影响正式演示时处理，旧测试的失败状态如实保留，不修改日志冒充全量通过。正式输出、时钟和引脚更改后仍需相应仿真和时序检查，这些比现场盲调省时。

当前 `program_sram.ps1` 默认仍调用全量门禁。周五交付一份精简测试入口是待办，不在本文中假装已有脚本。后续执行可在定向检查通过并保存同一构建输入/位流哈希后，使用现有 `-SkipSimulation` 避免脚本再次跑全量套件；日志写明“依据 2026-10-20 用户要求，已跑哪些定向测试、跳过哪些旧套件”。这不等于允许未经任何检查的候选直接烧录。


## 11. 评分证据与 90 秒演示

多音验证模式使用实际事件分配器逐路起音，先用正弦预设避免谐波造成误计数。8 路与 32 路都从同一程序化规则产生频率；例如 NFFT=16384、Fs=46875Hz 时，选 `k_i=101+37i`、`f_i=k_i×Fs/NFFT`，32 路约覆盖 289—3571Hz，间隔可分辨。给每路独立包络并留足混音余量，频谱数峰同时检查逐路开关；屏幕上的数字不是声部证据。外部声卡有时钟误差，实测分析允许峰在邻近频点偏移，不能强求理想 bin 完全一致。

当前 MIDI 音高查表不能直接得到这些任意频率。实现时可仅在 F8 测试模式下，把测试音符编号映射到 `phase_inc=k_i×262144` 的增量表，仍经过正常事件分配和包络；退出后恢复普通音高表。若来不及增加该测试入口，直接用分散的 MIDI 音符做非相干 FFT，采用窗函数与峰值检测，不为凑整数频点绕过整机声部控制。

按键输入到音频输出的测量包含键盘扫描、USB、CH9350L 串行帧、FPGA 和 DAC。USB 路径不保证确定性无抖动；尽量选低轮询间隔、可确认无冲的有线键盘。先争取 ≤10ms 的实际结果，再依据测量决定是否宣传 ≤5ms；不能用 0.955ms 串口时间或几十微秒 DSP 计算时间代替整机延迟。

| 演示时段 | 操作 | 观众看到/听到什么 |
|---|---|---|
| 0—15 秒 | 直接上电，按三音和弦 | 无电脑音源；灯跟随琴键，屏幕显示真实活动数 |
| 15—35 秒 | 持音，逐渐加压，再转弯音旋钮 | 压力改变响度，旋钮独立变调，视觉同步 |
| 35—55 秒 | 松键后 F6 切到吉他，演奏同一短句 | 两种乐器差异，音色不是靠音量悬殊伪装 |
| 55—70 秒 | F7 合唱开/关 | FPGA 内部效果可听、可旁路 |
| 70—85 秒 | 降音量，F8 进入已验证的多音模式 | 现场分析或事先采集的原始频谱对应真实 8/32 路 |
| 85—90 秒 | 退出测试，Esc 清音 | 操作闭环、停止干净 |

若合唱或屏幕未完成，删除相应环节，不用预录音频补演示。F8 测试模式只发送音符事件，输出样本由 FPGA 实时生成；预录的演示视频可用于材料展示，不能代替现场实时发声。
