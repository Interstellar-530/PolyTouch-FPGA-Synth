## 4. 正式录制前验收

### 4.1 版本和位流冻结

1. 固定使用已通过门禁的 `standard27` 位流，录制期间不改源码。
2. 记录分支、提交号、构建时间、位流 SHA256。
3. 保存 Quick 门禁或完整门禁日志、构建收据和 PnR 报告。
4. 视频中的 RTL、资源数字和位流必须来自同一个版本。
5. 不显示 GitHub Token、串口账号、本机用户名和其他敏感信息。

### 4.2 必须通过的硬件检查

| 检查项 | 通过标准 |
|---|---|
| Dock 供电和下载 | 配置成功，串口命令有 `OK` 应答 |
| CH9350L 键盘链路 | 按下、松开、四音和弦有效 |
| MCP3208 与 FSR | 松、轻、重三档数值可重复变化 |
| PCM5102A | BCK 约 3.000 MHz，LRCK 约 46.875 kHz，每帧 64 BCK |
| 模拟输出 | 示波器或 Line In 能看到对应频率 |
| 四音和弦 | 至少四个独立音符同时发声 |
| 八音并发 | 串口八音事件全部被接受，频谱有八个基频峰 |
| 双音色 | F6 或 `I0/I1` 生效，切换后重新起音 |
| 长按与清音 | 五秒以上长按不被误截断，Esc/X 能清音 |
| 延迟测量 | 十次波形完整，最大值记录清楚 |

### 4.3 示波器测量接法

| 测量任务 | CH1 | CH2 | 触发与时间基准 |
|---|---|---|---|
| BCK/LRCK | DAC 模块 `BCK` 或 Dock `B12` | DAC 模块 `LCK` 或 Dock `C12` | CH1 上升沿，5 µs/div |
| BCK/DIN | DAC 模块 `BCK` | DAC 模块 `DIN` 或 Dock `B13` | CH1 下降沿，1 µs/div |
| 键盘延迟 | CH9350L TXD 或 Dock `L9` | PCM5102A `LINE OUT` 左/右 | CH1 下降沿，1 ms/div |
| 串口测试延迟 | Dock `T13`（BL702 → FPGA） | PCM5102A `LINE OUT` 左/右 | CH1 下降沿，1 ms/div |
| 模拟频谱 | PCM5102A `LINE OUT` 左/右 | 不接 | FFT，0-5 kHz |

接地夹必须接公共 GND 或 3.5 mm 插座 `SLEEVE`，不能夹在信号线上。使用 10× 探头和高阻输入，BCK 测量优先使用短地弹簧。

延迟起点和终点必须在视频字幕中写清。建议统一写为：

> 起点：CH9350L TXD UART 起始位  
> 终点：PCM5102A LINE OUT 达到峰值 10%  
> 十次测量：最小 X.XX ms / 中位 X.XX ms / 最大 X.XX ms

### 4.4 八音频谱测试

串口依次发送并等待每条 `OK`：

```text
D0
M1
V100
I0
N60
N64
N67
N71
N74
N76
N79
N83
X
M0
```

频谱必须来自 PCM5102A 的真实线路输出或示波器模拟通道。图中保留采样率、记录长度、频率分辨率和八个基频标记，不使用软件合成音频替代。

## 5. 三分钟分镜脚本

### 场景 1：开场演奏，0:00-0:12

画面：手指按下四音和弦，最后一下同时切到整机广角。画面叠加标题。

口播：

> 这是一台由 FPGA 逐样本实时计算的电子乐器。键盘决定音高，压力传感器控制表情，所有振荡、包络、混音和输出都在硬件逻辑中完成。

字幕：

> PolyTouch FPGA Synth  
> 纯硬件实时波表合成

### 场景 2：整机与演奏维度，0:12-0:35

画面：镜头依次指向 Dock、CH9350L、MCP3208、FSR402、PCM5102A，然后用一个和弦和一次压力变化完成操作。

口播：

> 系统以 Tang Primer 20K 为核心。CH9350L 接收键盘事件，MCP3208 采集 FSR 压力，PCM5102A 接收 FPGA 输出的标准 I2S 音频。电脑只用于调试和测试事件，不参与音频合成。

字幕：

> 2 个独立演奏维度：键盘选音/触发 + FSR 压力表情  
> 演奏输入与 DAC 之外，音频路径不使用 CPU

### 场景 3：纯 HDL 音频架构，0:35-0:55

画面：先显示一页架构图，再切到 RTL 高亮代码。框图依次出现声部分配、32 位相位累加器、单周期波表、ADSR、混音和 I2S。

口播：

> 每个声部都有独立相位累加器和 ADSR 包络。ROM 保存的是单周期波形，不是整段歌曲或预录 PCM。相位步进、插值、包络和混音都在每个采样节拍实时计算。

字幕：

> 单周期波表，不是预录 PCM  
> 逐样本实时计算  
> 音频路径不使用软核 CPU 或 BL702

### 场景 4：多声部演奏，0:55-1:25

画面：左半屏手部演奏，右半屏串口记录或波形。先单音，再加入四音和弦，松开其中一个音，最后改变 FSR 压力。

口播：

> 按下四个键后，四个声部同时保持各自的音高和包络。松开一个键，只有对应声部进入释放，其余声部继续发声。FSR 提供连续的力度或表情控制。

字幕：

> 4 个以上声部独立发声  
> 独立释放，不截断其他声部  
> 当前整机生产配置为 8 声部

### 场景 5：双音色，1:25-1:45

画面：保持一个和弦，切换钢琴到吉他，再弹同一段短句。切换后必须重新起音。

口播：

> 这里切换钢琴和吉他两种音色。音色参数和包络切换由 FPGA 内部完成，电脑不参与声音生成。

字幕：

> 2 种乐器音色：钢琴 / 吉他  
> 切换后重新起音

### 场景 6：I2S 与 DAC 证据，1:45-2:05

画面：示波器显示 BCK 和 LRCK，随后显示 DIN 活动；最后切到 PCM5102A 模拟输出。示波器刻度、单位和探头接地同时入镜。

口播：

> FPGA 通过标准 I2S 将音频送入 PCM5102A。当前整机档 BCK 约 3 MHz，LRCK 为 46.875 kHz，每帧 64 个 BCK。

字幕：

> 标准 I2S，24 位时隙，64 BCK/帧  
> 当前整机采样率：46.875 kHz

### 场景 7：八音并发与频谱，2:05-2:25

画面：串口界面发送八音事件，右侧显示频谱和八个基频标记。电脑界面只显示事件发送和 OK 回复。

口播：

> 为避免普通键盘的无冲限制，这里通过串口发送八个实时音符事件。FPGA 同时运行八个独立声部，频谱中出现对应的八个基频峰。

字幕：

> 8 个独立声部 × 46.875 kHz  
> 约 375,000 次独立振荡器采样更新/秒  
> 电脑只发送事件，声音由 FPGA 实时合成

### 场景 8：延迟测量，2:25-2:44

画面：示波器 CH1 显示 UART 起始位，CH2 显示 PCM5102A 模拟输出。光标标出起点和终点，角落叠加十次统计值。

口播：

> 延迟测量从键盘事件进入 FPGA 的 UART 起始位开始，到 DAC 模拟输出达到峰值百分之十为止。十次触发中，最大延迟为 [X.XX] 毫秒。

字幕：

> 控制到模拟输出：最小 [X.XX] ms / 中位 [X.XX] ms / 最大 [X.XX] ms  
> 测量端点、阈值、探头位置与十次原始波形随作品报告提交

只有最大值不超过 10 ms 时才使用“满足基础延迟要求”的表述。

### 场景 9：总结，2:44-2:55

画面：回到整机广角，最后演奏一个和弦，叠加关键指标和项目名称。

口播：

> PolyTouch 完成了实时波表合成、多声部混音、多维演奏输入、双音色和标准 I2S 输出。所有关键结果都来自同一冻结版本的 FPGA 位流与实测证据。

字幕：

> 8 声部整机  
> 2 种音色  
> 2 个演奏维度  
> FPGA 实时合成 → I2S → PCM5102A

如果 32 声部已经完成整机板级验证，可在本场景用 3 秒静态指标卡补充“32 声部核心/整机验证”。如果尚未完成整机集成，不进入提交版。

## 7. 拍摄与剪辑顺序

1. 先拍演奏 A 机位和手部 B 机位，确保四音和弦、FSR 和双音色各至少两条可用素材。
2. 单独录制示波器画面，保证刻度、单位、触发电平和探头接地可见。
3. 录制 RTL、构建报告、串口命令和频谱屏幕，隐藏个人信息。
4. 先按 2 分 55 秒粗剪，删除重复动作和等待时间。
5. 技术证据画面优先保留，不为了镜头效果删掉延迟波形或频谱峰值。
6. 最后加旁白、字幕、标题和结尾，统一音量和色彩。
7. 不使用无授权背景音乐；真实乐器输出和旁白是主声源。

  -vf "scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2,fps=30" `

## 10. 事实口径边界

可以展示：

- 8 声部实时合成
- 钢琴和吉他两种音色
- 键盘触发和 FSR 压力两个演奏维度
- 标准 I2S 到 PCM5102A

必须有实测证据才能展示：

- 控制到模拟输出延迟不超过 10 ms
- 32 声部整机并发
- 5 ms 低延迟
- FPGA 内部混响、延迟、合唱
- LED、频谱或波形实时可视化
- 48 kHz 整机档

没有证据时只能写“RTL 仿真结果”“核心原型验证”或“后续工作”，不能写成“整机已完成”。
