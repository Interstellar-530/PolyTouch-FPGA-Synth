## 4. 正式录制前验收

### 4.1 版本和位流冻结

1. 固定使用已通过门禁的 `standard27` 位流，录制期间不改源码。
2. 记录分支、提交号、构建时间、位流 SHA256。
3. 保存 Quick 门禁或完整门禁日志、构建收据和 PnR 报告。
4. 视频中的 RTL、资源数字和位流必须来自同一个版本。
5. 不显示 GitHub Token、串口账号、本机用户名和其他敏感信息。

### 4.2 必须通过的硬件检查

| 检查项 | 通过标准 |
|---|---|
| Dock 供电和下载 | 配置成功，串口命令有 `OK` 应答 |
| CH9350L 键盘链路 | 按下、松开、四音和弦有效 |
| MCP3208 与 FSR | 松、轻、重三档数值可重复变化 |
| PCM5102A | BCK 约 3.000 MHz，LRCK 约 46.875 kHz，每帧 64 BCK |
| 模拟输出 | 示波器或 Line In 能看到对应频率 |
| 四音和弦 | 至少四个独立音符同时发声 |
| 八音并发 | 串口八音事件全部被接受，频谱有八个基频峰 |
| 双音色 | F6 或 `I0/I1` 生效，切换后重新起音 |
| 长按与清音 | 五秒以上长按不被误截断，Esc/X 能清音 |
| 延迟测量 | 十次波形完整，最大值记录清楚 |

### 4.3 示波器探头接线

#### 4.3.1 先确认板卡和模块方向

Dock 的 PMOD 排针必须先找 `J5/J6` 丝印和方形焊盘确认 1 脚，不能按照片左右方向猜孔号。CJMCU-5102 的左侧 11 孔按实物照片从上到下依次是：

```text
1  VCC
2  3.3V
3  GND
4  FLT
5  DMP
6  SCL/SCK
7  BCK
8  DIN
9  LCK
10 FMT
11 XMT/XSMT
```

这些是模块孔名，不是 PCM5102A 芯片脚号。数字测量使用 10× 探头，接地夹接公共 GND；模拟测量使用立体声 3.5 mm 转接头，地夹接 `SLEEVE`，不要使用会把右声道短接到地的单声道插头。

#### 4.3.2 固定针位对照

| 信号 | Dock/FPGA 端 | DAC 模块端 | 用途 |
|---|---|---|---|
| BCK | PMOD2 `J6-5`，球号 `B12` | 第 7 孔 `BCK` | I2S 位时钟 |
| LRCK/LCK | PMOD2 `J6-6`，球号 `C12` | 第 9 孔 `LCK` | I2S 帧时钟 |
| DIN | PMOD2 `J6-7`，球号 `B13` | 第 8 孔 `DIN` | I2S 数据 |
| 数字 GND | PMOD2 `J6-3/4`，`GND` | 第 3 孔 `GND` | 数字探头地 |
| CH9350L TXD | PMOD3 `J5-5`，球号 `L9` | CH9350L 模块 `TXD` | 普通 USB 键盘事件 |
| PC 串口 RX | 球号 `T13`，仅在有测试点时使用 | BL702 → FPGA | 电脑串口测试事件 |
| DAC 模拟左声道 | 不使用 FPGA 引脚 | 3.5 mm `TIP` | 左声道模拟输出 |
| DAC 模拟右声道 | 不使用 FPGA 引脚 | 3.5 mm `RING` | 右声道模拟输出 |
| 模拟地 | 不使用 FPGA 引脚 | 3.5 mm `SLEEVE` | 模拟探头地 |

CH9350L 的接线关系是 `CH9350L TXD → Dock PMOD3/L9`，`CH9350L RXD → 模块自身 GND`，`Dock PMOD3/N8` 留空。不要把 `N8` 当作键盘数据脚，也不要把 `M11` 当作控制起点；`M11` 是 FPGA 发给电脑的 UART 回复信号。

`T13` 是 BL702 到 FPGA 的串口接收球号，只在板上存在可安全探测的测试点或明确排针时使用。如果没有可接触的 T13 测试点，不要直接去碰芯片球，改用 `L9` 测量实体键盘事件，或者只记录串口命令和声音起音，不宣称完成了精确的总延迟测量。

#### 4.3.3 四种推荐的示波器捕获

**捕获 A：BCK 和 LRCK**

```text
CH1 10×  → DAC 模块 BCK（第 7 孔）或 Dock J6-5/B12
CH2 10×  → DAC 模块 LCK（第 9 孔）或 Dock J6-6/C12
接地夹   → DAC 模块第 3 孔 GND 或 Dock J6-3/4
CH1 触发 → 上升沿，约 1.5 V
时间基准 → 5 µs/div
```

预期 BCK 周期约 `333 ns`、频率约 `3.000 MHz`；LRCK 周期约 `21.33 µs`、频率约 `46.875 kHz`；一个 LRCK 周期内应有 64 个 BCK 周期。先调 `1 V/div`，如果波形超出屏幕再增大档位。

**捕获 B：BCK 和 DIN**

```text
CH1 10×  → DAC 模块 BCK（第 7 孔）或 Dock J6-5/B12
CH2 10×  → DAC 模块 DIN（第 8 孔）或 Dock J6-7/B13
接地夹   → DAC 模块第 3 孔 GND 或 Dock J6-3/4
CH1 触发 → 下降沿
时间基准 → 1 µs/div
```

DIN 应在 BCK 边沿附近发生数据变化，松键或发送 `M0` 后应停止发送有效音频。普通示波器不要求逐位人工解码 24 位数据；这一段用于证明数据线有真实音频活动。需要详细解码时再用 Gowin GAO。

**捕获 C：实体键盘到模拟输出的延迟**

```text
CH1 10×  → Dock PMOD3 J5-5/L9，或 CH9350L 模块 TXD
CH2 10×  → PCM5102A LINE OUT 的 TIP 或 RING
CH1 地夹 → Dock PMOD3 J5-3/4 GND
CH2 地夹 → 3.5 mm SLEEVE 或模块音频地
CH1 触发 → UART 起始位下降沿，约 1.5 V
时间基准 → 先设 1 ms/div
采集     → Single 或 Normal
```

从 CH1 的 UART 起始位量到 CH2 模拟输出达到峰值约 10% 的时间。连续测量十次，记录最小值、中位数和最大值。这个结果包含 CH9350L 上报、FPGA 处理、I2S 输出和 DAC 模拟建立时间，但不能把键盘内部 USB 扫描时间算作已测量。

**捕获 D：电脑串口事件到模拟输出的延迟**

```text
CH1 10×  → 仅在可安全接触时接 Dock T13（BL702 → FPGA）
CH2 10×  → PCM5102A LINE OUT 的 TIP 或 RING
CH2 地夹 → 3.5 mm SLEEVE 或模块音频地
CH1 触发 → 下降沿，约 1.5 V
时间基准 → 先设 1 ms/div
```

如果找不到安全的 T13 测试点，不进行这项精确测量。可以展示串口命令发送、设备 `OK` 回复和实际声音，但不能把软件时间戳与声音起音直接拼成一个精确的总延迟数字。

**捕获 E：PCM5102A 模拟频谱**

```text
CH1 10×  → LINE OUT 的 TIP（左）或 RING（右）
接地夹   → 3.5 mm SLEEVE
垂直档位 → 先设 1 V/div
耦合     → 基线偏置明显时使用 AC
FFT 范围 → 0 到 5 kHz
```

播放八音并发后，在频谱中标记八个基频峰。保留频率轴、幅度轴、时间基准和 FFT 设置；如果示波器 FFT 分辨率不足，改用电脑 Line In 录音和 Python FFT，不要用软件合成音频替代。

#### 4.3.4 延迟字幕的固定写法

推荐在视频中写：

> 起点：CH1 接 PMOD3 `J5-5/L9`，CH9350L TXD 的 UART 起始位  
> 终点：CH2 接 PCM5102A `LINE OUT`，达到峰值 10%  
> 十次测量：最小 X.XX ms / 中位 X.XX ms / 最大 X.XX ms

如果只测到 `L9` 到 `DIN` 的数字链路，字幕必须写“FPGA 数字链路延迟”，不能写成“整机模拟输出总延迟”。

> 为避免普通键盘的无冲限制，这里通过串口发送八个实时音符事件。FPGA 同时运行八个独立声部，频谱中出现对应的八个基频峰。
>
> 延迟测量从键盘事件进入 FPGA 的 UART 起始位开始，到 DAC 模拟输出达到峰值百分之十为止。十次触发中，最大延迟为 [X.XX] 毫秒。
>
> PolyTouch 完成了实时波表合成、多声部混音、多维演奏输入、双音色和标准 I2S 输出。所有关键结果都来自同一冻结版本的 FPGA 位流与实测证据。

## 7. 拍摄与剪辑顺序

1. 先拍演奏 A 机位和手部 B 机位，确保四音和弦、FSR 和双音色各至少两条可用素材。
2. 单独录制示波器画面，保证刻度、单位、触发电平和探头接地可见。
3. 录制 RTL、构建报告、串口命令和频谱屏幕，隐藏个人信息。
4. 先按 2 分 55 秒粗剪，删除重复动作和等待时间。
5. 技术证据画面优先保留，不为了镜头效果删掉延迟波形或频谱峰值。
6. 最后加旁白、字幕、标题和结尾，统一音量和色彩。
7. 不使用无授权背景音乐；真实乐器输出和旁白是主声源。
