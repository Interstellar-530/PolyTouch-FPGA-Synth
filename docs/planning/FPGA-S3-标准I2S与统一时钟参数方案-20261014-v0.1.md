# S3 方案：标准 I2S 发送器、独立接收模型与统一时钟参数

日期 2026-10-14，版本 v0.1，状态：方案待用户确认，尚未编写代码。工作基线是 S2 分支 `codex/s2-gpio-keyboard` 的 `dd43257`，生产发布仍为 `b559237`（v1.01）。本文件只记录实现方法与核查依据，不代表任何功能已经通过验收。

## 1. 任务范围与验收口径

计划表把 S3 定义为“i2s_tx、独立接收解码模型、统一时钟/采样率参数”，自检标准为：12.288 MHz 模拟时钟；LRCK 每 256 周期、BCK 每 4 周期；64 BCK/帧、一位延迟；正负/极值/左右交替逐位一致；帧内样本不撕裂；sample_tick 单周期；复位/静音无 X。下面把这条文字展开成可执行的断言，作为本轮唯一的验收定义：

在被测模块跑 12.288 MHz 时钟的前提下，LRCK 的一个完整周期恰为 256 个时钟，BCK 的一个完整周期恰为 4 个时钟，每帧恰好出现 64 个 BCK 周期；LRCK 每次跳变与一次 BCK 下降沿同拍；LRCK 为低表示左声道；LRCK 跳变后的第一个 BCK 上升沿采到的数据位是填充位，第二个上升沿才是 MSB；独立解码模型从 BCK/LRCK/DIN 三根引脚重建出的左右两个字与当帧期望样本逐位相等；帧中途改变输入样本不会改变本帧已经发出的内容；`sample_tick` 高电平只持续一个时钟；复位期间、复位刚释放以及数字静音期间，三根引脚都不出现 X。

证据一律取自引脚级解码与模块端口，不引用被测模块内部的位计数器或移位寄存器。这条纪律沿用 S1：`tb_audio_capture` 只解 PT8211 引脚，内部 `frame_data` 仅作独立对照。

## 2. 核查结果

### 2.1 比赛文件

`docs/history/handoff-20261008/COMPETITION_REQUIREMENTS.md` 要求“逐样本 FPGA HDL 合成、I2S 输出至 DAC、控制到音频延迟 ≤10 ms、≥4 声部、不使用预录 PCM”，评分核心是“活跃独立振荡器数 × 实际输出采样率”，并明确“提高内部过采样不加分”。这条对 S3 的直接含义是：采样率必须是真实的 48 kHz，不能靠 27 MHz 近似分频凑数后宣称 48 kHz；同时 I2S 只是输出接口，本项不产生任何振荡器吞吐量，不改变评分。

`docs/planning/电子乐器项目规划.md` 第 4.7 节给出的目标参数是 48 kHz、24 位有效数据、每声道 32 个 BCK，即 BCK = 3.072 MHz、LRCK = 48 kHz，PCM5102A 可用内部 PLL 不强制提供 MCLK，FMT 选择标准 I2S。`docs/design/minimum_design/01_时钟配置.md` 进一步限定：12.288 MHz 直接作为系统时钟、不用 PLL；`sample_tick` 在 `sys_cnt == 0` 时拉高一个周期；`i2s_bck` 三个时钟周期翻转一次得 3.072 MHz；`i2s_lrck = sys_cnt[7]` 得 48 kHz；并明确“27 MHz 无法通过高云 rPLL 整数分频得到 12.288 MHz，可以把 27 MHz 用于 PT8211 近似调试，但不应把标准 I2S 锁定建立在它上面”。本方案与这两份文件一致。

### 2.4 本机与工具链约束

板载 27 MHz 无法整数分频到 12.288 MHz，所以 12.288 MHz 只能由外部有源晶振提供，本轮仿真用测试台模拟这一时钟，不涉及实物晶振与 GCLK 引脚（这部分是计划里单独列出的时钟迁移与上板步骤）。门禁工具是 Icarus Verilog，`run_simulation.ps1` 用 `-g2012 -I .` 编译，`\`include "rtl/audio/xxx.vh"` 这种相对源码根的写法已有先例（`song_player.v` 引 `rtl/audio/song_roms.vh`，`tb_song_timing.v` 引 `rtl/audio/song_expect.vh`），Gowin 侧构建脚本 `build_instrument.tcl` 会 `cd` 到源码根再综合，因此新增头文件沿用同一写法即可，不需要额外改构建脚本的包含路径。

当前 Codex 默认沙箱下 Icarus 编译仍异常退出 `0xC0000005`（配置为 `prefer_mxc = true` 与 `windows.sandbox = "elevated"`），仿真门禁需要在沙箱外执行，沿用已批准的 `powershell -NoProfile -ExecutionPolicy Bypass -File` 前缀。详细结论和需要手动调整的配置放在任务收尾单独给出。

## 3. 设计

### 3.1 i2s_tx 结构

模块端口按下面的定义实现，风格与现有 `pt8211_tx.v` 一致：单一 `clk` 域、显式复位初值、`sample_tick` 为单时钟脉冲，不用 PLL、不用厂商原语。

| 端口 | 方向 | 说明 |
| --- | --- | --- |
| `clk` | in | 系统时钟，本轮由测试台按 12.288 MHz 驱动，模块本身不假设具体频率 |
| `rst` | in | 同步复位，清串行器与样本保持寄存器，DIN 输出零；顶层建议接 `por`，不要接软复位 |
| `sample_l`、`sample_r` | in | 每声道 `DATA_BITS` 位有符号样本，默认 16 位；顶层把混音结果同时接两个输入 |
| `bck`、`lrck`、`din` | out | 标准 I2S 三线输出 |
| `sample_tick` | out | 帧边界的一个时钟脉冲，供上层作为 48 kHz 全局采样使能 |

内部只有三组状态：帧长计数器、半周期相位累加器、每声道 32 槽的串行器。串行器在每次 BCK 下降沿推进一个槽，槽 0 输出填充位 0，槽 1 到槽 `DATA_BITS` 依次输出样本的 MSB 到 LSB，其余槽输出 0；这样 16 位数据正好落在图 14 所示的位置，且 24 位数据只需把 `DATA_BITS` 改成 24 即可，24 位配 64 BCK/帧同样是手册允许的组合。

### 3.2 分频与相位关系

BCK 不用固定分频比，而用相位累加器：每个时钟给累加器加 128，超过帧长就减去帧长并翻转 BCK。它带来三个可验证的性质。其一，12.288 MHz 配 48 kHz 时帧长 256、每次累加正好两次时钟翻转一次，得到 BCK 周期 4 个时钟、每帧 64 个 BCK，与验收标准逐项吻合。其二，帧长不是 128 的整数倍时（例如 27 MHz 调试档的 576），翻转次数仍然精确等于 128，BCK 平均周期 4.5 个时钟，得到 BCK = 3 MHz、LRCK = 46.875 kHz，比例关系仍是 64:1，只是单周期抖动不超过一个时钟（约 37 ns）。其三，每帧翻转次数固定为偶数，最后一帧的末尾必然落在 BCK 下降沿上，于是 LRCK 的每次跳变都与 BCK 下降沿同拍，符合 I2S 对 LRCK 与 BCK 相位关系的要求，也避免了手册 §9.3.2.1 描述的“关系无效即静音”分支。

| 档案 | 时钟 | 帧长（时钟） | BCK | BCK 周期 | LRCK | 用途 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 标准 | 12.288 MHz | 256 | 3.072 MHz | 4 个时钟 | 48 kHz | 验收目标，配 PCM5102A |
| 调试 | 27 MHz | 576 | 3.000 MHz | 平均 4.5 个时钟（4/5 交替） | 46.875 kHz | 只作参数化与仿真对照，不作为 48 kHz 证据 |

27 MHz 档案存在的意义是证明同一份参数化代码在两个时钟下都成立，并在没有外部晶振时提供一条可跑通的数字路径；它的采样率是 46.875 kHz，不能写成 48 kHz。

### 3.3 统一时钟与采样率参数

新增 `rtl/audio/clk_params.vh`，把 `CLK_HZ`、`SAMPLE_RATE_HZ` 以及派生量（帧长、每声道槽数、BCK 比例）集中在一处，两个档案各自成段，`i2s_tx` 通过 module parameter 接收这两个值，模块内部只允许出现由参数推导出来的 localparam，不再出现裸常数。文件同时用注释列出受采样率影响、但本轮不修改的模块，作为时钟迁移那一步的清单：`note_phase_inc.v` 的十二个半音频率常数（现按 46875 Hz 生成）、`uart_ctrl.v` 的 `CLK_HZ`、`song_player.v` 的每拍样本数、`adsr.v` 的步进与时间换算、`pt8211_tx.v` 的 18 分频（12.288 MHz 下整除关系不同）、`tb_tick_rate.v` 的期望值、`tools/analyze_audio_capture.py` 里的 `FS = 46875`、以及 `tools/run_audio_verification.ps1` 里写入 `reproduction.json` 的采样率字段。这一条把“统一”落成一张可执行的清单，而不是只在文档里写一句“统一参数”。

参数合法性检查放在 `` `ifdef SIMULATION `` 保护块里，用 `$fatal` 结束仿真：帧长小于 128、`DATA_BITS` 大于 31（标准 I2S 的 32 槽半帧内放不下 32 位数据加一位延迟）、或者时钟与采样率不能整除时报错退出。综合时这个块被忽略，避免厂商综合器对仿真系统任务的兼容风险。

### 3.4 独立接收解码模型

新增 `sim/i2s_rx_model.v`，它只从 `bck`、`lrck`、`din` 三根线恢复样本，行为按手册定义而不是按被测模块的内部实现：在 BCK 上升沿采样 DIN 与 LRCK，LRCK 为低收左声道、为高收右声道；每次 LRCK 跳变后的第一位丢弃（一位延迟），随后收 `DATA_BITS` 位；槽内多余位忽略。模型带一个 `FORMAT` 参数，可以切换成“左对齐”或“右对齐”这两种错误假设，用于负面控制。这个模型将来抓顶层 I2S 引脚时可以复用，与 S1 的 PT8211 引脚解码台是同一套思路。

### 3.5 测试台与负面控制

新增第十三台 `tb_i2s_tx.v`，自检失败用 `$fatal(1, ...)` 结束，使门禁退出码非零。断言覆盖：LRCK 周期 256 个时钟、BCK 周期 4 个时钟（记录实测）、每帧 64 个 BCK 上升沿、`sample_tick` 周期 256 且宽度 1 个时钟、LRCK 跳变与 BCK 下降沿同拍、延迟位为 0 且 MSB 紧随其后；解码一致性的测试向量取 0x0000、0x0001、0x7FFF、0x8000、0xFFFF、0x5555、0xAAAA 以及固定种子的伪随机序列，覆盖正负、极值与满量程；左右声道用不同数值（左为 n、右为 −n）验证交替与极性；帧中途在多个时刻改变输入，断言本帧解码结果不变、下一帧等于新值；复位期间与释放后检查三根线无 X，且复位后的首个完整帧左右字都为零。

负面控制做两层。第一层把解码模型的 `FORMAT` 换成左对齐与右对齐，断言两种错误假设都必须与原序列不一致，用来证明“一位延迟”确实存在且检查器有分辨力，这个场景同时对应实物把 FMT 跳线接错时的表现。第二层用 27 MHz 档案再跑一遍同样的解码与断言（LRCK 576 个时钟、每帧 64 个 BCK、BCK 半周期只允许 4 或 5 个时钟、解码一致），把“统一参数”从声明变成证据。两个档案在同一个测试台里用两套时钟与两个被测实例分时段运行，互不干扰。

## 4. 可行性与鲁棒性自查

帧内不撕裂来自设计而不是运气：串行器只在帧边界从 `sample_l/sample_r` 锁存一份数据，整帧内所有槽都从锁存后的寄存器取值，所以输入在任何时刻变化都只能影响下一帧。配合 `sample_tick` 在帧边界给出，上层流水线有一整帧（48 kHz 下 20.8 µs）的余量，这与当前 `pt8211_tx` “整条音频流水线存在帧延迟”的约定一致。

无 X 来自两处：一是所有寄存器都有显式复位值，二是复位期间 DIN 强制为零、BCK/LRCK 保持翻转。手册 §9.3.2.1 说明 LRCK 与 BCK 关系失效超过 4 个 LRCK 周期器件会静音等待重同步，所以顶层应当把 `i2s_tx.rst` 接 `por`，软复位只作用于样本值（置零），这与现有顶层把 `pt8211_tx.rst` 接 `por` 的做法相同，也是本项不修改顶层的前提下需要写进文档的接线约定。

12.288 MHz 档的时序余量充足：BCK 半周期约 163 ns，DIN 在下降沿更新、上升沿被采样，寄存器到引脚之间只有一级选择逻辑，高云器件在 81 ns 周期下的布线余量远大于该路径需求。本模块不使用 BSRAM、不使用 18×18 乘法器，只增加计数器与少量组合逻辑，资源压力可以忽略；具体数字留待可选的独立综合记录。

已知限制需要如实记录。手册没有给出 DIN 相对 BCK 的建立/保持具体数值，只有“上升沿采样”这一条事实与 20–1000 ns 的 SCK 周期范围，所以下降沿更新的选择依据是半周期余量，实物仍须用逻辑分析仪核对波形与建立时间。数字静音会触发器件自身的零数据检测（连续 1024 帧后模拟静音），这不是缺陷，报告中不应把它写成静音失败。XSMT 斜坡、外部 12.288 MHz 晶振、GCLK 引脚、Bank 电压与实物 I2S 眼图都属于上板验收范围，本轮不涉及。本轮也不把 `i2s_tx` 接进顶层，所以不能声称“标准 I2S 输出已达标”，只能说模块级数字逻辑通过仿真。

## 5. 执行步骤与回退

按“先写约束与参数文件、再写模块与模型、再写测试台、最后进门禁”的顺序推进，每一步都以门禁退出码为放行条件。参考做法是 S2 的教训：新增模块必须同时进入 Gowin 工程源文件清单，且不要把连续赋值写到 `reg` 上，这类问题只有跑过一次综合才会暴露。

| 步骤 | 内容 | 预计工时 |
| --- | --- | ---: |
| 1 | `rtl/audio/clk_params.vh` 与 `rtl/audio/i2s_tx.v` | 1.5–2 h |
| 2 | `sim/i2s_rx_model.v` 与 `sim/tb_i2s_tx.v`（含两个档案与负面控制） | 2.5–3 h |
