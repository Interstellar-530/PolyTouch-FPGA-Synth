### A 线的算法要求

A1 先建立算术约定，再决定是否改运算。例如 16 位有符号表的两个极值相减需要 17 位；32 路 24 位有符号样本求和至少需要 29 位，现有 32 位累加器应先证明有余量。乘法保留足够中间位宽，明确每次右移的舍入和负数行为。把可证明等价的窄加法/寄存拆分作为首选，不默认用更高阶插值、更宽数据或额外乘法器换取难以测出的收益。

A2 的频率约束按实际最大频率计算，包括弯音和新增调制的上界。512 点周期表的谐波数不超过 255；采用保守带限时可用 `H <= min(255, floor(0.45*Fs/f_max))` 作为生成上限，明确这是本项目的设计余量。先优化已有音区对应的表，保留 bank 编号。若确实需要增加音区/表数，单独提交存储预算和接口变更方案。仅在输出后加低通，不能证明已经消除查表产生的混叠。

先保留两类乐器，并精调四个确实不同的配置，再考虑八预设。当前 `start_stage=(tone>=3)?4:3` 只有两种起始阶段行为，不能把五个键位直接写成五种已验证音色。预设差异要落在实际包络、阶段或表混合参数上，保持既有全局换音色语义；持音是否切换不偷偷改变。

A3 分开检查换表、增益突变和重按，不给所有相邻样本统一设一个“越小越好”的差值阈值。高音正常波形本来就可能有大斜率。用连续参考及切换瞬间的额外残差比较过渡噪声，保护起音瞬态；如果更长的淡入只是把响应拖慢，就不应视为优化成功。A3 只修改数据通路的过渡处理；包络和表阶段定时仍由 B 维护，需要调整配置序列时交给 B，避免两侧重复平滑。

### B 线的算法要求

B1 在满声部时按明确的确定性顺序选择声部，例如空闲优先、释放中较弱者优先，再按固定优先级窃声；实际策略以基线约定为准。优化配置流量时，不能漏掉包络推进、表阶段变化和整帧弯音刷新。ready 拉低时，已提交事务保持稳定，更新保留在待处理状态；不要覆盖等待中的 Note Off。队列深度先根据最坏突发计算，再决定是否扩容。

B2 已有三点中值加一阶 IIR，不从零重写。用输入序列比较响应速度、静止抖动、中心偏置和低位舍入停滞，再决定是否增加内部小数位、迟滞或调整更新频率。全部 ADC 码可以在 Python 中扫完，RTL 只取边界和关键序列。无真实 FSR 数据时把阈值、ADC 中心和滤波参数做成可调项，不把人造噪声模型的最佳参数当成实物标定值。

弯音应比较“目标音分→频率比例→实际 DDS 增量”的误差，滑音与颤音复用配置路径，控制更新与逐样本发声分层。三维表情是 P1 的扩展目标：当前压力、弯音和独立新增亮度可以在模型中分别测试；一个压力值同时改变三个参数只能算一个输入维度，自动 LFO 也不能代替第三个独立演奏输入。物理第三维映射留待硬件阶段。

B3 同时解决现场展示的可重复输入问题。CH9350L 当前键盘帧只有六个普通键码槽，不能用“实体键盘同时按 32 键”作为 32 复音的验收前提。测试模式应直接通过既有事件握手产生 32 个独立音符，让各声部拥有自己的相位、频率和包络；再逐个 Note Off 检查对应贡献消失。这证明数字能力，最终还需实机演示。

## 4. 没有设备时，怎样判断做得对

不需要电表、示波器、声卡或外部音箱。最低环境为已有 `C:/iverilog/bin/iverilog.exe`、`vvp.exe` 和 Python；数值分析需要 NumPy，已有脚本使用的依赖沿用现有环境。Gowin 只由你在本机做资源与静态时序实现。队友没有 Gowin 也能独立交 RTL、自检和数值结果。电脑试听 WAV 是可选补充。

| 检查项 | 在电脑上的做法 | 可以得出的结论 |
|---|---|---|
| 音高 | 根据实际 `phase_increment*Fs/2^32` 计算，再与目标频率比较音分；短 RTL 核对增量和相位推进 | DDS 数字音高正确；无需靠短 FFT 猜 1Hz 精度 |
| 包络与控制 | Python 独立参考和 RTL 逐值/逐帧比对 | 攻击/衰减/释放时长、范围和更新逻辑符合约定 |
| 波表质量 | 对周期表做频域分析；相同频率、相同响度渲染定点参考；关键片段与 RTL 对照 | 带限、量化和指定音色变化有依据；没有证明模拟底噪或真实听感 |
| 32 声部 | 独立状态与参考求和，逐个静音/释放检查结果；需要时追加一次较长 I2S 数字捕获 | 每声部独立参与数字输出；频谱图片本身不能替代声部状态与因果检查 |
| I2S/丢样 | 接收模型从 BCK/LRCK/DIN 独立解码，核对位序、位数、帧号与内部提交值 | 标准数字协议、每帧提交与输出一致 |
| 数字延迟 | 测试台对“接受事件→配置完成→样本完成→对应 I2S 样本”分别计时 | 指定数字接口之间的响应；没有测到 USB 扫描、物理动作或 DAC 模拟延迟 |
| 资源与速度 | 在完整候选配置上做一次 Gowin 综合/PnR，核对报告而非只看退出码 | 资源和约束下静态时序；没有证明晶振、接线或供电稳定 |

每个任务只保留三类最小证据：一条可复现命令、一份自检/指标结果、一个能说明变化的数值或样本片段。无需先搭复杂评测平台。B4 复用 `S/tools/pressure_bend_ref.py`，以及仓库根目录下 `tools/s6_reference.py`、`tools/analyze_audio_capture.py`、`tools/verify_audio_quality.py`、`tools/verify_ram_audio.py` 中适合的部分；先核对脚本支持的输入格式，不能把模型 WAV 当成 RTL 捕获。

建议在 `metrics.json` 记录提交/输入哈希、参考算法版本、随机种子、测试名、退出码、实际 Fs、采样数、最大数值误差、帧尾、数字延迟与覆盖边界。Python 长渲染用于音色比较，RTL 主要跑短片段与极值。长 FFT、长音符和完整历史回归按变更需要执行，避免每次改动都等待长仿真。

| 独立复音与采样 | 32 路独立相位/增量/包络，实际输出 48kHz，每帧恰提交一次 | 固定声部规模，提升控制与音质 |
| 等价优化 | 与位精确参考逐样本一致 | 实际减少周期、资源或组合路径之一 |
| 有意改变数值的优化 | 改前约定误差界和比较方法；简单增益路径可从 ≤1 LSB/级评估 | 有听感意义的路径同时给模型指标与 RTL 片段；不把全链误差一律设为 1 LSB |
| 音高 | 支持音域内静态 DDS 误差目标 ≤1 音分；报告弯音全范围最差误差 | 弯音映射误差目标 ≤2 音分；若基线已满足则保持 |
| 音质 | 无新增回绕、直流异常、周期缝与切换额外阶跃；既有音色无未说明退化 | 对事先选定的高音案例，混叠残差较基线改善 ≥6dB；匹配响度并记录分析方法，未达标如实说明 |
| 事件 | 不丢事件、不粘音、背压期间数据稳定；32 事件突发全部处理 | 核心接受到对应 I2S 样本目标 ≤4 帧，突发全部响应 ≤1ms；快速起音参数单独注明 |
| 完整数字输入 | 独立记录 UART 首位/末位、ADC 事务完成、事件接受与 I2S 输出时间 | 在明确输入假设下争取 ≤5ms；不得写成实物总延迟已通过 |
| 总帧预算 | 所有 P0 同时启用、最坏已定义突发下帧尾 ≤1152/1536，至少留 25% | 与同功能基线比较，干声争取保持 ≤800 拍；旧基线 617 拍不是全功能承诺 |
| 静态时序 | 73.728MHz 与相关真实约束下 setup/hold 违例均为 0 | 最差 setup 争取 ≥0.5ns；Fmax 本身不单独算音频收益 |

默认 Attack=140/帧，完整上升约需 `ceil(65535/140)/48000=9.77ms`。因此测数字调度延迟用快速起音，测正常演奏响应则单独报告预设与输出检测阈值；不把两种数据混用。当前 CH9350L 11 字节键盘帧在 115200、8N1 下的线缆传输约 0.955ms，也要与模块内部延迟分开。USB 上游时延仍未知。

## 5. 资源使用与合并顺序

本阶段先不争取更高 Fmax、64 声部、96kHz 或内部过采样。已有 617/1536 拍的记录说明可以先完成有价值的算法和控制，不必为追求更短代码重新设计整套流水。代码的清晰度体现在明确算术、固定边界、一次锁存、有限状态和可复现结果。

| 资源 | 主线分配建议 | 约束 |
|---|---|---|
| BSRAM | 基线 26；A/B 各预留最多 2 块增量；合流保守上界 30/46 | 小状态先计算是否适合寄存器；不要为了用 RAM 而搬运所有状态 |
| P1 单声道延迟 | 例如 4096×16 按 1024×18 组织约 4 块，48kHz 下约 85.33ms | 端口模式、反馈位宽和初始化另算；必须用厂商映射确认，不只做 bit 数相除 |
| 乘法器 | 基线保守按约 5 个 18×18 等效记账；A/B 各建议增量不超过 4 个 | 规划上界约 13 个等效；最终同时记录原语与厂商 DSP 宏口径，不把 24 宏当作 24 个 18×18 |
| 帧周期 | A 音频/主处理预留 800 拍，B 调度配置预留 288 拍，提交交接 64 拍，共 1152 | 这是保守预约，不把现有重叠计算重复当收益；最终测完整配置的最坏路径 |

每次增加表、状态、效果或队列前更新块数和周期预算。BSRAM ROM 继续使用 Gowin IP/原语；不改成大 case，不用 DDR3 做逐样本查表，也不引入软核 CPU 或 BL702 执行音频算法。

合并按 G0→A1/B1→A2/B2→A3/B3→A4 顺序分小批推进，B4 贯穿全程。每项提交同时包含 RTL、自己的测试台、参考变化和证据，避免把全部工作压成一个难以拆分的提交。ROM 表值、厂商初始化、元数据与生成脚本必须同批合入。

由你先合并 B 的独立模块和测试，再统一登记构建源与测试列表；不能只拷贝 `.v` 而漏掉 HEX、头文件或参数。原有 `run_simulation.ps1 -Tests` 只认识已登记名称，新增测试在登记前用各自目录内的独立 runner，未知名称应继续失败。两人不并行改公共测试注册表。

可立即使用的现有检查命令如下，均从仓库根运行，不接硬件：

```powershell
$gate = (Resolve-Path -LiteralPath '.\output\handoff_milestone2_20261008\source\sim\run_simulation.ps1').Path
& $gate -Suite Quick
& $gate -Suite Ram32
& $gate -Tests @('tb_voice_sched32_review','tb_ram32_controls')
```

日常执行改动专项，合流执行 Quick、Ram32 和对应的音频/控制专项；不把 Quick 称为完整回归。新增断言失败必须 `$fatal`，编译失败、超时、空测试或缺失输入都不能通过。任何后续 Verilog 烧录都必须先通过规定仿真门禁，本阶段不烧录。

若采用时间安排，可按 10/24—25 做 G0、A1/B1，10/26—27 做 A2/B2，10/28—29 做 A3/B3 与合流。先完成 P0 再选择 P1；预计超出容量时取消 P1，不压缩合流验证。官网目前给出的提交截止为 11/4 18:00，建议 11/2 冻结提交候选，为报告、复现和之后可能恢复的硬件验证留时间。硬件迟迟不可用时，材料中如实保留未验项。

回退按任务提交逐项撤回，先保留优化关闭的基线模式。共享 dirty 工作区禁止整树恢复或清空；回退只作用于该任务所有的文件。归档到 `archive/FPGA-日期-版本/`，保留源码、日志、数值结果、复现命令、限制、MANIFEST 和 SHA256。临时目录先列出解析后的绝对路径，确认位于各自 tmp 子目录，再删除；不得清理对方任务或运行环境。
