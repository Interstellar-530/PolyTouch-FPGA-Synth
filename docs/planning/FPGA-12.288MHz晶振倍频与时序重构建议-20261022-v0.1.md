# 12.288MHz 外部晶振：倍频利用与时序重构建议

日期：2026-10-22。规划基线：`c7e4bc6`，RTL 沿用 `4f51a63` 合流版本。目标器件为 GW2A-LV18PG256C8/I7，版本 C。本文只提供执行建议，不修改 RTL、约束、引脚或位流，不执行烧录。声部保持 32 路，继续使用已接受的钢琴 12 表、吉他 30 表方案。

## 1. 建议采用的方案

**用 12.288MHz 外部有源晶振作为音频参考，I2S 保持在这个参考时钟域；通过一个 rPLL 为合成与效果器生成更高的计算时钟。先接通 49.152MHz 基线，完成关键路径重构后以 73.728MHz 为主目标，98.304MHz 作为后续冲刺档。** 原有依赖板载时钟的 USB/HID 等外设逻辑保留原时钟，通过事件队列与音频计算域连接。

12.288MHz 可以精确整数分频得到 48kHz 采样节拍和 3.072MHz I2S BCK。倍频增加的是每个采样周期内可执行的计算拍数；BSRAM、DSP 和 ROM 端口数量不会因此增加。新增计算空间优先用于音色插值、表情滤波、立体声合唱与延迟，不增加声部数。

外部晶振解决标准音频频率来源，PLL 提供计算频率，流水线负责让代码承受这个频率。三项工作需要配合。当前代码已经在接近 49.152MHz 的上限运行，换入晶振不会自动缩短组合路径；直接把同一份代码改为 73.728MHz，会使时序要求更紧。

“避免飘红”的验收含义是：真实目标时钟下的布局布线 setup/hold 负裕量端点为零，实际传输路径没有遗漏约束，音频计算也能在下一帧之前交付。修正错误约束可以消除误报，真实超时路径则需要重构。不能靠降低约束频率、宽泛 false path 或随意添加多周期约束获得通过结果。

## 3. 倍频档位和实际收益

按当前 rPLL 的内部反馈模式，`Fout = Fin × FBDIV / IDIV`，`FVCO = Fout × ODIV`。静态原语参数 `IDIV_SEL`、`FBDIV_SEL` 分别填写实际系数减一，`ODIV_SEL` 直接填写输出分频系数。候选值如下，均关闭动态分频，保持 `DEVICE="GW2A-18C"`、`FCLKIN="12.288"`。

| 用途 | 计算频率 | 周期 | IDIV / FBDIV / ODIV | 对应 SEL 参数 | VCO | 48kHz 每帧拍数 |
|---|---:|---:|---|---|---:|---:|
| 接入基线与回退 | 49.152MHz | 20.345052ns | 1 / 4 / 16 | 0 / 3 / 16 | 786.432MHz | 1024 |
| 推荐重构目标 | 73.728MHz | 13.563368ns | 1 / 6 / 8 | 0 / 5 / 8 | 589.824MHz | 1536 |
| 后续性能冲刺 | 98.304MHz | 10.172526ns | 1 / 8 / 8 | 0 / 7 / 8 | 786.432MHz | 2048 |

上述三档的 PFD 都是 12.288MHz。官方 DS102-2.7.8E 的 GW2A-18 C8/I7 列给出输入和 PFD 范围 3—500MHz、VCO 范围 500—1250MHz；UG286 的 rPLL 参数表允许表中的 ODIV 值。因此这些组合满足所核对的频率范围。最终仍用本机 Gowin IP 配置检查及目标器件实现结果确认，不能从 PLL 合法推导整个设计必然通过时序。[UG286-2.0.2E，第 30—34 页](https://cdn.gowinsemi.com.cn/UG286E.pdf)、[DS102-2.7.8E，表 3-21，第 38—39 页](https://cdn.gowinsemi.com.cn/DS102E.pdf)

假设原有 992 拍计算量暂时不变，49.152、73.728、98.304MHz 下分别耗时约 20.182、13.455、10.091μs，每帧分别余下 32、544、1056 拍。对应 3.125%、35.42%、51.56% 的理论空闲比例。它们只是频率换算，重构增加的流水拍数、跨域交接和效果计算还没有计入。

73.728MHz 比当前频率提高 50%，同时要求把约 20ns 的关键路径压缩到 13.56ns 周期内。98.304MHz 的周期只有 10.17ns，通常需要进一步拆分选择、宽加法和乘法结果处理。建议以实际功能收益决定是否进入下一档，不安排无目的的连续扫频。若流水化后 49.152MHz 已能装下目标效果，也可以直接作为可用配置保留。

48kHz 输出保持不变。升级计算频率后仍按采样节拍推进相位和 ADSR，不改变音高、包络时间和效果延迟。不要同时把输出改成 96kHz：98.304MHz / 96kHz 又回到每帧 1024 拍，会消耗刚获得的计算空间。

## 4. 时钟域如何分配

```text
12.288MHz 外部参考
    ├─ 音频接口域：I2S 发送、48kHz 帧边界
    │      └─ BCK 3.072MHz、LRCK 48kHz，作为输出信号
    └─ rPLL：49.152 / 73.728 / 98.304MHz，编译时选择一个
           └─ 计算域：32 路调度、包络、查表、混音、效果、状态快照

已有外设时钟域（保留原来正确的时钟关系）
    └─ USB/HID、串口等 → 事件队列/参数握手 → 计算域

音频接口域 ↔ 帧请求与完整左右样本桥 ↔ 计算域
```

I2S 内部继续用参考时钟计数和使能，BCK/LRCK 不作为新增内部逻辑时钟。包络、LFO、毫秒节拍等低速工作优先用计算域的 clock enable，不为每个功能单独生成一根时钟。保持少量清晰时钟域，能减少跨域路径和约束维护量。

主线只需要一个新增音频 PLL。若将来做真实视频输出，再按显示模式单独规划像素时钟，不将整个音源迁入像素时钟域。板载 27MHz 与外部 12.288MHz 没有确定相位关系；来自同一个外部参考的 PLL 计算时钟则属于派生时钟，应在时序分析中保留这层关系。

当前规划假定“外部晶振”指能够提供时钟输出的 12.288MHz 有源振荡器。接入阶段仍需确定实际可用的专用时钟输入、对应 PLL 和全局布线资源；本文件不指定待焊引脚，也不借用其他 Dock 版本的点位。代码层可以先完成外壳、仿真与内部布局布线评估。

## 5. 重构的重点与顺序

### 5.1 先拆当前真正的最长路径：包络读取到 dirty 写回

`voice_sched32.v` 目前通过 `env_ptr` 动态选择 `env/est/gate/timer/stage_q`，同拍计算新包络、判断阶段变化，再更新 `dirty[env_ptr]`。当前报告的最差路径就落在这一段。建议先改成“读出并锁存声部状态 → 计算包络和阶段 → 写回状态及变更标志”的流水过程，声部编号、有效位和相关参数一起延迟。

第一轮可以每路占三拍，32 路扫描约 96 拍，再考虑是否需要每拍投入一路。这里需要同时核算计算核的配置窗口：扫描变长不能使本帧配置无法提交。明确采用本帧还是下一帧的包络快照，固定延迟可以接受，时有时无的错帧需要修正。

把多个动态写入 dirty 的来源收敛到明确的提交点，规定包络更新、音符事件、配置快照清除发生冲突时的优先级。若先清 dirty、随后才接收配置，要保留期间发生的新变化。读取中的声部被重按或窃声时，旧流水结果不能覆盖新音符；可以暂停该路提交，或随流水携带代次标记并丢弃过期结果。声部 RAM 化是后续选择，不必为了第一轮时序修复立即替换所有寄存器数组。

### 5.2 再分离音高、音色和配置快照

保留现有轮询选择，避免重新引入 32 路优先编码器。将声部选择、音高查表/弯音、bank/weight 计算、配置打包分段寄存。音符、力度、音色、阶段和 retrigger 必须对应同一份快照，背压期间保持完整数据。

采用统一的 `COMPUTE_HZ`、`AUDIO_REF_HZ`、`FS_HZ` 和 `FRAME_CYCLES` 定义，避免只改顶层参数而遗留 1024 拍常量。73.728MHz 对应 1536 拍，不是二的幂：帧计数器要按终值显式结束，不能依赖位宽溢出。32 路扫描数、48kHz 包络步进和 I2S 的 256 参考拍/帧，各自保持原本含义。

### 5.3 按下一轮时序报告拆分宽算术

当前 `split_audio_multiplier.v` 已对两个 18×18 乘积寄存，但输出还有宽位拼接加法；调用处又有舍入、移位、加到基准样本和累加操作。升级到更短周期时，可在“乘积拼接”“舍入/缩放”“声部累加”之间增加寄存器，并评估 DSP 输入/内部流水寄存配置。不要仅因使用了 DSP 就认为它后面的组合加法已被自动流水化。

每增加一级必须同步修改有效信号、声部标签、ROM 返回标签和状态机等待条件。单纯插入等待状态会增加每声部拍数；要维持收益，应让不同声部或不同运算阶段重叠，或为主混合与效果器提供独立运算单元。对累加反馈尤其要处理流水依赖，可用分组部分和后再归并，不能让后一个样本读到旧累加值。

先保持数学公式、位宽、舍入和波表内容不变，以延迟对齐后的逐样本比较证明重构未改变声音。滤波或新插值等有意改变音质的工作另行衡量，不混入时钟迁移。

### 5.4 保留 ROM 共享，拆开不必要的计算争用

不复制完整双音色 ROM 来增加通路。当前基线已用 26/46 块 BSRAM，复制整套音色会迅速耗尽容量。提高频率后优先在原 ROM 端口上安排更清楚的读表流水，并注册 bank 选择和地址，检查读延迟、CE 停读保持以及多个请求的返回顺序。

允许给主音量、滤波和效果单独分配乘法器，减少它们等待音源空闲窗口的时间。第一次重构可预留新增 4—8 个 18×18 等效乘法器，基线加起来约 6—10/48；这是预算，不是综合结果。跨域样本缓存和事件队列初步预留 0—2 块 BSRAM，寄存器实现或实际 IP 映射决定占用。后续效果与 FFT 的资源继续按[固定 32 路优化路线](FPGA-竞赛软件极限优化路线-20261022-v0.1.md)合并核算，不能把每个模块的独立余量重复使用。

## 6. 帧桥和跨域接口需要一起重构

让音频参考域提供唯一的帧边界，计算域按请求生成下一帧完整左右样本。桥接单元建议携带 `{frame_id, left[23:0], right[23:0]}`，左右必须原子提交。计算完成后，数据保持到接收确认；接收侧在同步后的有效标记到达后取数。可采用带确认的保持寄存器桥，或浅异步 FIFO，不对多位音频总线逐位打两拍。

现有 `audio_frame_bridge.v` 只有单声道保持寄存器和 toggle，没有完整接收确认，依赖“一帧内按时完成、下一次覆盖前已取走”的约定。它可以作为起点，但升级时应明确固定一帧交付、帧编号检查和保持期限。复位/PLL 重新锁定时同时清空请求与结果状态，避免把旧 toggle 当作新结果。先使用现有分域复位释放结构，不做运行中动态切频。

总预算必须包含请求跨域、调度、音源、效果、结果跨域以及 I2S 锁存前的等待。按当前参考域两级同步加取数的结构，结果返回就会占用数个 81.38ns 参考周期。原型的“992/1024 拍”是在另一种单时钟外壳中得到，不能不加计算地套入新桥。

| 档位 | 一帧计算拍数 | 初始交接预留 | 调度＋音源＋效果建议上限 | 说明 |
|---|---:|---:|---:|---|
| 49.152MHz | 1024 | 64 拍 | 960 拍 | 原 992 拍已超过这个初始预算，需要缩短或重新设计交付时序 |
| 73.728MHz | 1536 | 96 拍 | 1440 拍 | 推荐主档；相对原 992 拍名义上可多安排 448 拍工作 |
| 98.304MHz | 2048 | 128 拍 | 1920 拍 | 冲刺档；名义上可多安排 928 拍工作 |

三档交接预留都约为 1.302μs，是用于排程的起始额度，尚未测得。定向仿真按实际桥接延迟修订一次即可，不要求长期保留多余等待。记录的时间端点应包括 I2S 真正锁存，不能只在计算核 `sample_valid` 拉高时就宣称交付完成。

控制域到计算域采用事件 FIFO 或数据保持握手。连续参数可传完整快照，音符事件需要有序、不丢失。若保持原 UART/USB 时钟，现有波特率和接口时序参数可继续使用；若迁移某个模块，则其超时、去抖、分频和外设接口时序必须同步换算。

## 7. 时序约束与“红项”的处理方式

| 报告现象 | 优先检查 | 对应行动 |
|---|---|---|
| 同一计算域 setup 为负 | 路径端点、逻辑级数、布线延迟 | 拆分动态选择/算术，寄存高扇出控制；必要时回退已通过档位 |
| hold 为负 | 时钟关系、偏斜、过短数据路径 | 核对派生时钟与实际传输边沿，交给合法布局布线修复；降频通常不解决 hold |
| 综合报告默认 10ns 下变红 | 是否已经加载真实时钟约束 | 改为实际工作档位再分析，不能将默认估计当作最终 PnR 结论 |
| PLL 输出重复时钟或未知时钟 | 自动派生时钟与手写约束是否重复 | 每个实际时钟保留一致定义，核对 Clock Summary |
| 跨域总线大量报错 | 是否确有完整 CDC 协议 | 先保证同步、握手和数据稳定窗口，再精确处理相应例外 |
| 内部时序全绿但板级接口未分析 | I2S 等输出是否有外部时序约束 | 按 DAC 采样边沿建立输出检查；引脚未确定时标注为内部预评估 |

外部参考建立约 81.380208ns 的主时钟；计算时钟用其 PLL 输出引脚建立 4、6 或 8 倍派生关系。可以沿用 `ram_audio_pll_probe.sdc` 的组织方式，但层级名必须来自新顶层实现，检查约束匹配对象非空。工具已经自动建立正确派生时钟时，不再叠加第二个冲突定义。

12.288MHz 与它的 PLL 输出不应整体设成异步。旧探针中对同步器首级和保持总线的例外，是依据旧桥的具体行为写的，不能原样复制到新立体声桥。保持总线需要证明从数据发布到接收取数之间的最小稳定时间，并用匹配的路径延迟约束/检查覆盖；不要仅保留一个宽泛 false path。真正独立的 27MHz 域则按实际跨域接口单独处理。

clock enable 表示部分周期不更新，并不自动允许多周期路径。只有协议确实保证源数据保持、目标在指定周期采样时，才考虑成对、准确的 setup/hold 多周期约束。包络是低速算法，也不能据此把计算域全部放宽到 48kHz。

主档的设计目标可取最差 setup 约 +0.5ns 或更好，便于后续增加功能；这不是额外反复跑实现的硬门槛。最低通过条件仍是完整目标配置下 setup/hold 非负、约束覆盖正确、帧交付满足要求。目标时钟下已经通过且没有新改动时，不重复 PnR 追求更好看的余量。

## 8. 建议执行批次

| 批次 | 工作与影响范围 | 最小有效验证 | 保留或回退方式 |
|---|---|---|---|
| A：整理时钟外壳 | PLL 静态档位、双时钟顶层、统一参数，保留 49.152MHz | 一个厂商 PLL 模型用例，检查输出比例、LOCK/复位释放；原帧桥短测 | 保留旧单时钟原型作为数值参考 |
| B：修复最长路径 | 包络扫描分级、dirty 写回、事件冲突处理 | 满 32 路包络更新＋重按/窃声交叠；比对新旧状态与配置 | 单独提交调度重构，便于回退 |
| C：完成 73.728MHz 主档 | 必要算术流水、立体声帧桥、事件入口；先不加新效果 | 一段真实双音色 RTL 输出比对、连续帧编号和交付期限；完整新顶层一次 PnR | 若未通过，只处理最差路径后重跑；保留通过的低频档 |
| D：使用新增计算空间 | 接滤波、立体声合唱/延迟，保持 32 路和 48kHz | 最重实际功能组合的帧预算、数值/短音频检查、资源报告 | 功能配置分档，保留可用组合 |
| E：按需冲刺 98.304MHz | 仅当目标效果确实受计算预算限制时继续拆流水 | 复用同一短测和目标时钟 PnR，不扩成长可靠性门禁 | 无明显功能收益则停在 73.728MHz |

以上是后续执行建议，本轮不实施架构修改。进入实施时应先确认所采用的时钟域和桥接接口，再按批次推进；无需对每个寄存器调整单独确认。提高频率与新增效果分开提交，可以独立回退，也更容易判断声音变化来自哪里。

每批只跑与变化有关的测试。PLL 模型能检查配置和数字行为，不能证明真实晶振的相噪、接线和 DAC 模拟音质；晶振未到位不阻止软件重构和内部时序评估。后续正式烧录仍遵守项目的完整 RTL 仿真门禁，本轮规划不运行该门禁。
