## 2. 资料复核与原方案修正

依据 [TI PCM5102A 官方手册 SLAS859C](https://www.ti.com/lit/ds/symlink/pcm5102a.pdf) §9.3.2 和图 14，DIN 在 BCK 上升沿采样，FMT 低选择标准 I2S，LRCK 低为左、高为右，新声道 MSB 比 LRCK 切换晚一个 BCK。16/24 位数据均可使用 64 BCK/帧。三线模式见 §9.3.5.3、表 11：48 kHz 对应 3.072 MHz BCK，SCK 应保持低电平，启动检测要求连续 16 个 LRCK 周期；不能把“不提供 MCLK”写成 SCK 任意悬空。实物芯片是否带 A 后缀仍须核对，具体跳线以模块实物为准。

本次已阅读先前转换的 Markdown，并视觉复核手册第 15、16、25 页。图 14 的 32 位波形明确显示上一声道 LSB 跨到 LRCK 切换后的第一个采样位置。因此“32 槽容不下 32 位加一位延迟”不是标准 I2S 的限制。本轮只支持 16/24 位，是缩小实现范围的选择；以后支持 32 位，需要修改边界处理和模型，不能只放宽位宽检查。不要把 SCK 的 50 MHz 限制当作单独给出的 BCK 建立/保持时间指标。

`docs/minimum_design/01_时钟配置.md` 当前原文是“每 2 个系统时钟翻转 BCK”，旧方案转述为“三个”有误。当前生产 `pt8211_tx.rst` 接 `por`；模块在复位时将时钟置零，正常运行中的软复位只将样本置零。旧方案同时写“同步复位清所有状态”和“复位期间 BCK/LRCK 持续翻转”，应按第 4 节统一。

已重新检索相似开源实现。[Sipeed 官方示例](https://github.com/sipeed/TangPrimer-20K-example)包含 PT8211 示例，现有本地模块已参考其右对齐通路，不能直接当标准 I2S 发送器。[ultraembedded/core_audio](https://github.com/ultraembedded/core_audio)提供 I2S，但其接口是 AXI4-Lite，并含 2048 项缓冲，采用 GPL-2.0；旧文的“APB”不准确。当前范围不引入这些源码或运行依赖，按器件时序实现小模块更便于适配现有门禁。没有证据支持“所有开源项目都无法复用”的绝对结论，也不按星标数量判断时序可靠性。以后复制外部代码须另行固定提交、保留对应许可并说明依赖和适配。

## 3. 两档参数与分频实现

这两个档案都能使用整数长度的 BCK 周期，采用一个 BCK 周期计数器和一个 64 槽计数器即可。省去原方案的运行时相位累加器，也不需要独立自由运行的帧计数器。BCK、LRCK、DIN 均由 `posedge clk` 中的寄存器更新，内部用使能判断发送时刻；RTL 不用 `posedge bck`、`negedge bck` 或 `lrck` 建立新时钟域。

固定两声道、每声道 32 槽。编译期派生 `FRAME_CYC = CLK_HZ / SAMPLE_RATE_HZ`、`BCK_CYC = FRAME_CYC / 64`、`BCK_HIGH_CYC = BCK_CYC / 2`、`BCK_LOW_CYC = BCK_CYC - BCK_HIGH_CYC`。每次 BCK 下降沿推进一个槽，连续 32 槽后切换声道，连续 64 槽形成一帧。奇数分频时固定高电平短一拍、低电平长一拍，完整 BCK 周期仍恒定。

| 档案 | `CLK_HZ` | `SAMPLE_RATE_HZ` | 帧 / 半帧系统拍 | BCK 周期 / 高 / 低系统拍 | BCK 频率 | 使用范围 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 标准 | 12,288,000 | 48,000 | 256 / 128 | 4 / 2 / 2 | 3.072 MHz | S3 正式数字验收目标 |
| 调试 | 27,000,000 | 46,875 | 576 / 288 | 9 / 4 / 5 | 3.000 MHz | 参数化仿真对照，不作为 48 kHz 证据 |

标准档一个 LRCK 完整周期是 256 拍，LRCK 每次跳变相隔 128 拍；调试档分别为 576 和 288 拍。两档每半帧均有 32 个 BCK 上升沿、每完整帧 64 个。原方案调试档“BCK 周期平均 4.5 拍、4/5 交替”少算一倍；4/5 是两个半周期，完整周期为 9 拍。修订后的调试档没有逐周期长度抖动，存在 4:5 的占空比。是否被实物 DAC 接受，仍需实机证据。

`clk_params.vh` 使用包含保护和项目专用宏名前缀，例如 `FPGA_AUDIO_STD_CLK_HZ`、`FPGA_AUDIO_STD_FS_HZ`、`FPGA_AUDIO_DBG_CLK_HZ`、`FPGA_AUDIO_DBG_FS_HZ`。模块参数保留 `CLK_HZ`、`SAMPLE_RATE_HZ`、`DATA_BITS`，默认标准档、16 位。档案由实例参数或构建时选择，不做运行时切钟。头文件只接入本轮新模块与测试，不将既有顶层的默认 27 MHz/46,875 Hz 改成 48 kHz。

合法条件为 `CLK_HZ > 0`、`SAMPLE_RATE_HZ > 0`、时钟可整除采样率、`FRAME_CYC` 可整除 64、`BCK_CYC >= 2`、`DATA_BITS` 为 16 或 24。各计数器位宽至少为 1，防止 `$clog2(1)` 形成零宽寄存器。非法参数须在仿真中 `$fatal(1, ...)`，输出明确的 `S3_PARAM_INVALID` 及原因。涉及除法的 localparam 用安全占位值保护零分母，使非法配置能进入诊断而非直接产生无法辨识的展开错误。

若检查放在 `` `ifdef SIMULATION `` 下，门禁编译必须实际加入 `-DSIMULATION`。目前脚本只有 `-g2012 -I .`，没有这个宏；不能只新增保护块后声称参数检查已执行。综合时排除仿真系统任务，并记录同一参数的综合配置。协议常量 2、32、64 可以明确命名，频率与时长不散落为裸常数。

## 4. 发送接口、复位与样本时序

| 端口 | 方向 | 唯一语义 |
| --- | --- | --- |
| `clk` | in | 单一系统时钟；采样率正确性依赖参数与真实输入时钟一致 |
| `rst` | in | 高有效同步硬复位，清分频/槽状态、样本保持寄存器和 tick，输出三线为 0 |
| `sample_l`、`sample_r` | in | 同域、有符号二进制补码，宽度 `DATA_BITS`；左右同时锁存 |
| `bck`、`lrck`、`din` | out | 寄存器输出，标准 I2S；稳态 DIN/LRCK 只在 BCK 下降沿改变 |
| `sample_tick` | out | LRCK 从高到低的帧边界产生、恰好一个 `clk` 周期的寄存器脉冲 |

硬复位期间允许时钟停止，DAC 可能重新锁定；这是明确的启动/恢复行为。未来顶层把 `rst` 接上电复位，演奏软复位/Panic/数字静音通过将左右输入样本置零实现，不拉高串行器 `rst`。软静音必须保持 BCK、LRCK 和 tick 连续，不用组合逻辑把 DIN 强行改零。静音生效遵守帧锁存：命令后下一个锁存边界接受零样本，当前已发出的完整帧保留原数据。

以下“无 X”从至少一个有效同步复位上升沿之后检查；不承诺同步复位尚未采样时的 t=0 输出。硬复位可在任意槽发生，允许中断正在发送的帧；接收模型丢弃不完整帧并重新对齐，不能把残帧当作错误完整帧比较。

将复位释放后第一次真实的 LRCK 高→低且 BCK 下降沿定义为 `E0`。启动残段只发零，`E0` 后的第一个完整左右帧仍强制为零，即使输入预先非零；`E0` 发第一个 tick。`E1` 为下一次同类边界，从 `E1` 起正常同时锁存左右输入。`E0` 应在释放后不超过 `FRAME_CYC + BCK_CYC` 拍出现。此后 `En` 的间隔严格为 `FRAME_CYC`，不能用无限跳过首帧掩盖启动错误。

对每个正常边界 `E[n]`，发送器锁存的是该边沿之前稳定的 `sample_l/sample_r`，两路用于紧随其后的完整左右帧。`sample_tick` 在该边界后经非阻塞赋值变高；上游同步模块在一个系统时钟后才看到它，并开始下一样本的计算。该次计算结果在下一帧边界 `E[n+1]` 锁存，必须在边界前稳定。旧混音链有 DDS、包络和 FIR 的额外延迟，本轮不推定整机只延迟一帧；后续集成须测完整流水线。

每声道以 LRCK 切换后的第一个 BCK 上升沿为位置 0：位置 0 是本轮约定的零延迟位；位置 1 是当前声道 MSB，位置 `DATA_BITS` 是 LSB，其后到位置 31 都发 0。下降沿先设置这些位，随后上升沿采样。16 位时布局为“0、16 位数据、15 位零”，24 位为“0、24 位数据、7 位零”。零填充放在有效数据之后，不在 MSB 前额外添零，不对填充位置做符号扩展。这是本轮 16/24 位发送格式，不推广为所有 I2S 字宽的边界规则。

同一帧左右样本只锁存一次；右声道开始时不得重新读取输入。测试在左声道中途、左右边界、右声道中途改变输入，均应保持当前左右帧一致，下一正常帧等于锁存边界前最后稳定的两路值。测试输入在 `negedge clk` 改变，避免与 DUT 的锁存边沿竞争。

## 5. 独立接收模型与自检

`i2s_rx_model.v` 是仅供仿真的行为模型，输入为 `rst/bck/lrck/din`，输出为解码左右字和完整帧有效指示。它在 BCK 上升沿采样，从实际 LRCK 变化恢复声道与 32 槽位置，丢弃位置 0，接收位置 1 到 `DATA_BITS`。先得到完整左槽组，再得到完整右槽组后报告一对左右字；`frame_valid` 最多一个 BCK 周期。复位或尚未对齐时丢弃残段。模型不模拟模拟 DAC、PLL 锁定、XSMT 斜坡或滤波延迟。

模型和测试不得读取 DUT 的内部位计数器、相位或保持寄存器，也不导入 DUT 的串行移位函数。期望队列由测试激励在实际帧边界之前的稳定输入建立，不能从解码结果反过来产生期望值。先用测试台人工构造的已知 I2S 位串检查接收模型，再用该模型检查发送器；参考位串至少包含零、最小负数、左右不同值。时序监视器另行测系统拍、引脚边沿与填充位，避免只凭“发送器和接收器相互一致”放行。

一个 `tb_i2s_tx` 可以分阶段或分实例运行下表四种组合，分别统计，不需要扩展成四套重复测试代码。标准/调试时钟在测试台中各自生成，报告按整数系统拍计数；时间精度设为 1 ps，并记录模拟时钟周期的取整误差，不以小数显示值严格等于 48,000.000000 Hz 为断言。每种组合至少覆盖 256 个正常完整帧，并配置有界超时。

| 配置 | 帧周期 / LRCK 跳变间隔 | BCK 周期 / 高 / 低 | 数据检查 |
| --- | --- | --- | --- |
| 标准、16 位 | 256 / 128 拍 | 4 / 2 / 2 拍 | 16 位原始字逐位相等 |
| 标准、24 位 | 256 / 128 拍 | 4 / 2 / 2 拍 | 24 位原始字逐位相等 |
| 调试、16 位 | 576 / 288 拍 | 9 / 4 / 5 拍 | 16 位原始字逐位相等 |
| 调试、24 位 | 576 / 288 拍 | 9 / 4 / 5 拍 | 24 位原始字逐位相等 |

16 位定向向量为 `0000/0001/7FFF/8000/FFFF/5555/AAAA/8001`，24 位为 `000000/000001/7FFFFF/800000/FFFFFF/555555/AAAAAA/800001`。左右采用独立、不相等的序列；可含左正右负，但不要全部依赖 `R = -L`，因为最小负数取反会超出同宽有符号范围。伪随机序列固定种子 `32'h53A32026`，记录生成方法和实际向量数量。

| 断言 | 必须检查的行为 |
| --- | --- |
| 时钟与帧 | 完整周期、高低脉宽、LRCK 半帧/整帧、32/64 个 BCK 上升沿；LRCK 只在 BCK 下降沿切换 |
| I2S 格式 | 左低右高、位置 0 为零、下一位置为 MSB、所有有效位/填充位正确；稳态 DIN 只在下降沿改变 |
| 样本使能 | 每帧仅一个 tick，脉宽一系统拍，边界同拍；帧中无多余 tick |
| 锁存关系 | 左/右半帧中改变输入，本帧不撕裂，下帧符合边界前稳定值；tick 后更新的样本不得被提前发送 |
| 复位 | 先满足同步复位条件再查无 X；输入预置非零时首个完整帧仍为零；在左数据、右数据和填充槽中途复位后均恢复 |
| 数字静音 | 正常运行时两路输入改零，按锁存边界进入全零完整帧；保持至少 8 帧，时钟/tick 连续，随后恢复非零 |
| 检查器能力 | 对已知位串正确解码；错误位偏移、声道互换或单比特翻转会产生预期不一致 |

边沿测量要处理 Verilog 非阻塞赋值更新顺序：引脚事件监视器读实际引脚变化；系统拍监视器在寄存器更新后采样，例如延迟一个仿真精度单位。不要同一 `posedge clk` 未经调度处理就把新 tick 当旧 tick，也不要用 `force sample_tick` 生成 S3 的时序证据。复位豁免仅覆盖复位/残帧，不能关闭稳态断言。

负面控制保留两层。协议层将捕获的 32 槽按左对齐、右对齐错误偏移重解码，要求在指定非对称向量上至少各出现一次不一致；零向量等允许偶然相等。另对参考位串做左右互换和有效位翻转，确认比较器检测到差异。PCM5102A 的 FMT 高只代表左对齐，右对齐是验证用错误假设，不是该引脚的另一个硬件模式。无需把接收模型扩成三种完整协议实现。

参数层单独启动非法配置仿真，至少覆盖零采样率、`27 MHz/48 kHz` 不整除、`12.336 MHz/48 kHz` 得到 257 拍而不能整除 64、`3.072 MHz/48 kHz` 的 BCK 周期只有一拍，以及 `DATA_BITS=32`。负例的预期结果是非零退出且包含匹配原因的 `S3_PARAM_INVALID`；不能把语法错误、工具崩溃或任意非零都算通过。缺少失败或原因不匹配则整体门禁失败。所有普通断言和 watchdog 用 `$fatal(1,...)`，正向运行只有全部自检通过才 `$finish`。

## 6. 门禁、综合、资源与统一参数清单

把 S3 正向台登记到 `sim/run_simulation.ps1`，编译源包含发送器和接收模型，实际启用参数检查宏；参数负例由脚本顺序执行并区分预期失败。保留十二台原门禁，增加一个主台后正向台数应为十三；“十三台”本身不是验收证据，还须核对四组合、负例和各台退出码。门禁全局使用超时或各新台 watchdog，编译失败不可继续运行旧 `.vvp`。
